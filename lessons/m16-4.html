16.4 Graphs

Dependencies between tasks, imports between modules, links between documents, calls between services, steps in an agent's plan: all graphs. Representing a graph with dicts, breadth-first and depth-first search, shortest paths with and without weights, connected components and union-find, cycle detection, and topological sort for running dependency DAGs in the right order, with the complexity of each.

1Representing graphs

In Python, a graph is usually a dict from each node to its neighbours, an adjacency list: {"ingest": ["chunk"], "chunk": ["embed"], ...}, with sets instead of lists when you need fast "is there an edge?" checks, and dicts of dicts ({"a": {"b": 3}}) for weighted edges. Undirected edges are stored in both directions. This uses O(V + E) memory for V nodes and E edges, and iterating a node's neighbours costs O(its degree). An adjacency matrix (a V-by-V table) costs O(V^2) memory and suits only small, dense graphs. Remember to include nodes that have no outgoing edges, which a dict built only from edge sources silently drops (problem 7). Libraries such as networkx offer all the algorithms below, and graphlib.TopologicalSorter in the standard library does topological sorting.

2Breadth-first search

BFS explores a graph in layers: first the start node, then all its neighbours, then their unvisited neighbours, and so on, using a queue (collections.deque, 16.1) and a visited set marked when a node is enqueued. Because it reaches nodes in order of distance, the first time BFS reaches a node it has found a path with the fewest edges, so it computes shortest paths in unweighted graphs; recording each node's parent lets you rebuild the path backwards (problem 5). It runs in O(V + E). Typical uses: degrees of separation, the fewest hops between two documents in a link graph, crawling a site to a maximum depth, and the shortest sequence of transformations (word ladders, state machines).

bfs.py
from collections import deque

links = {
    "home": ["pricing", "docs"],
    "docs": ["api", "faq"],
    "pricing": ["faq"],
    "faq": ["refunds"],
    "api": [],
    "refunds": ["home"],
}

def bfs(graph, start):
    dist = {start: 0}
    order = []
    queue = deque([start])
    while queue:
        node = queue.popleft()
        order.append(node)
        for nxt in graph.get(node, []):
            if nxt not in dist:
                dist[nxt] = dist[node] + 1
                queue.append(nxt)
    return order, dist

order, dist = bfs(links, "home")
print(order)
print(dist)

{'home': 0, 'pricing': 1, 'docs': 1, 'faq': 2, 'api': 2, 'refunds': 3}

3Depth-first search

DFS follows one path as deep as possible before backtracking, using recursion or an explicit stack. It does not find shortest paths, but it is the natural tool for exploring everything reachable, finding connected components, detecting cycles, and producing a topological order. In Python, prefer an explicit stack for large graphs: recursion depth is limited (about 1,000 frames by default, and deep recursion can crash a browser-based Python like this site's). For cycle detection in a directed graph, DFS marks nodes with three states: unvisited, in progress (on the current path) and done; meeting an in-progress node means a back edge, which is a cycle (problem 14).

4Topological sort

A topological order lists the nodes of a DAG so that each node comes after its dependencies; it exists exactly when there is no cycle. Kahn's algorithm counts each node's unmet dependencies (its in-degree), starts with the nodes that have none, and repeatedly removes a ready node, decrementing its dependants' counts and adding any that reach zero; if some nodes never become ready, they are on or behind a cycle. Processing the ready set in rounds also gives levels: every node in one round can run in parallel, which is how build systems, Airflow DAGs and multi-step agent plans schedule work (problem 6). It runs in O(V + E).

5Weighted shortest paths and union-find

When edges have costs (latency between services, price of a model call, distance), BFS no longer finds the cheapest path. Dijkstra's algorithm does, for non-negative weights: keep a priority queue (heapq) of (distance, node), repeatedly pop the closest unfinished node, and relax its edges, pushing any neighbour whose tentative distance improves; with a heap it runs in O((V + E) log V). Negative weights break it (Bellman-Ford handles them). For undirected connectivity questions that arrive as a stream of edges ("are these two records the same customer?"), union-find (disjoint sets) keeps a parent pointer per node; find follows parents to a root, with path compression flattening the chain, and union links two roots, so each operation is nearly O(1) amortised (problem 12).

1. BFS layers and DFS order

from collections import deque

g = {"a": ["b", "c"], "b": ["d"], "c": ["d", "e"], "d": ["f"], "e": ["f"], "f": []}

def bfs_order(start):
    seen, order, q = {start}, [], deque([start])
    while q:
        n = q.popleft()
        order.append(n)
        for m in g[n]:
            if m not in seen:
                seen.add(m)
                q.append(m)
    return order

def dfs_order(start):
    seen, order, stack = set(), [], [start]
    while stack:
        n = stack.pop()
        if n in seen:
            continue
        seen.add(n)
        order.append(n)
        for m in reversed(g[n]):
            stack.append(m)
    return order

print(bfs_order("a"), dfs_order("a"))
print(bfs_order("d"), dfs_order("e"))

from collections import defaultdict


def build_graph(edges, directed=True):
    adj = defaultdict(set)
    for a, b in edges:
        adj[a].add(b)
        adj[b]
        if not directed:
            adj[b].add(a)
    return {node: sorted(adj[node]) for node in sorted(adj)}


def degrees(graph):
    indeg = {node: 0 for node in graph}
    for node, nbrs in graph.items():
        for m in nbrs:
            indeg[m] = indeg.get(m, 0) + 1
    return {node: (len(graph[node]), indeg[node]) for node in graph}

The adjacency list is the workhorse representation: O(V + E) memory and fast iteration over a node's neighbours. Sets remove duplicate edges (the repeated ingest -> chunk), and touching adj[b] ensures that sinks such as index, which have no outgoing edges, still appear as nodes, otherwise algorithms that iterate over the dict's keys would miss them. Sorting makes the output deterministic, which matters for tests and for reproducible scheduling. Out-degree is the length of a node's list; in-degree counts how often it appears as a target, which is exactly what Kahn's algorithm needs.

from collections import deque

def hops(graph, start):
    dist = {start: 0}
    todo = deque([start])
    while todo:
        node = todo.popleft()
        for nxt in graph.get(node, []):
            if nxt not in dist:
                dist[nxt] = dist[node] + 1
                todo.append(nxt)
    return dist

Assigning a distance the first time a node is reached is only correct if nodes are reached in order of distance, which is what a FIFO queue guarantees: all nodes at distance 1 are processed before any at distance 2. With pop() (a stack), the search took the last discovered page first, went down the blog chain, and reached faq through the long blog -> post1 -> post2 path, recording 4 instead of 2; with the links listed in the other order it would have been right by luck, which is why such bugs survive tests. deque.popleft() is O(1), whereas list.pop(0) would make the search quadratic.

4. Kahn's algorithm in rounds

def levels(deps):
    nodes = set(deps) | {d for ds in deps.values() for d in ds}
    remaining = {n: set(deps.get(n, ())) for n in nodes}
    rounds = []
    while remaining:
        ready = sorted(n for n, ds in remaining.items() if not ds)
        if not ready:
            raise ValueError(f"cycle among {sorted(remaining)}")
        rounds.append(ready)
        for n in ready:
            del remaining[n]
        for ds in remaining.values():
            ds.difference_update(ready)
    return rounds

solution.py
from collections import deque


def shortest_path(graph, start, goal):
    parent = {start: None}
    queue = deque([start])
    while queue:
        node = queue.popleft()
        if node == goal:
            path = []
            while node is not None:
                path.append(node)
                node = parent[node]
            return path[::-1]
        for nxt in graph.get(node, []):
            if nxt not in parent:
                parent[nxt] = node
                queue.append(nxt)
    return None

BFS reaches every node first along a path with the fewest edges, so remembering who discovered each node is enough to reconstruct that path backwards from the goal, in O(V + E) time and O(V) memory. The parent dict doubles as the visited set. Exploring neighbours in listed order makes ties deterministic (policy before payment). In a knowledge graph, the shortest chain of relations between two entities is a compact explanation to show the user or to feed a model; graph-based retrieval uses such multi-hop paths to answer questions no single document answers.

def execution_levels(plan):
    for step, deps in plan.items():
        for d in deps:
            if d not in plan:
                raise KeyError(f"step {step!r} depends on unknown step {d!r}")
    remaining = {step: set(deps) for step, deps in plan.items()}
    levels = []
    while remaining:
        ready = sorted(s for s, deps in remaining.items() if not deps)
        if not ready:
            raise ValueError(f"cycle among steps: {', '.join(sorted(remaining))}")
        levels.append(ready)
        for s in ready:
            del remaining[s]
        for deps in remaining.values():
            deps.difference_update(ready)
    return levels


def run_plan(plan, run_step):
    results = {}
    for level in execution_levels(plan):
        for step in level:
            results[step] = run_step(step, {d: results[d] for d in plan[step]})
    return results

Agent frameworks and workflow engines represent multi-step work as a DAG, so independent steps (two searches) can run concurrently and every step sees its dependencies' outputs. Kahn's algorithm in rounds gives both a valid order and the parallel levels; in an async runner, each level becomes one asyncio.gather (14.4). Validating that every dependency names a real step catches typos in a model-generated plan before anything runs, and the cycle check turns a plan that could never finish into a clear error, which can be sent back to the model to repair (7.4). The cost is O(V + E) per level scan here (O(V + E) overall with in-degree counters).

from collections import deque

def build_order(deps):
    nodes = set(deps) | {d for ds in deps.values() for d in ds}
    indegree = {n: len(deps.get(n, ())) for n in nodes}
    dependants = {n: [] for n in nodes}
    for pkg, d in deps.items():
        for dep in d:
            dependants[dep].append(pkg)
    queue = deque(sorted(p for p, n in indegree.items() if n == 0))
    order = []
    while queue:
        p = queue.popleft()
        order.append(p)
        for q in sorted(dependants[p]):
            indegree[q] -= 1
            if indegree[q] == 0:
                queue.append(q)
    if len(order) != len(nodes):
        raise ValueError("cycle")
    return order

Leaf dependencies (anyio, certifi) are written only as values, never as keys, so a graph built from the keys alone has no entry for them: they never enter the queue, and the first dependants[dep] lookup fails. Taking the union of keys and values gives every node an in-degree (0 for leaves, which makes them the first ready nodes) and a dependants list. Comparing the output length with the number of nodes detects cycles: nodes on a cycle never reach in-degree 0. This node-collection step is the most common bug in hand-written dependency resolution, the same mistake as the sink nodes in problem 2.

from collections import defaultdict


def customer_groups(records):
    by_value = defaultdict(list)
    for r in records:
        if r.get("email"):
            by_value[("email", r["email"].strip().lower())].append(r["id"])
        if r.get("phone"):
            by_value[("phone", r["phone"].strip())].append(r["id"])
    graph = {r["id"]: set() for r in records}
    for ids in by_value.values():
        for a in ids:
            graph[a].update(i for i in ids if i != a)
    seen, groups = set(), []
    for start in graph:
        if start in seen:
            continue
        stack, comp = [start], []
        seen.add(start)
        while stack:
            node = stack.pop()
            comp.append(node)
            for nxt in graph[node]:
                if nxt not in seen:
                    seen.add(nxt)
                    stack.append(nxt)
        groups.append(sorted(comp))
    return sorted(groups)

Entity resolution is a connected-components problem: r1 and r3 share nothing directly, but r1 shares an email with r2, and r2 a phone with r3, so all three are one customer. Indexing records by each normalised identifying value links them in O(total records) for typical data, and an iterative DFS (no recursion limit) groups them in O(V + E). Linking every pair within a large value group is quadratic in that group's size, so production code links each record only to the first record with the same value, or uses union-find (problem 12), which needs no explicit graph at all.

10. Dijkstra on service latencies

import heapq

def dijkstra(graph, start):
    dist = {start: 0}
    heap = [(0, start)]
    while heap:
        d, node = heapq.heappop(heap)
        if d > dist[node]:
            continue
        for nxt, w in graph.get(node, {}).items():
            nd = d + w
            if nd < dist.get(nxt, float("inf")):
                dist[nxt] = nd
                heapq.heappush(heap, (nd, nxt))
    return dist

latency = {
    "gateway": {"auth": 5, "cache": 2},
    "cache": {"retriever": 30, "auth": 1},
    "auth": {"retriever": 10},
    "retriever": {"llm": 200},
    "llm": {},
}
print(dijkstra(latency, "gateway"))
fewest_hops = ["gateway", "auth", "retriever", "llm"]
print(sum(latency[a][b] for a, b in zip(fewest_hops, fewest_hops[1:])))

import heapq
from collections import defaultdict


def cheapest(edges, start, goal):
    graph = defaultdict(list)
    for a, b, w in edges:
        if w < 0:
            raise ValueError(f"negative cost on {a} -> {b}")
        graph[a].append((b, w))
    dist, parent = {start: 0}, {start: None}
    heap = [(0, start)]
    while heap:
        d, node = heapq.heappop(heap)
        if d > dist[node]:
            continue
        if node == goal:
            path = []
            while node is not None:
                path.append(node)
                node = parent[node]
            return d, path[::-1]
        for nxt, w in graph[node]:
            nd = d + w
            if nd < dist.get(nxt, float("inf")):
                dist[nxt], parent[nxt] = nd, node
                heapq.heappush(heap, (nd, nxt))
    return None, []

Dijkstra pops nodes in order of their final cost, so when the goal is popped its cost and parent chain are final, and the search can stop early. Relaxation keeps, for each node, the cheapest known way in and who provided it, so the cheapest route (cache, then the small model, then the check, 0.21) beats both the direct small-model route (0.25) and the large model. Non-negative costs are essential: a negative edge could make an already settled node cheaper later, which Dijkstra never revisits, so the function rejects them. With a heap the cost is O((V + E) log V); model routers, network routing and map apps all rely on this algorithm or its variants (A*).

SolutionShow the solution and why
solution.py
class DisjointSet:
    def __init__(self):
        self.parent, self.size = {}, {}

    def find(self, x):
        if x not in self.parent:
            self.parent[x], self.size[x] = x, 1
            return x
        root = x
        while self.parent[root] != root:
            root = self.parent[root]
        while self.parent[x] != root:
            self.parent[x], x = root, self.parent[x]
        return root

    def union(self, a, b):
        ra, rb = self.find(a), self.find(b)
        if ra == rb:
            return False
        if self.size[ra] < self.size[rb]:
            ra, rb = rb, ra
        self.parent[rb] = ra
        self.size[ra] += self.size[rb]
        return True

    def groups(self):
        members = {}
        for x in self.parent:
            members.setdefault(self.find(x), []).append(x)
        return sorted(sorted(m) for m in members.values())


def cluster(pairs, items):
    ds = DisjointSet()
    for x in items:
        ds.find(x)
    for a, b in pairs:
        ds.union(a, b)
    return ds.groups()

Union-find answers "are these in the same group?" while groups are being formed, without building or searching a graph: near-duplicate pairs from a similarity search are merged as they arrive, and transitivity (faq-1 ~ faq-2 ~ faq-7) comes for free. Union by size keeps trees shallow and path compression flattens them on every find, so a chain of 20,000 unions stays fast and, because both loops are iterative, never hits a recursion limit. Clusters then drive deduplication (keep one representative per cluster), and the same structure appears in Kruskal's minimum spanning tree and in entity resolution at scale.

from collections import deque


def _normalise(url):
    url = url.split("#", 1)[0]
    if len(url) > 1 and url.endswith("/"):
        url = url[:-1]
    return url


def crawl(start, get_links, max_depth):
    start = _normalise(start)
    depth_of = {start: 0}
    queue = deque([start])
    while queue:
        page = queue.popleft()
        depth = depth_of[page]
        if depth == max_depth:
            continue
        for link in get_links(page):
            link = _normalise(link)
            if link not in depth_of:
                depth_of[link] = depth + 1
                queue.append(link)
    return depth_of

A crawler is a BFS over a graph you discover as you go, and each bug breaks one BFS rule. Without a visited set, pages linking back to each other were fetched repeatedly (exponentially many paths), and without the depth limit it would never stop. URL normalisation decides what counts as the same node: /docs and /docs/, or a link with a #fragment, are one page, and treating them as different doubles the work and the duplicates in a RAG index. Recording depth when a page is first enqueued gives its true minimum depth, the off-by-one max_depth + 1 let a third level in, and pages at the maximum depth are not expanded at all, which saves the fetches the grader counted. deque.popleft keeps it linear.

14. Detecting cycles with three colours

def find_cycle(graph):
    WHITE, GREY, BLACK = 0, 1, 2
    colour = {n: WHITE for n in graph}
    for start in sorted(graph):
        if colour[start] != WHITE:
            continue
        stack = [(start, iter(sorted(graph[start])))]
        path = [start]
        colour[start] = GREY
        while stack:
            node, it = stack[-1]
            nxt = next(it, None)
            if nxt is None:
                colour[node] = BLACK
                stack.pop()
                path.pop()
            elif colour.get(nxt, WHITE) == GREY:
                return path[path.index(nxt):] + [nxt]
            elif colour.get(nxt, WHITE) == WHITE:
                colour[nxt] = GREY
                path.append(nxt)
                stack.append((nxt, iter(sorted(graph.get(nxt, [])))))
    return None

15. BFS or DFS: how do you choose?

SolutionModel answer

Both visit everything reachable in O(V + E). Use BFS (a queue) when you need shortest paths in unweighted graphs or anything layered by distance: fewest hops, nearest matching node, level-by-level processing, crawling to a depth; it may hold a whole frontier in memory, which can be wide. Use DFS (a stack or recursion) when you need to explore paths fully: connected components, cycle detection with colours, topological order by finishing times, backtracking searches, or when the graph is deep and narrow; it uses memory proportional to the depth, but recursion in Python is limited, so use an explicit stack for big graphs. For weighted shortest paths neither is enough: Dijkstra (non-negative weights) or Bellman-Ford. Mention visited sets (marked on enqueue for BFS) to avoid revisiting nodes and infinite loops on cycles.

16. What is a topological sort, and where have you used one?

SolutionModel answer

A topological sort orders the nodes of a directed acyclic graph so that every edge points forward: each node appears after everything it depends on. It exists if and only if the graph has no cycle, so computing one doubles as cycle detection. Kahn's algorithm repeatedly takes nodes with no remaining dependencies (in-degree zero), and processing them in rounds yields groups that can run in parallel; a DFS that outputs nodes in reverse finishing order is the alternative. Both are O(V + E). Uses: build systems and package installers (dependencies before dependants), data pipelines and Airflow DAGs, running an agent's multi-step plan where steps consume earlier results, spreadsheet recalculation, migration ordering, and course prerequisites. In Python, graphlib.TopologicalSorter provides it, including an incremental API (get_ready, done) that fits concurrent execution.

17. How would you find the shortest route between two services when calls have different latencies, and when does your method fail?

SolutionModel answer

Model the services as a directed graph with edge weights equal to latency (or cost) and run Dijkstra's algorithm from the source: a min-heap keyed by tentative distance, repeatedly settling the closest node and relaxing its outgoing edges, with parent pointers to rebuild the route, O((V + E) log V); stop early when the destination is settled. It fails with negative weights (use Bellman-Ford, O(V E), which also detects negative cycles), and it optimises a single additive metric, so trade-offs (latency versus cost, reliability) need a combined weight or a multi-objective method. Weights that change over time or with load call for recomputation, and for huge graphs with geometry (maps) A* with an admissible heuristic explores far fewer nodes. If all weights are equal, plain BFS suffices; with only 0 and 1 weights, a deque- based 0-1 BFS is linear.

Recap

  • Represent graphs as dicts of neighbour lists or sets (O(V + E) memory), and include nodes that only appear as edge targets.
  • BFS with a deque and visited-on-enqueue finds fewest-edge paths; record parents to rebuild them.
  • DFS (prefer an explicit stack) finds components and cycles; three colours detect cycles in directed graphs.
  • Topological sort (Kahn's algorithm, in rounds for parallel levels) orders dependency DAGs and reports cycles.
  • Dijkstra with heapq finds cheapest paths for non-negative weights; union-find groups connected items with near O(1) operations.
