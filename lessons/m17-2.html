1DataFrames, Series and dtypes

A DataFrame is a table: named columns, each one a Series (a one-dimensional array with a dtype, usually a NumPy array underneath), all sharing a row Index. If you know Power BI, a DataFrame is a table in the data view and a Series is one column; if you know SQL, it is the result of a SELECT, held in memory, that you can keep transforming in Python. Because each column has one dtype, column operations are vectorised like D.1's arrays, and the same rule applies: work with whole columns, not row loops.

The first three calls on any new dataset are df.head() (the first rows), df.info() (each column's dtype and non-null count, plus memory) and df.describe() (count, mean, spread and quartiles of the numeric columns). info is the most useful: a numeric column read as text, or a column that is 90% empty, shows up immediately.

2Selecting rows and columns

df["col"] returns one column as a Series and df[["a", "b"]] several as a DataFrame. For rows, use the two indexers and never mix them up. loc selects by label: df.loc[row_labels, column_labels], and its slices include the end label (df.loc[0:2] is three rows). iloc selects by position, like NumPy, and its slices exclude the end (df.iloc[0:2] is two rows). After filtering or sorting, labels and positions no longer agree, which is exactly when the difference bites.

A boolean mask is a Series of True/False aligned to the rows, and df[mask] or df.loc[mask, cols] keeps the True rows: the WHERE clause. Combine conditions with &, | and ~, each in parentheses. isin([...]) is SQL's IN, between(a, b) is BETWEEN (inclusive), and query("amount > 100 and state == 'CA'") reads like SQL when the expression gets long. Comparisons with NaN are always False, so a missing amount is in neither amount > 100 nor amount <= 100; ask for missing rows with isna() explicitly.

3Missing values

pandas marks missing data with NaN in float columns and in the default str columns, NaT in datetime columns, and pd.NA in the optional nullable dtypes (Int64, Float64, boolean, string), which can hold a missing value without turning integers into floats. isna() finds them all; isna().sum() counts them per column, and isna().mean() gives the fraction. Statistics such as mean and sum skip missing values by default, which is convenient and dangerous: a mean over 2 of 5 rows looks just like a mean over 5.

Three ways to deal with them, all of which you will use. Drop rows (dropna(subset=[...])) when the value is essential and rarely missing, such as the label of a training example. Fill (fillna(value) or fillna({col: value})) when a sensible default exists: 0 for "no payments", "unknown" for a category. Impute a statistic such as the median for a numeric feature, and add an indicator column amount_missing so the model can learn that "missing" itself carries information. For ML, the statistic must come from the training split only, or the test score leaks information from the test set (problem 6).

4Dtypes and conversions

Correct dtypes are the difference between a working feature and a silent bug: a numeric column read as text cannot be averaged, an id read as a number loses its leading zeros, and a category stored as text wastes memory. astype("float64") converts and raises on anything that does not parse; pd.to_numeric(s, errors="coerce") turns unparseable values into NaN, which you then count, so data problems become visible numbers instead of crashes. Read identifiers as strings from the start with read_csv(..., dtype={"zip": "str"}).

Memory follows dtype. df.memory_usage(deep=True) reports bytes per column, including the strings themselves. A text column with few distinct values (state, product) is far smaller as category, which stores each distinct value once plus small integer codes (D.4 covers it), and float32 halves a float column. On a 10-million-row complaint table these choices decide whether the data fits in memory.

5Copy-on-Write and method chaining

In older pandas, whether sub = df[df.a > 0] was a view or a copy depended on internals, so changing sub sometimes changed df and sometimes did not, with a SettingWithCopyWarning that nobody understood. pandas 3 settles it with Copy-on-Write: every indexing result behaves as a copy. Changing sub never changes df (data is only actually copied when you write, so it stays cheap). The consequence is that chained assignment, df[mask]["col"] = 0, can never work: the first [] produces a new object, the assignment changes that object, and it is thrown away. pandas 3 warns with ChainedAssignmentError and leaves df unchanged. Write it as one loc call: df.loc[mask, "col"] = 0.

solution.py
import pandas as pd


def first_value(col):
    i = col.first_valid_index()
    return None if i is None else col[i]


def quality_report(df):
    missing = df.isna().sum()
    report = pd.DataFrame({
        "dtype": df.dtypes.astype(str),
        "missing": missing,
        "missing_pct": (missing / len(df) * 100).round(1),
        "unique": df.nunique(),
        "example": pd.Series({c: first_value(df[c]) for c in df.columns}, dtype=object),
    })
    return report.sort_values("missing_pct", ascending=False, kind="stable")

Every statistic here is a per-column reduction, and pandas has one for each: isna().sum(), nunique() (which skips missing values), dtypes. They return Series indexed by column name, so building the report is just putting them side by side; the starter looped over rows, which is both slow and the wrong direction. first_valid_index handles an all-missing column by returning None. The example column is built as object dtype so that a Python None stays None. kind="stable" keeps the original order among equal percentages, so the report is deterministic. Run this on every new dataset: it is the df.info() you can sort, filter and save.

import pandas as pd


def flag_large(df, limit):
    out = df.assign(priority="normal")
    out.loc[out["amount"] > limit, "priority"] = "high"
    return out

solution.py
import pandas as pd


class MedianImputer:
    def __init__(self):
        self.medians_ = None

    def fit(self, train_df, columns):
        self.columns = list(columns)
        self.medians_ = train_df[self.columns].median()
        return self

    def transform(self, df):
        if self.medians_ is None:
            raise RuntimeError("call fit() first")
        out = df.copy()
        for c in self.columns:
            out[f"{c}_missing"] = out[c].isna().astype(int)
        out[self.columns] = out[self.columns].fillna(self.medians_)
        return out

The starter computed the median of the frame being transformed, so the test set was filled with the test set's own median: information from the data you are evaluating on leaks into its features, and the score becomes optimistic. Worse, the same row would get different values depending on what else is in the batch. Learning the statistics in fit and only applying them in transform is the contract scikit-learn uses for every transformer (D.6), which is why its SimpleImputer exists. The indicator columns let a model learn that "amount was missing" is a signal in itself, and they must be computed before filling erases it. fillna with a Series fills each column with its own value.

solution.py
import pandas as pd


def make_xy(df, label, drop=()):
    if label not in df.columns:
        raise KeyError(label)
    labelled = df.dropna(subset=[label])
    X = labelled.drop(columns=[label, *drop])
    X = X.loc[:, X.notna().any()]
    return X, labelled[label]

A row without a label cannot be used for supervised training, and leaving it in makes most libraries fail or, worse, treat the missing label as a class, so those rows go first, from both X and y at once, which keeps their indexes aligned. Identifiers such as id must not be features: a model can memorise them and look accurate on data it has seen, then fail on new ids. A column with no values carries no information. X.notna().any() is a boolean Series over columns, and loc[:, mask] selects those columns. pandas raises KeyError itself for a missing column in df[label], but checking first gives a clearer error before any work is done.

import pandas as pd


def to_records(df, text_col, max_chars, fields):
    text = df[text_col].str.strip()
    keep = df[text.str.len() > 0]
    text = text[keep.index]
    cut = text.str.len() > max_chars
    text = text.where(~cut, text.str[: max_chars - 3] + "...")
    out = keep[["id", *fields]].astype(object)
    out = out.where(out.notna(), None)
    out.insert(1, "text", text)
    return out.to_dict("records")

to_dict("records") turns each row into a dict, but it keeps NaN as a float, and json.dumps writes it as the bare word NaN, which is not JSON: many LLM APIs and parsers reject the request. Converting the fields to object dtype first lets where put a real None in every missing cell, which serialises as null. Empty and missing narratives carry nothing to classify, so they are dropped before spending tokens on them. Truncation is a character budget standing in for a token budget; cutting to max_chars - 3 and adding the ellipsis makes the model, and a human reviewing the prompt, see that the text was shortened. The allow_nan=False in the test makes json.dumps refuse NaN outright.

solution.py
import pandas as pd


def dedupe(df):
    key_customer = df["customer"].str.strip().str.lower()
    key_text = df["narrative"].str.lower().str.replace(r"[^a-z0-9]+", " ", regex=True).str.strip()
    work = df.assign(_k1=key_customer, _k2=key_text)
    work["copies"] = work.groupby(["_k1", "_k2"])["id"].transform("size")
    kept = work.sort_values(["submitted", "id"]).drop_duplicates(subset=["_k1", "_k2"])
    return kept.drop(columns=["_k1", "_k2"]).sort_values("id").reset_index(drop=True)

Exact matching misses every real duplicate here, because people retype the same complaint with different case, spacing and punctuation. Normalising builds a key that ignores those differences: lower-case, collapse every run of non-alphanumeric characters (punctuation, repeated spaces) into one space, and strip. groupby(...).transform("size") returns, for every row, the size of its group, aligned to the original rows, so it can be stored before anything is dropped. Sorting by submitted and then id makes "keep the first" mean "keep the earliest, then the smallest id"; drop_duplicates keeps the first row per key by default. This is the cheap, exact layer of de-duplication; near-duplicates with different wording need MinHash or embeddings (16.2 sketched shingles and Jaccard).

solution.py
import pandas as pd
from pandas.api import types as pdt


def shrink(df, max_unique_ratio=0.5):
    out = df.copy()
    for col in out.columns:
        s = out[col]
        if pdt.is_integer_dtype(s):
            out[col] = pd.to_numeric(s, downcast="integer")
        elif pdt.is_float_dtype(s):
            out[col] = s.astype("float32")
        elif pdt.is_string_dtype(s) or pdt.is_object_dtype(s):
            if s.nunique() <= max_unique_ratio * len(s):
                out[col] = s.astype("category")
    return out


def saved(before, after):
    b = before.memory_usage(deep=True).sum()
    a = after.memory_usage(deep=True).sum()
    return round(100 * (1 - a / b), 1)

Defaults are generous: read_csv gives every integer column int64 and every float float64, eight bytes per value. Values from 0 to 99 fit in one byte (int8), values up to about 100 million in four (int32), and downcast="integer" picks the smallest type that holds the actual minimum and maximum. float32 halves floats at the cost of precision beyond 7 digits, usually fine for features (D.1). A text column with four distinct values repeated 1,000 times is mostly repeated strings; as a category each value is stored once with one-byte codes. A column of unique strings would get bigger as a category (codes plus every value), which is why the ratio check exists. Looping over columns is fine: there are few, and each operation inside is vectorised. The input keeps its dtypes because the function works on a copy.

14. What is the difference between loc and iloc, and where do people go wrong?

SolutionModel answer

loc selects by label (index values and column names) and iloc by integer position, like NumPy. Their slices differ: df.loc["a":"c"] includes "c", because labels have no natural "one past the end", while df.iloc[0:3] excludes position 3, like Python. The common mistakes: assuming labels equal positions after filtering or sorting (after df[df.x > 0] the labels have gaps, so loc[0] may not exist or may be any row); using df[0], which looks up a column named 0; chained indexing such as df[mask]["col"] = v, which under pandas 3 Copy-on-Write never writes into df (use df.loc[mask, "col"] = v); and forgetting that boolean masks must be aligned Series or arrays of the right length. Rule of thumb: use loc with masks and column names in application code, iloc for "the first n rows" or positional sampling, and reset_index(drop=True) when you want labels to equal positions again.

Interview

15. How do you handle missing values when preparing data for a model?

SolutionModel answer

First, measure and understand them: count and fraction per column (isna().mean()), and ask why they are missing, because the mechanism decides the treatment: missing at random, missing because of the value itself (high incomes unreported), or structurally missing (no second applicant). Then decide per column. Drop rows only when the value is essential (the label) or rarely missing; drop columns that are nearly empty. Impute numeric features with the median (robust to outliers) or a model-based estimate, categorical ones with the mode or an explicit "unknown" category, and add missing-indicator columns because missingness is often predictive. The critical rule is no leakage: imputation statistics are learned on the training split only and applied to validation, test and production data, ideally inside a scikit-learn Pipeline with SimpleImputer so cross-validation refits them per fold (D.6). Some models (gradient-boosted trees such as LightGBM and XGBoost, or HistGradientBoostingClassifier) handle NaN natively. Finally, beware defaults that hide missingness: pandas statistics skip NaN, and comparisons with NaN are False, so filters silently drop those rows.

Interview

16. What changed with Copy-on-Write in pandas 3, and why does it matter?

SolutionModel answer

Before pandas 3, an indexing result could be a view or a copy depending on the operation and memory layout, so modifying a subset sometimes modified the parent frame and sometimes did not, and SettingWithCopyWarning tried, unreliably, to warn about it. pandas 3 makes Copy-on-Write the only behaviour: any object derived from another (a column, a filtered frame, the result of reset_index or rename) behaves as a copy, so changing it never changes the original. Internally pandas still shares memory until one side is written, so operations that used to copy defensively are now often cheaper. Consequences for code: chained assignment df[mask]["col"] = v never works (pandas emits ChainedAssignmentError) and must be one df.loc[mask, "col"] = v; inplace=True is rarely useful; functions can return modified copies safely; and to_numpy() may return a read-only array, so call to_numpy(copy=True) if you need to write. For teams it removes a whole class of "my preprocessing changed the raw data" bugs.

Recap

  • A DataFrame is named columns, each a Series with one dtype, sharing an Index. Start with head, info and describe; pandas 3 reads text as the str dtype.
  • loc is by label and includes the slice end; iloc is by position and excludes it. Masks combine with &, |, ~; NaN fails every comparison.
  • Missing values: count with isna(), then drop, fill, or impute with training statistics plus an indicator column. pd.NA uses three-valued logic.
  • Convert with pd.to_numeric(errors="coerce") and count the NaNs; downcast numbers and use category for repetitive text to save memory.
  • Copy-on-Write: every indexing result behaves as a copy, so chained assignment never works; write df.loc[mask, col] = v or chain assign calls.
