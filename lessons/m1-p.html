2. Clamp a value

Write clamp(x, lo, hi) that returns x limited to the range lo to hi (both included).

TestsThe 4 checks Run tests uses
assert clamp(5, 0, 10) == 5
assert clamp(-3, 0, 10) == 0
assert clamp(99, 0, 10) == 10
assert clamp(0.5, 0.0, 1.0) == 0.5
HintOpen a hint

You can do it with if, or with one line of min and max.

SolutionShow the solution and why
solution.py
def clamp(x, lo, hi):
    return max(lo, min(x, hi))

min(x, hi) cuts off the top, then max(lo, ...) cuts off the bottom. Clamping shows up all over ML: clipping gradients, clipping predicted probabilities away from 0 and 1 before a log loss (np.clip).

3. Count the digits

Write count_digits(n) that returns how many digits the integer n has, using a loop with //, not len(str(n)). 0 has one digit, and the sign does not count.

TestsThe 5 checks Run tests uses
assert count_digits(7) == 1
assert count_digits(0) == 1
assert count_digits(4073) == 4
assert count_digits(-120) == 3
assert count_digits(10 ** 20) == 21
HintOpen a hint

Work on abs(n), and handle 0 before the loop (or use a loop that always runs once).

SolutionShow the solution and why
solution.py
def count_digits(n):
    n = abs(n)
    count = 1
    while n >= 10:
        n //= 10
        count += 1
    return count

Starting count at 1 and looping while n >= 10 handles 0 without a special case. The abs matters: -120 // 10 is -12, and -1 // 10 is -1, not 0, so a loop on a negative number with while n != 0 never ends. That is floor division from 1.1 biting back.

5. Average of a list

average(nums) has two bugs: it crashes on an empty list and gives a wrong answer for [1, 2]. An empty list should return None.

TestsThe 4 checks Run tests uses
assert average([1, 2]) == 1.5
assert average([4, 4, 4]) == 4
assert average([]) is None
assert average([-1, -2]) == -1.5
Hint 1Open a hint

Which division operator did 1.1 say always gives a float?

Hint 2Open a hint

Check for the empty list before dividing.

SolutionShow the solution and why
solution.py
def average(nums):
    if not nums:
        return None
    return sum(nums) / len(nums)

// floors, so 3 // 2 is 1, and -3 // 2 is -2, which is wrong in a different direction. Returning None for no data (rather than 0) matches SQL's AVG over no rows, which gives NULL. The library version is statistics.mean, which raises on empty input instead.

6. Round up to a multiple

Write next_multiple(n, k) that returns the smallest multiple of k that is greater than or equal to n (k is positive). Do it without math.ceil and without a loop.

TestsThe 5 checks Run tests uses
assert next_multiple(7, 5) == 10
assert next_multiple(10, 5) == 10
assert next_multiple(0, 3) == 0
assert next_multiple(-7, 5) == -5
assert next_multiple(10 ** 18 + 1, 10) == 10 ** 18 + 10
Hint 1Open a hint

n // k rounds down. How do you get a division that rounds up?

Hint 2Open a hint

Try -(-n // k).

SolutionShow the solution and why
solution.py
def next_multiple(n, k):
    return -(-n // k) * k

Flooring a negated number and negating back is ceiling division: -(-7 // 5) is -(-2) = 2. It stays in exact integers, so it works for huge numbers where math.ceil(n / k) would go through a float and lose precision (the last test). Use it for "how many pages / batches do I need": -(-rows // batch_size).

7. Second largest

Write second_largest(nums) that returns the second largest distinct value in one pass, without sorting. Return None if there is no such value.

TestsThe 5 checks Run tests uses
assert second_largest([3, 9, 4, 9, 7]) == 7
assert second_largest([5, 5, 5]) is None
assert second_largest([1]) is None
assert second_largest([-1, -5]) == -5
assert second_largest([2, 8]) == 2
Hint 1Open a hint

Keep two variables, first and second, both starting at None.

Hint 2Open a hint

A new value bigger than first pushes the old first down to second. A value equal to first is ignored.

SolutionShow the solution and why
solution.py
def second_largest(nums):
    first = second = None
    for x in nums:
        if first is None or x > first:
            first, second = x, first
        elif x != first and (second is None or x > second):
            second = x
    return second

Three cases per value: a new maximum (shift down), a duplicate of the maximum (skip), or a new runner-up. first, second = x, first swaps in one step without a temporary. Starting at None instead of 0 keeps negative inputs working, and the is None checks, not truthiness, keep a real 0 from being treated as missing.

solution.py
def grade(score):
    if not 0 <= score <= 100:
        return "invalid"
    if score >= 90:
        return "A"
    if score >= 75:
        return "B"
    if score >= 50:
        return "C"
    return "F"

Guard clause first, then the bands from the top down. Each if returns, so the order does the job of the lower bounds. The nesting went five deep, the flat version reads like the spec.

10. Adding 0.1 ten times

import math
total = 0.0
for _ in range(10):
    total += 0.1
print(total)
print(total == 1.0, math.isclose(total, 1.0))
print(sum([0.1] * 10), math.fsum([0.1] * 10))
Hint 1Open a hint

Each += rounds to the nearest float, and the tiny errors add up.

Hint 2Open a hint

math.fsum tracks the lost bits. And since Python 3.12, so does the built-in sum for floats.

SolutionShow the solution and why
Real output
0.9999999999999999
False True
1.0 1.0

The loop rounds after every += and ends up just under 1, so == fails and isclose passes. The surprise is the last line: since Python 3.12, sum() on floats uses compensated summation, which keeps track of the rounding error as it goes, so it gives exactly 1.0, the same as math.fsum. Older Pythons print 0.9999999999999999 there, so this is also a nice interview detail. The lesson stays the same: when you add many floats, such as losses over a dataset, the method of adding changes the last digits. Compare with isclose, and know that numpy's sum uses yet another method (pairwise summation).

11. Longest Collatz chain

For each starting number from 1 up to (not including) limit, count the Collatz steps to reach 1 (1.2, problem 8). Write longest_collatz(limit) that returns the starting number with the most steps. On a tie, return the smaller number.

TestsThe 4 checks Run tests uses
assert longest_collatz(2) == 1
assert longest_collatz(10) == 9
assert longest_collatz(30) == 27
assert longest_collatz(7) == 6
Hint 1Open a hint

Write a small helper steps(n) with a while loop first.

Hint 2Open a hint

Use > (not >=) when updating the best, so the first, smaller number keeps a tie.

SolutionShow the solution and why
solution.py
def steps(n):
    count = 0
    while n != 1:
        n = n // 2 if n % 2 == 0 else 3 * n + 1
        count += 1
    return count

def longest_collatz(limit):
    best, best_steps = 1, 0
    for start in range(1, limit):
        s = steps(start)
        if s > best_steps:
            best, best_steps = start, s
    return best

Splitting out steps keeps each loop simple. The tie rule comes free from the comparison: with > an equal later value never replaces the current best. 27 takes 111 steps, far more than its neighbours, which is why it is the famous example. For big limits you would cache steps already computed (Module 3).

12. Check a card number

Write luhn_valid(number) for a string of digits. The Luhn check: starting from the rightmost digit, double every second digit; if doubling gives more than 9, subtract 9; add everything up. The number is valid if the total is a multiple of 10. Card numbers and many ID numbers use it to catch typing mistakes.

TestsThe 5 checks Run tests uses
assert luhn_valid("79927398713")
assert not luhn_valid("79927398710")
assert luhn_valid("4111111111111111")
assert not luhn_valid("4111111111111112")
assert luhn_valid("0")
Hint 1Open a hint

Loop over reversed(number) with enumerate. Positions 1, 3, 5, ... (counting from 0) get doubled.

Hint 2Open a hint

int(ch) turns a digit character into a number.

SolutionShow the solution and why
solution.py
def luhn_valid(number):
    total = 0
    for i, ch in enumerate(reversed(number)):
        d = int(ch)
        if i % 2 == 1:
            d *= 2
            if d > 9:
                d -= 9
        total += d
    return total % 10 == 0

Walking the digits right to left with enumerate(reversed(...)) makes "every second digit from the right" simply "odd positions". d - 9 is the same as adding the two digits of d (for 10 to 18). Validations like this are typical data-quality rules in a pipeline: cheap checks before a row is loaded.

break only leaves the inner loop. The else belongs to the inner loop too.

SolutionShow the solution and why
Real output
1 0
2 0
2 1
outer done

For i = 0, j = 0 equals i straight away, so it breaks with nothing printed and the inner else is skipped. i = 1 prints 1 0, then breaks at j = 1. i = 2 prints 2 0 and 2 1, then breaks. The inner loop never finishes on its own, so "inner finished" never prints.

3Mini project: a payment batch checker

A finance team sends a batch of payment amounts every night. Before loading it, you check it and send back a short summary. The amounts are floats. Some are missing (None), some are refunds (negative), and 0 is a real, valid payment. Build three functions; the tests check all three.

Project

14. Payment batch checker

1. band(amount) returns "refund" for negative amounts, "small" for 0 up to (not including) 100, "medium" for 100 up to 1000, and "large" for 1000 and over.

2. round_money(x) rounds to 2 decimal places the way the finance system does: ties away from zero (1.1, problem 12), returning a float.

3. summarize(payments, limit) returns a dict with:

  • "count": how many amounts are present (not None)
  • "missing": how many are None
  • "total": the sum of the present amounts, rounded with round_money
  • "bands": a dict of how many amounts fall in each band, with all four keys always present
  • "first_over": the position in the list of the first amount above limit, or None
  • "ok": True only if nothing is missing and nothing is above limit

Hint 1Open a hint

band: a guard for negatives, then chained comparisons (1.1).

Hint 2Open a hint

round_money: Decimal(str(x)).quantize(Decimal("0.01"), rounding=ROUND_HALF_UP).

Hint 3Open a hint

summarize: one for i, amount in enumerate(payments) loop. Use is None for missing, never if not amount, or the zero payments disappear.

Hint 4Open a hint

Only record first_over the first time: check first_over is None before setting it. Round the total once, at the end.

SolutionShow the solution and why
solution.py
from decimal import Decimal, ROUND_HALF_UP


def band(amount):
    if amount < 0:
        return "refund"
    if amount < 100:
        return "small"
    if amount < 1000:
        return "medium"
    return "large"


def round_money(x):
    return float(Decimal(str(x)).quantize(Decimal("0.01"), rounding=ROUND_HALF_UP))


def summarize(payments, limit):
    bands = {"refund": 0, "small": 0, "medium": 0, "large": 0}
    count = missing = 0
    total = 0.0
    first_over = None
    for i, amount in enumerate(payments):
        if amount is None:
            missing += 1
            continue
        count += 1
        total += amount
        bands[band(amount)] += 1
        if amount > limit and first_over is None:
            first_over = i
    return {
        "count": count,
        "missing": missing,
        "total": round_money(total),
        "bands": bands,
        "first_over": first_over,
        "ok": missing == 0 and first_over is None,
    }

Everything from the module meets here:

  • amount is None rather than if not amount: the batch contains real zero payments (1.1, the COALESCE trap).
  • continue skips missing rows early, which keeps the rest of the loop flat (1.2).
  • enumerate gives the position for first_over, and the first_over is None check keeps the first one, like the search problems in 1.2, without stopping the loop, because the counts still need every row.
  • The raw float total of 0.1 + 0.2 is 0.30000000000000004. Rounding once at the end with a decimal rounding mode gives the 0.3 the finance team expects (1.1).
  • Chained comparisons are not needed in band because each if returns. The order of the checks does it.

A real version would read the batch from a file (Module 12), raise a custom error on bad rows (Module 8) and come with a pytest suite (Module 13). The structure stays the same.

Recap

  • Missing is not zero: test for None with is None, and keep truthiness for real emptiness checks.
  • Floor division, ceiling division -(-n // k), and % cover most counting, paging and digit problems.
  • Round money once, at the end, with Decimal and an explicit rounding mode. Compare floats with isclose.
  • One loop with enumerate and continue can count, sum, search and band a whole batch in one pass.
