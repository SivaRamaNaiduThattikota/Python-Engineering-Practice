12.1 pathlib and files

Almost every ML and GenAI job starts and ends with files: corpora to index, datasets to load, checkpoints and reports to write. Paths as objects with pathlib, finding files with glob, text files and encodings, binary files and chunked reading, seeking, and atomic writes that survive crashes. Applied to corpora, checkpoints, duplicate detection and log tails.

1Paths as objects

File paths are strings in old code, glued together with + or os.path.join and taken apart with split. pathlib.Path replaces that with an object that knows how paths are built: the / operator joins parts (root / "runs" / name), and attributes take a path apart: name (the last part), stem (the name without its last suffix), suffix and suffixes, parent and parents, parts. Methods derive new paths: with_suffix(".json"), with_name("config.json"), relative_to(root). The same code works on Windows and Linux, because Path is WindowsPath or PosixPath depending on the system; PurePosixPath and PureWindowsPath do the path arithmetic for one system without touching the disk, which is handy in tests.

paths.py
from pathlib import PurePosixPath as P

ckpt = P("/data/runs/exp-1/model.best.pt")
print(ckpt.name, ckpt.stem, ckpt.suffix, ckpt.suffixes)
print(ckpt.parent, ckpt.parent.name, ckpt.with_suffix(".onnx"))
root = P("/data")
print(ckpt.relative_to(root), ckpt.is_relative_to(root / "runs"), (root / "cache" / "emb.npy").as_posix())
print(P("a/b/../c"), P("logs") / "/tmp/app.log")
Output

/data/runs/exp-1 exp-1 /data/runs/exp-1/model.best.onnx
runs/exp-1/model.best.pt True /data/cache/emb.npy
a/b/../c /tmp/app.log

Two details catch people. Pure path arithmetic does not resolve .., because a/b/.. only equals a if b is not a symbolic link, which only the disk can say; Path.resolve() asks the disk and returns the absolute, normalised path. And joining an absolute path discards everything before it: P("logs") / "/tmp/app.log" is /tmp/app.log. That second rule matters for security: joining a user-supplied name to an upload folder can escape it, so check (base / name).resolve().is_relative_to(base.resolve()) before using such a path.

Paths can be passed to everything that accepts a file name (open, json.load callers, pandas, NumPy), because they implement os.fspath. Convert to a string with str(path) only when a library insists, and use as_posix() when you need forward slashes on every system, for example as a stable key in a manifest.

2Exploring and changing the file system

Concrete paths talk to the disk: exists(), is_file(), is_dir(), stat().st_size and st_mtime (size and modification time). iterdir() lists a folder's direct children, in no guaranteed order, so sort when order matters. glob(pattern) finds matches inside a folder: * matches within one name, ? one character, [ab] a set, and ** any number of folders, so root.glob("**/*.md") and root.rglob("*.md") both search the whole tree. Results are lazy generators, again unordered.

Changes: mkdir(parents=True, exist_ok=True) creates a folder and any missing parents, and does not fail if it exists (without those flags it raises FileNotFoundError or FileExistsError). unlink(missing_ok=True) deletes a file, rmdir() an empty folder, and shutil.rmtree(path) a whole tree. rename(target) and replace(target) move a file; replace overwrites an existing target on every system, which makes it the tool for atomic writes below. shutil.copy2 copies a file with its metadata. tempfile.TemporaryDirectory() is a context manager (10.2) that creates a fresh folder and deletes it afterwards, which is what tests and scratch work should use.

explore.py
import tempfile
from pathlib import Path

with tempfile.TemporaryDirectory() as tmp:
    root = Path(tmp)

3Text files and encodings

open(path, mode, encoding=...) returns a file object. The mode says what you will do: "r" read (the default), "w" write, truncating any existing file to empty immediately, "a" append to the end, "x" create, failing with FileExistsError if the file exists, and "+" adds the other direction ("r+"). Always use it in a with block so it is closed, which also flushes buffered writes to the operating system. Path.read_text() and write_text() do open, read or write, and close in one call, for small files.

A text file is bytes on disk, and an encoding turns them into characters. UTF-8 is the standard for data and code, but open without encoding= uses the platform's default, which is still a legacy code page such as cp1252 on many Windows machines, so the same code reads café correctly on a Mac and as cafÃ© (or crashes) on a colleague's laptop. Always pass encoding="utf-8". Read with errors="replace" when the input may contain invalid bytes and losing a character is acceptable (scraped web text), and with encoding="utf-8-sig" when files from Excel start with a byte-order mark. Text mode also translates line endings: on reading, \r\n and \r become \n; on writing, \n becomes the platform's line ending, unless you pass newline="" (12.2 needs that for CSV).

text.py
import os, tempfile

path = os.path.join(tempfile.mkdtemp(), "notes.txt")
with open(path, "w", encoding="utf-8") as f:
    print(f.write("café\nrefund window\n"))
print(os.path.getsize(path), "bytes on disk")
with open(path, encoding="utf-8") as f:
    for number, line in enumerate(f, start=1):
        print(number, repr(line))
with open(path, encoding="latin-1") as f:
    print(f.readline().rstrip())
with open(path, encoding="ascii", errors="replace") as f:
    print(f.readline().rstrip())

write returns the number of characters written, 19, while the file holds 20 bytes, because é takes two bytes in UTF-8. Iterating over a file yields one line at a time, newline included, and reads lazily, so a 50 GB log can be processed with constant memory; f.read() and f.readlines() load everything, which is fine for small files only. Decoding UTF-8 bytes as Latin-1 never fails but produces the classic mojibake cafÃ©, and decoding as ASCII with errors="replace" turns each invalid byte into the replacement character �.

4Binary files, chunks and seeking

Mode "rb" or "wb" opens a file in binary mode: no encoding, no newline translation, reads return bytes. Use it for images, model weights, NumPy and Parquet files, compressed data, and whenever you hash or copy a file exactly. Large binary files are read in chunks: f.read(n) returns up to n bytes and b"" at the end, so for chunk in iter(lambda: f.read(1 << 16), b""): walks any file with 64 KiB of memory. Hashing a file this way, hashlib.sha256() updated chunk by chunk, gives a content fingerprint used to detect duplicate documents and changed datasets (problem 7).

A file object has a position. f.tell() returns it, f.seek(offset, whence) moves it: whence 0 counts from the start, 1 from the current position, 2 from the end (with a negative offset). In binary mode positions are byte offsets, which is how tools such as tail read the end of a huge log without reading the whole file (problem 12). In text mode seek only accepts values previously returned by tell, because a character may span several bytes.

binary.py
import hashlib, os, tempfile

path = os.path.join(tempfile.mkdtemp(), "weights.bin")
with open(path, "wb") as f:
    f.write(b"HDR1" + bytes(range(256)) * 1000)
digest = hashlib.sha256()
chunks = 0
with open(path, "rb") as f:
    print(f.read(4), f.tell())
    f.seek(0)
    for chunk in iter(lambda: f.read(65_536), b""):
        digest.update(chunk)
        chunks += 1
    f.seek(-3, 2)
    print(list(f.read()), f.tell())
with open(path, "rb") as f:
    print(chunks, digest.hexdigest() == hashlib.sha256(f.read()).hexdigest())
Output

[253, 254, 255] 256004

5Atomic writes

Opening a file with "w" empties it at once, and the new content is written over time. If the program crashes, is killed, or raises an exception halfway through (an unserialisable value at the end of a json.dump), the file is left truncated or half-written, and the old content is gone. For a model registry, a checkpoint index or a config file, that turns one failed run into a broken system.

The fix is an atomic write: write the new content to a temporary file in the same folder, flush it and ask the operating system to put it on disk (f.flush() then os.fsync(f.fileno())), then call os.replace(tmp, target). On the same file system, a rename is atomic: other readers see either the old file or the new one, never a mix. If anything fails before the rename, delete the temporary file and the target is untouched. The temporary file must be in the same folder because a rename across file systems is a copy, which is not atomic; tempfile.mkstemp(dir=folder) creates a uniquely named file there, so two writers never collide on the temporary name.

atomic.py
import json, os, tempfile
from pathlib import Path

def save_json_atomic(path, data):
    path = Path(path)
    fd, tmp = tempfile.mkstemp(dir=path.parent, prefix=f".{path.name}.", suffix=".tmp")
    try:
        with os.fdopen(fd, "w", encoding="utf-8") as f:
            json.dump(data, f)
            f.flush()
            os.fsync(f.fileno())
        os.replace(tmp, path)
    except BaseException:
        os.unlink(tmp)
        raise

target = Path(tempfile.mkdtemp()) / "registry.json"
save_json_atomic(target, {"best": "v3"})
try:
    save_json_atomic(target, {"best": "v4", "model": object()})
except TypeError as e:
    print("failed:", e)
print(target.read_text(encoding="utf-8"), sorted(p.name for p in target.parent.iterdir()))
Output
failed: Object of type object is not JSON serializable
{"best": "v3"} ['registry.json']

The failed save raised, its temporary file was removed, and the registry still holds the complete previous version. except BaseException (not Exception) also cleans up on KeyboardInterrupt, and the error is re-raised (7.2). Problem 10 fixes a non-atomic save, and problem 13 turns the pattern into a reusable context manager.

solution.py
from pathlib import Path


def checkpoint_path(root, run, step):
    return Path(root) / "runs" / run / f"step-{step:06d}.pt"


def latest_checkpoint(run_dir):
    found = []
    for path in Path(run_dir).glob("step-*.pt"):
        number = path.stem.removeprefix("step-")
        if number.isdigit():
            found.append((int(number), path))
    if not found:
        return None
    return max(found)[1]

Building paths with / keeps them correct on every system, and padding the step makes new names sort correctly even as strings. The glob pattern step-*.pt requires the name to end in .pt, which excludes the temporary file, and the digit check excludes step-best.pt. Comparing parsed integers is what makes the legacy step-50.pt and step-7000.pt order correctly: as strings, "step-50.pt" sorts after "step-000100.pt". The (number, path) tuples sort by number first. Training scripts use exactly this to resume from the last checkpoint after a crash.

solution.py
from pathlib import Path

SUFFIXES = {".md", ".txt"}


def load_corpus(root):
    root = Path(root)
    docs = {}
    for path in root.rglob("*"):
        if not path.is_file() or path.suffix.lower() not in SUFFIXES:
            continue
        rel = path.relative_to(root)
        if any(part.startswith(".") for part in rel.parts[:-1]):
            continue
        text = path.read_text(encoding="utf-8")
        if text.strip():
            docs[rel.as_posix()] = text
    return dict(sorted(docs.items()))

rglob walks the entire tree, hidden folders included, so the loader makes three decisions explicitly: which file types are documents (case-insensitive, since README.MD exists in real repositories), which folders are not content (.git, drafts, caches; a hidden file is kept, as the spec says), and which files are empty. Keys relative to the root, with forward slashes, are stable document ids: the same on Windows and Linux and independent of where the corpus is checked out, which matters when the ids are stored in a vector index (5.P). Sorting makes runs reproducible, since rglob order is not guaranteed.

solution.py
import hashlib
from pathlib import Path


def sha256_file(path, chunk_size=65536):
    h = hashlib.sha256()
    with open(path, "rb") as f:
        for chunk in iter(lambda: f.read(chunk_size), b""):
            h.update(chunk)
    return h.hexdigest()


def find_duplicates(root):
    root = Path(root)
    by_size = {}
    for path in root.rglob("*"):
        if path.is_file():
            by_size.setdefault(path.stat().st_size, []).append(path)
    by_hash = {}
    for paths in by_size.values():
        if len(paths) < 2:
            continue
        for path in paths:
            by_hash.setdefault(sha256_file(path), []).append(path.relative_to(root).as_posix())
    return sorted(sorted(group) for group in by_hash.values() if len(group) > 1)

Reading in fixed-size chunks keeps memory constant whatever the file size, and the digest is identical to hashing the whole content at once. Grouping by size first is the classic optimisation: files of different sizes cannot be identical, and stat is far cheaper than reading, so in a real corpus most files are never hashed (here the unique 50-byte file is skipped, while the two 20-byte files are hashed and found to differ). Content hashes are how ingestion pipelines skip documents they have already embedded, and how dataset versioning tools detect changed files.

Asking for more bytes than remain is not an error: read returns what is left, here 17, 18, 19, and the position stops at the end.

SolutionShow the solution and why
solution.py
def tail(path, n, block=1024):
    if n <= 0:
        return []
    with open(path, "rb") as f:
        f.seek(0, 2)
        pos = f.tell()
        data = b""
        while pos > 0 and data.count(b"\n") <= n:
            step = min(block, pos)
            pos -= step
            f.seek(pos)
            data = f.read(step) + data
    if pos > 0:
        data = data[data.index(b"\n") + 1:]
    return data.decode("utf-8").splitlines()[-n:]

The file is read from the end in blocks, so the cost depends on the size of the last few lines, not of the file: two lines of a 150 KB log need at most two 256-byte reads. Binary mode is required because only byte offsets can be seeked freely (text-mode seek accepts only tell values). The loop stops once it has more than n newlines, since with a trailing newline, n complete lines need n + 1. When it stopped mid-file, the first bytes belong to a line that was cut, possibly in the middle of a multi-byte character, so everything before the first newline is dropped before decoding, which also prevents a UnicodeDecodeError at the boundary. Log viewers, monitoring agents and "show the last error" debugging tools all work this way.

Write a context manager atomic_write(path, mode="w", encoding="utf-8") that yields a file object for a temporary file in the same folder (created with tempfile.mkstemp, name starting with ".") and, on a clean exit, flushes, fsyncs and replaces path with it. SolutionShow the solution and why
solution.py
import os, tempfile
from contextlib import contextmanager
from pathlib import Path


@contextmanager
def atomic_write(path, mode="w", encoding="utf-8"):
    if mode not in ("w", "wb"):
        raise ValueError(f"atomic_write supports 'w' and 'wb', not {mode!r}")
    path = Path(path)
    fd, tmp = tempfile.mkstemp(dir=path.parent, prefix=f".{path.name}.", suffix=".tmp")
    try:
        with os.fdopen(fd, mode, encoding=None if "b" in mode else encoding) as f:
            yield f
            f.flush()
            os.fsync(f.fileno())
        os.replace(tmp, path)
    except BaseException:
        try:
            os.unlink(tmp)
        except FileNotFoundError:
            pass
        raise

The context manager packages the atomic-write recipe so callers write normally inside a with block (10.2). mkstemp creates a uniquely named file in the target's folder, so the final os.replace is a rename on the same file system, and concurrent writers never share a temporary file. The yield sits inside try, so an exception in the caller's block, here a failing embedding service, lands in the except, which removes the partial file and re-raises (a generator-based manager must re-raise, or the error would be swallowed). Only a clean exit reaches the flush, the fsync that forces the data to disk before the rename, and the replace. Validating the mode before mkstemp means a bad call leaves nothing behind. Vector-index writers, model registries and caching layers use exactly this helper.

import json
from pathlib import Path


def summarise_runs(src_dir, out_dir):
    counts = {}
    for path in sorted(Path(src_dir).rglob("*.json")):
        if path.name.startswith("_"):
            continue
        data = json.loads(path.read_text(encoding="utf-8"))
        for p in data["predictions"]:
            counts[p["label"]] = counts.get(p["label"], 0) + 1
    out_dir = Path(out_dir)
    out_dir.mkdir(parents=True, exist_ok=True)
    out = out_dir / "summary.txt"
    ordered = sorted(counts.items(), key=lambda item: (-item[1], item[0]))
    out.write_text("".join(f"{label} {n}\n" for label, n in ordered), encoding="utf-8")
    return out

Each bug is a file-handling habit from this lesson. glob("*.json") searches one folder; rglob searches the tree. Draft files need an explicit rule, since nothing skips them by default. open(path).read() without with leaves closing to the garbage collector, and without encoding reads with the platform default; read_text(encoding="utf-8") fixes both. Writing needs the folder to exist (mkdir with both flags). 16. What is an atomic write, and how do you implement one in Python?

SolutionModel answer

An atomic write makes a file change all-or-nothing: readers and later runs see either the complete old file or the complete new one, never a truncated or half-written file, even if the process crashes or raises halfway. Opening the target with "w" cannot give that, because it truncates the file immediately and writes over time. The recipe: create a temporary file in the same folder (tempfile.mkstemp(dir=target.parent) gives a unique name), write everything to it, flush() and os.fsync() so the data reaches the disk, then os.replace(tmp, target), which renames it over the target atomically on the same file system, on POSIX and Windows. On any exception, delete the temporary file and re-raise. Same folder matters because a rename across file systems becomes a copy, which is not atomic. Use it for config files, model registries, indexes, caches and any file another process reads while you write; for appending events, a log line per write is usually enough.

Interview

17. Why should you always pass an encoding when opening text files?

SolutionModel answer

Text files are bytes, and open needs an encoding to turn them into characters. Without encoding=, Python uses the platform's default: UTF-8 on Linux and macOS, but often a legacy code page such as cp1252 on Windows. So code that reads café correctly on the developer's laptop produces cafÃ© or raises UnicodeDecodeError on another machine or in a container, and files it writes are unreadable elsewhere. Passing encoding="utf-8" makes behaviour identical everywhere. Related choices: errors="replace" (or "ignore") for messy input where losing a character beats crashing, utf-8-sig for files with a byte-order mark from Excel, and binary mode for anything that is not text. Python 3.15 makes UTF-8 the default (PEP 686), and linters such as Ruff and Pylint flag open calls without an encoding, but explicit is still the habit to show.

18. How would you process a 50 GB log or JSONL file in Python?

SolutionModel answer

Never load it: stream it. Iterating over a text file object reads one line at a time through a buffer, so memory stays constant, and generators (6.3) can filter, parse and aggregate as lines pass, keeping only running totals or a bounded structure such as a heap of top-k or a reservoir sample. For binary data, read fixed-size chunks with f.read(n). Write results incrementally too, appending one line per record or flushing batches, and write final outputs atomically. Make the job resumable: record the byte offset (tell() in binary mode) or the line count of the last committed batch, and seek there on restart. For speed, measure first: parsing usually dominates I/O, so faster parsers (orjson), splitting the file by byte ranges at line boundaries across processes (14.3), or columnar tools (pandas chunksize, Polars, DuckDB scanning the file directly) are the next steps. Compressed input can be streamed with gzip.open in text mode. Finally, handle bad records (invalid JSON, broken encodings) by counting and logging them instead of crashing at hour three.

Recap

  • Use pathlib.Path: / joins, name, stem, suffix, parent, relative_to and with_suffix replace string surgery; absolute parts reset a join.
  • glob, rglob and iterdir are unordered and do not skip hidden folders; sort and filter explicitly. mkdir(parents=True, exist_ok=True) is repeat-safe.
  • Always pass encoding="utf-8"; "w" truncates at once, "a" appends, "x" refuses existing files; iterate lines to stream big files.
  • Binary mode for bytes: read in chunks, hash with hashlib, and seek/tell by byte offset to read from the end.
  • Atomic writes: temporary file in the same folder, flush and fsync, then os.replace; delete the temporary file on failure.
