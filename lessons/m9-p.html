solution.py
class Interval:
    def __init__(self, start, end):
        if start > end:
            raise ValueError(f"start {start} is after end {end}")
        self.start, self.end = start, end

    def __repr__(self):
        return f"Interval({self.start}, {self.end})"

    def __len__(self):
        return self.end - self.start

    def __contains__(self, x):
        return self.start <= x < self.end

    def __eq__(self, other):
        if not isinstance(other, Interval):
            return NotImplemented
        return (self.start, self.end) == (other.start, other.end)

    def __hash__(self):
        return hash((self.start, self.end))

    def overlaps(self, other):
        return self.start < other.end and other.start < self.end

Each dunder hooks one piece of syntax (9.2): len, in and ==, with the hash built from the same fields as equality so intervals work in sets. Half-open intervals (start included, end excluded) make adjacent intervals not overlap and lengths add up, the same convention as range and slicing. __len__ returning 0 also makes an empty interval falsy. Note that __len__ must return an integer, so this class works for integer ends; a float-based interval would expose a length property instead.

class ToolCall:
    def __init__(self, name, args):
        self.name = name
        self.args = dict(args)

    def __repr__(self):
        return f"{type(self).__name__}({self.name!r}, {self.args!r})"

    def __str__(self):
        arguments = ", ".join(f"{k}={v!r}" for k, v in self.args.items())
        return f"{self.name}({arguments})"

solution.py
class ConversationLog:
    def __init__(self):
        self._messages = []

    @classmethod
    def from_messages(cls, messages):
        log = cls()
        for m in messages:
            log.append(m["role"], m["content"])
        return log

    def append(self, role, content):
        self._messages.append({"role": role, "content": content})

    def __len__(self):
        return len(self._messages)

    def __iter__(self):
        for m in self._messages:
            yield dict(m)

    def __getitem__(self, key):
        if isinstance(key, slice):
            return type(self).from_messages(self._messages[key])
        return dict(self._messages[key])

    def __contains__(self, text):
        needle = text.lower()
        return any(needle in m["content"].lower() for m in self._messages)

    @property
    def last_user(self):
        for m in reversed(self._messages):
            if m["role"] == "user":
                return m["content"]
        return None

The class behaves like a read-only sequence of messages (indexing, slicing, iteration, len, in), but every message handed out is a copy, so callers cannot corrupt the history: the encapsulation rule of 9.3 implemented through the container protocol of 9.2. in is given a meaning that fits the domain (a text search) rather than dict equality. The slice builds a new log through the classmethod constructor, using type(self) so subclasses stay subclasses (9.6). from_messages reuses append, so there is one place where messages enter.

SolutionShow the solution and why
solution.py
class Retriever:
    def __init__(self, docs):
        self.docs = docs
        self.__cache = {}

    def retrieve(self, query):
        if query not in self.__cache:
            self.__cache[query] = [d for d in self.docs if query in d.lower()]
        return list(self.__cache[query])

class LoggingRetriever(Retriever):
    def __init__(self, docs):
        super().__init__(docs)
        self._cache = []

    def retrieve(self, query):
        self._cache.append(query)
        return super().retrieve(query)

Both classes wrote self._cache on the same instance, so the subclass replaced the base's dict with a list and the base's query not in self._cache then tested list membership, and indexing a list with a string crashed. This is precisely the problem name mangling solves (9.3): inside Retriever, self.__cache becomes self._Retriever__cache, a name no subclass will pick by accident. It is the right tool for base classes meant to be subclassed by other people; the alternative is composition (9.5), where the two objects never share attributes at all.

SolutionShow the solution and why

import math
from abc import ABC, abstractmethod


class NotFittedError(Exception):
    pass


class Scaler(ABC):
    _fitted = False

    @abstractmethod
    def fit(self, values):
        ...

    @abstractmethod
    def _apply(self, value):
        ...

    def transform(self, values):
        if not self._fitted:
            raise NotFittedError(f"{type(self).__name__} must be fitted before transform")
        return [round(self._apply(v), 4) for v in values]

    def fit_transform(self, values):
        return self.fit(values).transform(values)


class StandardScaler(Scaler):
    def fit(self, values):
        n = len(values)
        self.mean = sum(values) / n
        self.std = math.sqrt(sum((v - self.mean) ** 2 for v in values) / n) or 1.0
        self._fitted = True
        return self

    def _apply(self, value):
        return (value - self.mean) / self.std


class MinMaxScaler(Scaler):
    def fit(self, values):
        self.low = min(values)
        self.range = (max(values) - self.low) or 1.0
        self._fitted = True
        return self

    def _apply(self, value):
        return (value - self.low) / self.range

The ABC fixes the interface every scaler shares, so pipeline code can call fit and transform on any of them, and it supplies fit_transform and the not-fitted check once. fit returning self allows fit(...).transform(...) chains, scikit-learn's convention. _fitted = False as a class attribute is a safe immutable default that each instance shadows when fitted (9.1). The scalers learn their parameters from training data only; applying them to new data (25 and 40) uses the stored parameters, which is why fitting on the test set is a leakage bug. scikit-learn's real StandardScaler follows exactly this fit/transform split.

class HybridRetriever:
    def __init__(self, keyword, vector, weight=0.5):
        if not 0 <= weight <= 1:
            raise ValueError(f"weight must be in [0, 1], got {weight}")
        self.keyword = keyword
        self.vector = vector
        self.weight = weight

    @staticmethod
    def _normalise(pairs):
        top = max((s for _, s in pairs), default=0)
        return {d: (s / top if top else 0.0) for d, s in pairs}

    def search(self, query, k):
        kw = self._normalise(self.keyword.search(query, 2 * k))
        vec = self._normalise(self.vector.search(query, 2 * k))
        combined = {
            d: round(self.weight * vec.get(d, 0.0) + (1 - self.weight) * kw.get(d, 0.0), 4)
            for d in kw.keys() | vec.keys()
        }
        return sorted(combined.items(), key=lambda p: (-p[1], p[0]))[:k]

The hybrid retriever has two retrievers and knows only their search method, so either can be BM25, a vector store, a fake, or another hybrid: composition and duck typing (9.5). The two score scales are incomparable (BM25 scores of 12 versus cosine similarities below 1), so each list is normalised before mixing; real systems also use reciprocal rank fusion, which ignores raw scores entirely. Asking each side for more candidates than needed (2 * k) lets a document that is second in one list and third in the other still win. Sorting by (-score, id) makes ties deterministic. The weight is validated once, at construction (9.3).

11. When would you make an object immutable, and how do you do it in Python?

SolutionModel answer

Make an object immutable when it represents a value: money, a version, an interval, a label, a configuration snapshot, a cache key. Immutable objects can be shared freely without defensive copies, used as dict keys and set members (their hash cannot change), compared by value, and reasoned about easily, including across threads; "changes" return new objects, as with strings and tuples. In Python, use @dataclass(frozen=True) (11.3) or a NamedTuple for the common case; by hand, store values in __slots__ or private attributes, expose read-only properties, block __setattr__, and define __eq__ and __hash__ from the fields. Remember that immutability is shallow: a frozen object holding a list can still have that list changed, so use tuples and frozensets inside. Keep mutable objects for things with identity and changing state: sessions, caches, connections, accumulators.

Interview

12. Walk through exactly what happens when Python evaluates obj.attr.

SolutionModel answer

Python calls type(obj).__getattribute__(obj, "attr"), which for normal classes does the following. It searches the class's MRO for attr; if it finds a data descriptor there (an object with __set__ or __delete__, such as a property), it calls its __get__ and returns the result, so properties win over instance attributes. Otherwise it looks in the instance's __dict__ (or its slots) and returns the value if present. Otherwise, if the class attribute found earlier is a non-data descriptor (a function, classmethod, staticmethod, cached_property), it calls its __get__, which for a function produces a bound method; if it is a plain class attribute, it returns it. If nothing was found, __getattribute__ raises AttributeError, and Python then calls __getattr__ if the class defines it, which is how proxies forward missing attributes. Dunder methods used by syntax (len, +) skip the instance entirely and are looked up on the type. Understanding this chain explains bound methods, property validation, cached_property, shadowing of class attributes and delegation.

14. Build the provider layer

Implement the following.

  • Usage(prompt=0, completion=0): __repr__ (Usage(prompt=3, completion=2)), total property, __add__ and __radd__ (so sum() works), and __eq__.
  • Response(text, usage, provider): a plain class with those three attributes.
  • Provider, an abstract base class. Subclasses register themselves with a name in the class line, class EchoProvider(Provider, name="echo"), into Provider.registry (duplicates raise ValueError). __init__(self, model, temperature=0.0); temperature is a property validated to [0, 2] (ValueError), also at construction. complete(prompt) strips the prompt, rejects an empty one with ValueError, calls the abstract _generate(prompt) which returns (text, usage), adds the usage to a per-instance usage_total, and returns a Response with the provider's registered name. The classmethod from_config(config) builds the registered class named by config["provider"] (unknown names raise KeyError) with the remaining keys as keyword arguments.
  • EchoProvider (name "echo"): replies with the prompt; usage counts the words of the prompt and of the reply.
  • ReverseProvider (name "reverse"): replies with the prompt's words reversed; same usage rule.
  • CachedProvider(inner): composition, not inheritance. Its complete(prompt) returns the cached Response for a prompt already seen (after stripping), and otherwise delegates to inner.complete. It counts hits and misses, and exposes usage_total as a read-only property that forwards to the inner provider.

from abc import ABC, abstractmethod


class Usage:
    def __init__(self, prompt=0, completion=0):
        self.prompt = prompt
        self.completion = completion

    def __repr__(self):
        return f"Usage(prompt={self.prompt}, completion={self.completion})"

    @property
    def total(self):
        return self.prompt + self.completion

    def __add__(self, other):
        if not isinstance(other, Usage):
            return NotImplemented
        return Usage(self.prompt + other.prompt, self.completion + other.completion)

    def __radd__(self, other):
        if other == 0:
            return self
        return self.__add__(other)

    def __eq__(self, other):
        if not isinstance(other, Usage):
            return NotImplemented
        return (self.prompt, self.completion) == (other.prompt, other.completion)


class Response:
    def __init__(self, text, usage, provider):
        self.text = text
        self.usage = usage
        self.provider = provider


class Provider(ABC):
    registry = {}

    def __init_subclass__(cls, *, name, **kwargs):
        super().__init_subclass__(**kwargs)
        if name in Provider.registry:
            raise ValueError(f"provider {name!r} is already registered")
        cls.provider_name = name
        Provider.registry[name] = cls

    def __init__(self, model, temperature=0.0):
        self.model = model
        self.temperature = temperature
        self.usage_total = Usage()

    @property
    def temperature(self):
        return self._temperature

    @temperature.setter
    def temperature(self, value):
        if not 0 <= value <= 2:
            raise ValueError(f"temperature must be in [0, 2], got {value}")
        self._temperature = value

    @abstractmethod
    def _generate(self, prompt):
        ...

    def complete(self, prompt):
        prompt = prompt.strip()
        if not prompt:
            raise ValueError("prompt must not be empty")
        text, usage = self._generate(prompt)
        self.usage_total = self.usage_total + usage
        return Response(text, usage, self.provider_name)

    @classmethod
    def from_config(cls, config):
        options = dict(config)
        name = options.pop("provider")
        return cls.registry[name](**options)


class EchoProvider(Provider, name="echo"):
    def _generate(self, prompt):
        return prompt, Usage(len(prompt.split()), len(prompt.split()))


class ReverseProvider(Provider, name="reverse"):
    def _generate(self, prompt):
        text = " ".join(reversed(prompt.split()))
        return text, Usage(len(prompt.split()), len(text.split()))


class CachedProvider:
    def __init__(self, inner):
        self.inner = inner
        self._cache = {}
        self.hits = 0
        self.misses = 0

    def complete(self, prompt):
        key = prompt.strip()
        if key in self._cache:
            self.hits += 1
            return self._cache[key]
        self.misses += 1
        response = self.inner.complete(prompt)
        self._cache[key] = response
        return response

    @property
    def usage_total(self):
        return self.inner.usage_total

Every lesson of the module has a job here:

  • Classes and instances (9.1): each provider owns its usage_total, created in __init__; the only shared mutable state is the registry, written deliberately through Provider.registry.
  • Dunder methods (9.2): Usage behaves like a number: +, sum() (thanks to __radd__), equality and a readable repr.
  • Properties (9.3): temperature is validated on assignment and at construction, and a failed assignment keeps the old value; total and the cache's usage_total are read-only views.
  • Inheritance (9.4): complete is a template method; providers implement only _generate; __init_subclass__ registers each one by the name given in its class line and rejects duplicates.
  • Composition and ABCs (9.5): Provider cannot be instantiated without _generate; CachedProvider is not a Provider subclass but has the same complete method, so it wraps any provider.
  • Class methods (9.6): from_config picks the class from configuration and builds it, the way a settings file selects a model.

Real layers add streaming, tool calling and async methods, but they keep this shape: one small interface, implementations registered by name, shared behaviour in the base, and cross-cutting features as wrappers (and Module 11 will let type checkers verify the whole structure).

Recap

  • Own your state: create it in __init__, never in class attributes or mutable defaults, and hand out copies, not internals.
  • Make objects feel native with dunders; keep __eq__ and __hash__ consistent; return NotImplemented for foreign types.
  • Guard invariants with properties and validating methods, including in __init__.
  • Inherit for real "is a" relationships with template methods and super(); compose and inject for everything else.
  • Alternative constructors and registries are classmethods (or __init_subclass__) that build cls(...); copy objects according to what they mean.
