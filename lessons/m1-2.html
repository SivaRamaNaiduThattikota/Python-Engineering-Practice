1.2 Control flow and loops

if, for and while, plus the tools that make loops clean: range, enumerate, zip, break, continue and the loop else. Most interview warm-ups are loops, and most loop bugs are off by one.

1The rules in one screen

An if chain checks its conditions from top to bottom and runs only the first branch whose condition is true; once one branch has run, every later elif and the else are skipped, even if their conditions are also true.

ranges.py
print(list(range(5)))
print(list(range(2, 10, 3)))
print(list(range(5, 0, -1)))
print(list(range(5, 2)))
Output
[0, 1, 2, 3, 4]
[2, 5, 8]
[5, 4, 3, 2, 1]
[]

range(start, stop, step) includes start and stops before stop, like a half-open interval. The length of range(a, b) is b - a. A step that goes the wrong way gives an empty range, not an error.

enumerate_zip.py
names = ["Ana", "Ben", "Chi"]
scores = [91, 78, 85]
for i, name in enumerate(names, start=1):
    print(i, name)
for name, score in zip(names, scores):
    print(f"{name}: {score}")
Output
1 Ana
2 Ben
3 Chi
Ana: 91
Ben: 78
Chi: 85

enumerate gives you the position and the item together. zip walks several sequences side by side. Both remove the need for range(len(xs)) and the xs[i] lookups that come with it.

≈
SQL / Power BI

enumerate is ROW_NUMBER(). zip is a join by position, not by key: if one list is sorted differently or has a missing row, zip pairs the wrong rows and says nothing. It also silently stops at the shorter list. Pass strict=True and Python raises instead.

loop_else.py
for n in [3, 5, 8, 9]:
    if n % 2 == 0:
        print("first even:", n)
        break
else:
    print("no even numbers")

for n in [3, 5, 9]:
    if n % 2 == 0:
        print("first even:", n)
        break
else:
    print("no even numbers")
Output
first even: 8
no even numbers

break leaves the loop. continue skips to the next item. The loop else reads as "no break": it is the natural place for "searched everything and did not find it". A while loop can have an else too.

after_the_loop.py
total = 0
for i in range(1, 4):
    total += i
print(i, total)

n = 37
steps = 0
while n != 1:
    n = n // 2 if n % 2 == 0 else 3 * n + 1
    steps += 1
print(steps)
Output
3 6
21

The loop variable still exists after the loop and keeps its last value. x if cond else y is the one-line if, called a conditional expression. Use while when you do not know the number of passes in advance.

!
Changing a list while looping over it

Removing items from a list inside for x in items makes the loop skip the item after each removal, because the positions shift under it. Build a new list instead (problem 6).

≈
Row by row

A Python loop over rows is like a SQL cursor: fine for a few thousand items, slow for millions. In pandas and numpy you replace most loops with whole-column operations. That comes later, but the habit of asking "do I really need a loop here?" starts now.

3. Continue and the leftover variable

kept = 0

continue skips 0 and 3, so kept is 1 + 2 + 4 + 5 = 12. After the loop i still holds its last value, 5. Relying on that is fragile: if the list is empty, i is never set at all.

4. FizzBuzz

Write fizzbuzz(n) that returns a list of strings for 1 to n: "Fizz" for multiples of 3, "Buzz" for multiples of 5, "FizzBuzz" for multiples of both, and the number as a string otherwise.

TestsThe 4 checks Run tests uses
assert fizzbuzz(5) == ["1", "2", "Fizz", "4", "Buzz"]
assert fizzbuzz(15)[-1] == "FizzBuzz"
assert fizzbuzz(0) == []
assert fizzbuzz(30).count("FizzBuzz") == 2
Hint 1Open a hint

Loop over range(1, n + 1).

Hint 2Open a hint

Check the 15 case first, or it gets caught by the 3 case.

SolutionShow the solution and why
solution.py
def fizzbuzz(n):
    out = []
    for i in range(1, n + 1):
        if i % 15 == 0:
            out.append("FizzBuzz")
        elif i % 3 == 0:
            out.append("Fizz")
        elif i % 5 == 0:
            out.append("Buzz")
        else:
            out.append(str(i))
    return out

The order of the elif chain is the whole problem: the most specific condition goes first. Interviewers use it to see clean branching and range(1, n + 1), which catches the classic off-by-one of range(n).

5. First value over a limit

Write first_over(nums, limit) that returns the index of the first number greater than limit, or -1 if there is none. Use enumerate.

TestsThe 4 checks Run tests uses
assert first_over([3, 8, 12, 20], 10) == 2
assert first_over([3, 8], 10) == -1
assert first_over([], 0) == -1
assert first_over([11, 50], 10) == 0
HintOpen a hint

for i, x in enumerate(nums): and return as soon as you find it.

SolutionShow the solution and why
solution.py
def first_over(nums, limit):
    for i, x in enumerate(nums):
        if x > limit:
            return i
    return -1

Returning from inside the loop is the cleanest break. The return -1 after the loop is the "searched everything" case, the same idea as the loop else. This is what str.find and many search helpers do.

6. Removing negatives skips some

This should remove every negative number from the list and return it. It misses some. Fix it.

TestsThe 4 checks Run tests uses

assert remove_negatives([-1, -2, 3]) == [3]
assert remove_negatives([-5, -5, -5]) == []

Hint 1Open a hint

Trace [-1, -2, 3] by hand. After -1 is removed, what is at position 0, and which position does the loop look at next?

Hint 2Open a hint

Do not change the list you are looping over. Build a new one.

SolutionShow the solution and why
solution.py
def remove_negatives(nums):
    return [x for x in nums if x >= 0]

The for loop walks positions 0, 1, 2... Removing -1 shifts -2 into position 0, but the loop moves on to position 1 and never sees it. Building a new list avoids the problem and also leaves the caller's list untouched (more on why that matters in Module 2). If you must change it in place, nums[:] = [...] does it.

7. The last n items

last_n(items, n) should return the last n items in order. It is off by one. Fix the loop.

TestsThe 4 checks Run tests uses
assert last_n([1, 2, 3, 4], 2) == [3, 4]
assert last_n([1, 2, 3], 3) == [1, 2, 3]
assert last_n([1, 2], 0) == []
assert last_n(["a"], 1) == ["a"]
HintOpen a hint

What is the last index of a list? What does range do with its stop?

SolutionShow the solution and why
solution.py
def last_n(items, n):
    out = []
    for i in range(len(items) - n, len(items)):
        out.append(items[i])
    return out

The last index is len(items) - 1, and range already stops before stop, so stop should be len(items). Subtracting 1 twice is the most common off-by-one there is. Why not items[-n:]? Try it with n = 0: items[-0:] is items[0:], the whole list. That slicing trap comes back in Module 4.

9. Pair names with scores

Write pair_up(names, scores) that returns a list of strings like "Ana: 91". If the two lists have different lengths it must raise ValueError, because pairing by position would be wrong.

TestsThe 4 checks Run tests uses
def raises(exc, f, *args):
    try:
        f(*args)
    except exc:
        return True
    return False
assert pair_up(["Ana", "Ben"], [91, 78]) == ["Ana: 91", "Ben: 78"]
assert pair_up([], []) == []
assert raises(ValueError, pair_up, ["Ana"], [91, 78])
assert raises(ValueError, pair_up, ["Ana", "Ben"], [91])
HintOpen a hint

zip has a keyword argument that turns a length mismatch into an error.

SolutionShow the solution and why
solution.py
def pair_up(names, scores):
    return [f"{name}: {score}" for name, score in zip(names, scores, strict=True)]

Plain zip would quietly drop the extra score, and in a data pipeline that is a silent wrong answer. strict=True (Python 3.10+) raises ValueError as soon as one side runs out early. Use it whenever the inputs are supposed to line up.

10. Running maximum

Write running_max(nums) that returns a list where each position holds the largest value seen so far. [3, 1, 4, 1, 5] gives [3, 3, 4, 4, 5]. This is a cumulative max, like a running total in Power BI.

TestsThe 4 checks Run tests uses
assert running_max([3, 1, 4, 1, 5]) == [3, 3, 4, 4, 5]
assert running_max([]) == []
assert running_max([-2, -5, -1]) == [-2, -2, -1]
assert running_max([7]) == [7]
Hint 1Open a hint

Keep one variable for the best so far. Start it from the first value, not from 0, or negative inputs break.

Hint 2Open a hint

Or start it at float('-inf').

SolutionShow the solution and why
solution.py
def running_max(nums):
    out = []
    best = float("-inf")
    for x in nums:
        best = max(best, x)
        out.append(best)
    return out

Starting best at 0 is the classic bug: [-2, -5, -1] would give [0, 0, 0]. Minus infinity is smaller than any number, so the first value always wins. The library version is itertools.accumulate(nums, max), and in pandas it is s.cummax().

12. Use enumerate and zip

Rewrite this without manual indexes. Keep the tests green.

TestsThe 3 checks Run tests uses
assert report(["Ana", "Ben"], [91, 78]) == ["1. Ana 91", "2. Ben 78"]
assert report([], []) == []
assert report(["Chi"], [85]) == ["1. Chi 85"]
HintOpen a hint

enumerate(zip(names, scores), start=1) gives (i, (name, score)).

SolutionShow the solution and why
solution.py
def report(names, scores):
    return [f"{i}. {name} {score}"
            for i, (name, score) in enumerate(zip(names, scores), start=1)]

No counter to forget to increment, no [i] lookups, and start=1 replaces the i + 1. Nested unpacking (name, score) pulls the pair apart right in the loop header. A while loop with a manual counter is almost always a for loop in disguise.

13. Two numbers that add up

Write find_pair(nums, target) that returns the first pair of positions (i, j) with i < j and nums[i] + nums[j] == target, scanning i from left to right. Return None if there is no pair.

TestsThe 5 checks Run tests uses
assert find_pair([2, 7, 11, 15], 9) == (0, 1)
assert find_pair([3, 2, 4], 6) == (1, 2)
assert find_pair([3, 3], 6) == (0, 1)
assert find_pair([1, 2, 3], 7) is None
assert find_pair([], 1) is None
Hint 1Open a hint

Two nested loops: j starts at i + 1 so a number is never paired with itself.

Hint 2Open a hint

To stop both loops at once, return from inside the inner one.

SolutionShow the solution and why
solution.py
def find_pair(nums, target):
    for i in range(len(nums)):
        for j in range(i + 1, len(nums)):
            if nums[i] + nums[j] == target:
                return i, j
    return None

break only leaves the inner loop, so for "stop everything" put the loops in a function and return. Starting j at i + 1 skips self-pairs and duplicate pairs. This is the brute force O(n²) answer to the most famous interview question there is. Say so, then give the one-pass dict version (Module 4).

14. Primes with a loop else

Write primes_up_to(n) that returns all primes up to and including n. Use a for ... else to decide whether a number is prime, and only test divisors up to its square root.

TestsThe 5 checks Run tests uses
assert primes_up_to(10) == [2, 3, 5, 7]
assert primes_up_to(1) == []
assert primes_up_to(2) == [2]
assert primes_up_to(30)[-1] == 29
assert len(primes_up_to(100)) == 25
Hint 1Open a hint

For each candidate k, loop over d from 2 while d * d <= k. A range can do it: range(2, int(k ** 0.5) + 1).

Hint 2Open a hint

break when d divides k. The else of that inner loop is where k is prime.

SolutionShow the solution and why
solution.py
def primes_up_to(n):
    primes = []
    for k in range(2, n + 1):
        for d in range(2, int(k ** 0.5) + 1):
            if k % d == 0:
                break
        else:
            primes.append(k)
    return primes

If k has a divisor larger than its square root, it also has one smaller than it, so checking up to the square root is enough. The else belongs to the inner for: it runs when no divisor was found. For 2 and 3 the inner range is empty, so else runs straight away, which is correct. For big n, the sieve of Eratosthenes is much faster (Module 16).

15. Run lengths

Write run_lengths(xs) that turns consecutive repeats into (value, count) pairs: [1, 1, 2, 2, 2, 1] gives [(1, 2), (2, 3), (1, 1)]. In SQL this is the "gaps and islands" problem: grouping consecutive rows with the same status.

TestsThe 5 checks Run tests uses
assert run_lengths([1, 1, 2, 2, 2, 1]) == [(1, 2), (2, 3), (1, 1)]
assert run_lengths([]) == []
assert run_lengths(["a"]) == [("a", 1)]
assert run_lengths([0, 0, 0]) == [(0, 3)]
assert run_lengths([None, None, 1]) == [(None, 2), (1, 1)]
Hint 1Open a hint

Keep the current value and its count. When the value changes, save the finished run and start a new one.

Hint 2Open a hint

Do not forget the last run: it is still open when the loop ends.

SolutionShow the solution and why
solution.py
def run_lengths(xs):
    out = []
    for x in xs:
        if out and out[-1][0] == x:
            out[-1] = (x, out[-1][1] + 1)
        else:
            out.append((x, 1))
    return out

Looking at the last saved run (out[-1]) avoids a separate "current" variable and the classic bug of forgetting the final run after the loop. Note if out and ...: the truthiness check stops out[-1] failing on the first item, and it keeps working when the value is 0 or None. The library version is itertools.groupby.

5Interview questions

Interview

17. Is for i in range(len(xs)) wrong?

SolutionModel answer

Not wrong, but usually a sign something cleaner exists. Use for x in xs for the items, enumerate(xs) if you also need the index, and zip(a, b) to walk two lists together. range(len(...)) is fine when you really work with positions, for example comparing xs[i] with xs[i + 1] or the nested j in i + 1 loops.

Interview

18. What does else on a loop do, and when would you use it?

SolutionModel answer

It runs when the loop finishes without break. That makes it the "not found" branch of a search: loop over candidates, break when one matches, put the fallback in else. It replaces a found = False flag. It is easy to misread as "runs if the loop did not run", so many teams prefer a function with an early return. Know both, and say why.

Data work

19. Why is looping over rows slow in pandas, and what do you do instead?

SolutionModel answer

Each pass of a Python loop runs the interpreter: look up the row, build Python objects, call your function. df.iterrows() even builds a new Series per row. Whole-column operations (df["a"] * df["b"], np.where, .groupby().agg()) run one compiled loop in C over the raw arrays, often 100 times faster. It is the same lesson as cursors versus set-based SQL. Loops are still fine for small data or for logic that really goes row by row.

Recap

  • range(start, stop, step) never includes stop. The last index is len(xs) - 1, so range(len(xs)) is already right.
  • enumerate for index + item, zip to walk lists together, zip(..., strict=True) when they must line up.
  • break leaves the loop, continue skips to the next pass, and the loop else runs only if there was no break.
  • Never add to or remove from a list while looping over it. Build a new list.
  • To leave nested loops, put them in a function and return. Use while when the number of passes is unknown.
