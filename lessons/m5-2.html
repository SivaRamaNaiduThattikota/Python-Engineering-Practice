5.2 String methods

The methods you use daily for cleaning and parsing text, with the exact rules that cause bugs: split() versus split(" "), strip removing a set of characters rather than a prefix, partition, case methods that change length, the digit tests, translate, and building aligned text.

19 problems4 easy · 10 medium · 5 hard

1Splitting and joining

split is the workhorse of text parsing, and its two modes behave differently in a way that matters:

  • s.split() with no argument splits on any run of whitespace (spaces, tabs, newlines), ignores leading and trailing whitespace, and never returns empty strings. It is the right choice for "the words of this text".
  • s.split(sep) splits on exactly sep, and keeps the empty strings between consecutive separators and at the ends. It is the right choice for formats with a fixed delimiter, where an empty field is meaningful.
split.py
line = "  refund   policy\tEU  "
print(line.split())                    # words
print(line.split(" "))                 # every single space is a separator
print("a,,b,".split(","))              # empty fields are kept
print("k=v=w".split("=", 1), "a/b/c".rsplit("/", 1))   # maxsplit: split only so many times
print("one\ntwo\r\nthree\n".splitlines(), "one\ntwo\n".split("\n"))
Output
['refund', 'policy', 'EU']
['', '', 'refund', '', '', 'policy\tEU', '', '']
['a', '', 'b', '']
['k', 'v=w'] ['a/b', 'c']
['one', 'two', 'three'] ['one', 'two', '']

maxsplit limits the number of splits, which keeps any later separators inside the last part: "k=v=w".split("=", 1) gives a key and a value that may itself contain =. rsplit splits from the right, so rsplit("/", 1) separates a file name from its directory. splitlines() splits on every kind of line break (\n, \r\n and others) and does not produce a trailing empty string, which split("\n") does when the text ends with a newline.

sep.join(iterable) is the inverse: it puts sep between the items, which must all be strings (a number in the list raises TypeError; convert with map(str, ...)). It is the efficient way to build text (5.1).

SQL / Power BI

split(",") is SQL Server's STRING_SPLIT(s, ',') and Power Query's "Split column by delimiter"; ",".join(values) is STRING_AGG(value, ',') or DAX CONCATENATEX. Power Query's "Trim" and "Clean" steps correspond to strip() and removing control characters.

2partition: split once, never fail

s.partition(sep) splits at the first sep and always returns three parts: the text before, the separator itself, and the text after. If sep is not present, you get (s, "", ""): the middle part being empty tells you it was missing. rpartition does the same at the last occurrence. Because it always returns three items, it unpacks safely, which makes it ideal for "key: value" lines, URLs and file names.

partition.py
key, sep, value = "Authorization: Bearer abc:123".partition(": ")
print(key, "|", value)
print("no separator here".partition("="))
base, dot, ext = "report.final.pdf".rpartition(".")
print(base, ext, "README".rpartition("."))
Output
Authorization | Bearer abc:123
('no separator here', '', '')
report.final pdf ('', '', 'README')

3Trimming: strip removes characters, removeprefix removes a prefix

strip(), lstrip() and rstrip() with no argument remove whitespace from the ends. With an argument, they remove any of those characters, in any order and any number of times, until they meet a character not in the set. They do not remove a prefix or suffix as a unit. That is a famous bug: url.lstrip("https://") removes every leading h, t, p, s, : and /, which also eats the start of a domain such as "shop.example.com".

strip.py
print("xxhixx".strip("x"), "  hi \n".strip(), "--==hi==--".strip("-="))
url = "https://shop.example.com/refunds"
print(url.lstrip("https://"))                 # removes characters: 'shop' loses its letters too
print(url.removeprefix("https://"))           # removes the prefix once, exactly
print("report.csv.csv".removesuffix(".csv"), "data.json".rstrip(".json"))
Output
hi hi hi
op.example.com/refunds
shop.example.com/refunds
report.csv data

Use removeprefix and removesuffix (Python 3.9+) to remove a known prefix or suffix exactly once; they return the string unchanged if it does not start or end with it. Keep strip(chars) for its real purpose: trimming a set of padding characters such as quotes, punctuation or zero-width spaces.

4Case, replacing and testing

upper, lower, casefold, title, capitalize and swapcase all return new strings. Two warnings. title() upper-cases the first letter after any non-letter, so "o'neil's" becomes "O'Neil'S"; it is meant for simple words, not names or headlines. And case mapping can change the length of a string, because some characters map to several ("ß".upper() is "SS"), so never assume len(s.upper()) == len(s).

case.py
print("o'neil's refund".title(), "it's fine".capitalize())
print("ß".upper(), len("Straße".upper()), "ﬁle".upper())
print("refund refund refund".replace("refund", "return", 2))
Output
O'Neil'S Refund It's fine
SS 7 FILE
return return refund

replace(old, new, count) replaces non-overlapping occurrences, left to right, optionally only the first count. The is... tests check that every character is of a kind, and return False for the empty string. The digit tests differ in what they accept, which matters for user input:

    print(f"{s!r:6} isdecimal={s.isdecimal()!s:5} isdigit={s.isdigit()!s:5} isnumeric={s.isnumeric()!s:5}")
print("Refund".isalpha(), "café".isalpha(), "abc123".isalnum(), " \t\n".isspace())
Output

'-5'   isdecimal=False isdigit=False isnumeric=False
'3.2'  isdecimal=False isdigit=False isnumeric=False

None of them recognise "-5" or "3.2", and isdigit accepts "²", which int() rejects. To check whether text is a number, the reliable test is to try converting it (int(s) or float(s) inside try, Module 8). isdecimal is the closest match to "characters int() accepts"; note that it accepts digits from other scripts, such as Arabic-Indic "٤٢", which int also converts to 42.

5translate and alignment

For mapping or deleting many characters at once, str.maketrans builds a table and translate applies it in a single pass in C: much faster and clearer than a chain of replace calls. maketrans takes either a dict from characters to replacements (or None to delete), or two equal-length strings to map, plus an optional third string of characters to delete.

translate.py
import string

no_punct = str.maketrans("", "", string.punctuation)
print("Refund?! (EU-only), see: faq.".translate(no_punct))
smart = str.maketrans({"\u2018": "'", "\u2019": "'", "\u201c": '"', "\u201d": '"', "\u00a0": " "})
print("\u201cIt\u2019s\u00a0fine\u201d".translate(smart))
Output
Refund EUonly see faq
"It's fine"

For fixed-width text such as console tables and logs, ljust(width), rjust(width) and center(width) pad a string to a width (with spaces or a fill character), and zfill(width) pads a number string with zeros, keeping a sign in front. f-strings can do the same with format specs (5.3).

align.py
rows = [("faq.md", 0.913), ("terms-and-conditions.md", 0.4), ("api.md", 0.75)]
width = max(len(name) for name, _ in rows)
for name, score in rows:
    print(name.ljust(width), str(round(score, 2)).rjust(5))
print("7".zfill(3), "-7".zfill(4))
Output
faq.md                   0.91
terms-and-conditions.md   0.4
api.md                   0.75
007 -007

domain(url) should return the host of an https:// or http:// URL. For "https://shop.example.com/x" it returns "op.example.com". Fix it.

Hint 2Open a hint

SolutionShow the solution and why
solution.py
def domain(url):
    rest = url.removeprefix("https://").removeprefix("http://")
    return rest.partition("/")[0]

3. A URL slug without regex

Write slugify(title) that lower-cases the title, turns every run of characters that are not letters or digits into a single -, and removes - at the ends. Use isalnum and join, not regex.

HintOpen a hint

Replace each non-alphanumeric character with a space, then "-".join(text.split()) collapses runs and drops the ends.

SolutionShow the solution and why
solution.py
def slugify(title):
    spaced = "".join(ch if ch.isalnum() else " " for ch in title.lower())
    return "-".join(spaced.split())

Turning separators into spaces and then using split() reuses its two best properties: runs collapse into one break, and the ends disappear, so join with - produces exactly one dash between words and none at the edges. isalnum is Unicode-aware, so accented letters stay. Many systems also remove accents for slugs (normalise to NFKD and drop combining marks, 5.4) so URLs stay ASCII.

Each test is stricter than the next: isdecimal ⊂ isdigit ⊂ isnumeric. None accept signs or decimal points.

SolutionShow the solution and why
Real output

['7', '007', '²', '٧']
['7', '007', '²', '½', '٧']

isdecimal accepts only characters that are decimal digits in some script, including the Arabic-Indic "٧". isdigit also accepts superscripts like "²", and isnumeric also accepts fractions like "½". All three reject the sign and the decimal point, and are False for the empty string. int accepts leading zeros, other scripts' digits and surrounding whitespace. So "is this a number?" is best answered by attempting the conversion.

5. Parse key: value lines

An LLM was asked to answer as lines of key: value. Write parse_fields(text) that returns a dict from lower-cased, stripped keys to stripped values. Skip blank lines and lines starting with #. Values may themselves contain :. A line without : raises ValueError naming the line.

TestsThe 3 checks Run tests uses
def raises(exc, f, *args):
    try:
        f(*args)
    except exc as e:
        return str(e)
    return False
out = parse_fields("Title: Refund delayed\n\n# model notes\nPriority : high\nURL: https://x.io/a")
assert out == {"title": "Refund delayed", "priority": "high", "url": "https://x.io/a"}
assert parse_fields("") == {}
msg = raises(ValueError, parse_fields, "title: ok\nnot a field")
assert msg and "not a field" in msg
HintOpen a hint

text.splitlines(), then key, sep, value = line.partition(":"). An empty sep means the line had no colon.

SolutionShow the solution and why
solution.py
def parse_fields(text):
    out = {}
    for line in text.splitlines():
        line = line.strip()
        if not line or line.startswith("#"):
            continue
        key, sep, value = line.partition(":")
        if not sep:
            raise ValueError(f"not a key: value line: {line!r}")
        out[key.strip().lower()] = value.strip()
    return out

partition(":") splits only at the first colon, so the URL keeps its own colon, and its empty middle part is a clean signal for a malformed line. split(":") would cut the URL into pieces. Raising with the offending line in the message makes the error useful to log or to send back to the model for a retry. For anything nested or typed, ask the model for JSON instead and parse it with json.loads (Module 12).

6. Title case that mangles names

display_name formats names from a CRM: the first letter of each space-separated word upper-case, the rest lower-case, and extra spaces removed. title() gets it wrong: "mcdonald's" becomes "Mcdonald'S". Fix it.

TestsThe 4 checks Run tests uses

assert display_name("  ana   lopez ") == "Ana Lopez"
assert display_name("o'neil") == "O'neil"
assert display_name("") == ""
HintOpen a hint

Split on whitespace, then build each word as w[:1].upper() + w[1:].lower().

SolutionShow the solution and why
solution.py
def display_name(name):
    return " ".join(w[:1].upper() + w[1:].lower() for w in name.split())

title() treats every non-letter, including an apostrophe, as a word boundary, so the s after ' is capitalised. Splitting on whitespace gives the words you actually mean, and w[:1] (not w[0]) is safe even for an empty string. str.capitalize per word would do the same. Note that this rule is still wrong for names like "McDonald" or "van der Berg": real name formatting is cultural, which is why systems should store names as typed rather than re-case them.

9. An aligned text table

Write format_table(header, rows) that returns the table as a string: one line per row, columns separated by two spaces, each column as wide as its widest cell (header included). Text columns are left-aligned; columns whose cells are all numbers (int or float) are right-aligned. Lines must have no trailing spaces.

TestsThe 2 checks Run tests uses
out = format_table(["doc", "score", "tokens"], [["faq.md", 0.91, 120], ["terms-and-conditions.md", 0.4, 2300]])
assert out == (
    "doc                      score  tokens\n"
    "faq.md                    0.91     120\n"
    "terms-and-conditions.md    0.4    2300"
)
assert format_table(["a"], []) == "a"
Hint 1Open a hint

Convert every cell with str, then compute each column's width with max(len(...)) over the header and the cells.

Hint 2Open a hint

A column is numeric when every row's value in it is an int or float. Join the padded cells with two spaces and rstrip each line.

SolutionShow the solution and why
solution.py
def format_table(header, rows):
    cols = list(zip(*([header] + rows)))
    widths = [max(len(str(c)) for c in col) for col in cols]
    numeric = [bool(rows) and all(isinstance(r[i], (int, float)) for r in rows) for i in range(len(header))]
    lines = []
    for row in [header] + rows:
        cells = [str(c).rjust(w) if num else str(c).ljust(w) for c, w, num in zip(row, widths, numeric)]
        lines.append("  ".join(cells).rstrip())
    return "\n".join(lines)

Transposing with zip(*...) (4.3) gives each column, so widths are one max per column. Right-aligning numbers makes their digits line up, the convention in every spreadsheet and report; the header of a numeric column is right-aligned too, so it sits over its numbers. rstrip removes the padding after the last column, which would otherwise make tests and diffs noisy. Libraries such as tabulate and rich do this (with borders and colours); pandas does it in DataFrame.to_string.

13. Greedy word wrap

Write wrap(text, width) that returns a list of lines, each at most width characters, filled greedily with whole words separated by single spaces. A word longer than width goes on its own line, unbroken. Whitespace in the input is normalised.

TestsThe 4 checks Run tests uses
t = "Refunds are processed within five business days of the request"
assert wrap(t, 20) == ["Refunds are", "processed within", "five business days", "of the request"]
assert wrap("a supercalifragilistic word", 10) == ["a", "supercalifragilistic", "word"]
assert wrap("", 10) == [] and wrap("  one  ", 3) == ["one"]
assert all(len(l) <= 20 for l in wrap(t, 20))
Hint 1Open a hint

Walk the words with a current list and its length. Adding a word costs len(word) plus one space if the line is not empty.

Hint 2Open a hint

When the next word does not fit, finish the current line with " ".join(current) and start a new one with that word.

SolutionShow the solution and why
solution.py
def wrap(text, width):
    lines, current, length = [], [], 0
    for word in text.split():
        extra = len(word) + (1 if current else 0)
        if current and length + extra > width:
            lines.append(" ".join(current))
            current, length = [word], len(word)
        else:
            current.append(word)
            length += extra
    if current:
        lines.append(" ".join(current))
    return lines

Tracking the current length avoids re-measuring the joined line for every word, so the function is O(n). The if current checks handle two edge cases at once: the first word on a line needs no space, and a word longer than the width is accepted onto an empty line instead of looping forever. The final if current flushes the last line, the classic thing to forget (1.2, run lengths). textwrap.wrap in the standard library does this with more options, including breaking long words.

A " inside quotes followed by another " is a literal quote; otherwise it closes the quotes. Use an index loop so you can look one character ahead.

solution.py
def split_fields(line, sep=","):
    fields, current, in_quotes = [], [], False
    i = 0
    while i < len(line):
        ch = line[i]
        if in_quotes:
            if ch == '"' and i + 1 < len(line) and line[i + 1] == '"':
                current.append('"')
                i += 1
            elif ch == '"':
                in_quotes = False
            else:
                current.append(ch)
        elif ch == '"':
            in_quotes = True
        elif ch == sep:
            fields.append("".join(current))
            current = []
        else:
            current.append(ch)
        i += 1
    fields.append("".join(current))
    return fields

line.split(",") breaks "Lopez, Ana" into two fields, which shifts every later column by one: the most common bug in hand-rolled CSV parsing. A small state machine (inside or outside quotes) fixes it, with one look-ahead for the doubled quote. Characters are collected in a list and joined per field (5.1). The final append keeps the last field even when it is empty. In real code use the csv module (Module 12), which implements exactly these rules plus newlines inside quoted fields and other dialects.

Interview

17. What is the difference between s.split() and s.split(" ")?

SolutionModel answer

split() with no argument splits on any run of whitespace (spaces, tabs, newlines, and Unicode spaces such as a non-breaking space), ignores leading and trailing whitespace and never returns empty strings: it gives the words. split(" ") splits on each single space character only: consecutive spaces produce empty strings, tabs and newlines are not separators, and leading or trailing spaces produce empty strings at the ends. Use split() for natural text and split(sep) for delimited formats where empty fields matter. Mention maxsplit, rsplit, partition for "split once" and splitlines for line breaks.

Interview

18. Why does "https://shop.com".lstrip("https://") give "op.com"?

SolutionModel answer

lstrip (like strip and rstrip) treats its argument as a set of characters, not as a prefix: it removes characters from the left as long as each one is in {"h", "t", "p", "s", ":", "/"}. After https:// it continues through s and h of shop and stops at o. To remove an exact prefix or suffix once, use removeprefix / removesuffix (Python 3.9+) or slice after a startswith check. The same trap applies to rstrip(".json"), which would also eat a trailing n or o of the name. Use strip(chars) only for trimming a set of padding characters.

Interview

19. How would you normalise text before matching or deduplicating it, and what can go wrong?

SolutionModel answer

A typical pipeline: Unicode-normalise (NFC to unify composed and decomposed accents, or NFKC to also fold compatibility forms such as ligatures and full-width letters), casefold for case, collapse whitespace with " ".join(s.split()), map typographic quotes and dashes with a translation table, and optionally remove punctuation or accents. What can go wrong: each step loses information, so normalise a copy for matching and keep the original for display; NFKC changes meaning in some cases ("²" becomes "2"); removing accents merges different words in some languages; and normalising one side of a comparison but not the other silently breaks matches. Apply the same function to both sides, and test it with real messy examples.

Recap

  • split() gives words (any whitespace, no empties); split(sep) follows a delimiter exactly and keeps empty fields. splitlines() handles \r\n.
  • partition and rpartition split once and always return three parts: the safe way to parse key: value, URLs and file names.
  • strip(chars) removes a set of characters. Use removeprefix / removesuffix for an exact prefix or suffix.
  • Case mapping can change length; compare with casefold(). The is... digit tests do not answer "is this a number?": try converting.
  • Use translate for many single-character replacements, join to build, and format_map (not repeated replace) to fill templates.
