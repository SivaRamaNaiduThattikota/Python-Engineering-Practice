1.1 Numbers, operators and truthiness

Division, rounding, precedence and what counts as false. Small rules, but each one is a classic source of silent bugs in data code, and a favourite in interviews.

19 problems6 easy · 8 medium · 5 hard

1The rules in one screen

Three number types cover daily work: int (whole numbers with no size limit), float (64-bit binary, about 15 to 16 significant digits) and bool, which is a kind of int: True is 1 and False is 0.

division.py
print(7 / 2, 7 // 2, 7 % 2)
print(-7 / 2, -7 // 2, -7 % 2)
print(divmod(-7, 2))
print(int(-3.5))
Output
3.5 3 1
-3.5 -4 1
(-4, 1)
-3

/ always gives a float. // floors: it rounds toward minus infinity, not toward zero. % follows the same rule, so (a // b) * b + a % b == a is always true and the remainder takes the sign of the divisor. int() on a float just cuts off the decimals, which moves toward zero.

i
Step by step: why -7 // 2 is -4
  • Step 1, divide exactly. -7 / 2 is -3.5.
  • Step 2, floor it. Floor means "the nearest whole number that is less than or equal to it". The two whole numbers around -3.5 are -4 and -3. Which one is smaller? -4, because on the number line it is further left. So the answer is -4. For negative numbers, "down" moves away from zero.
  • Step 3, the remainder fills the gap. -7 % 2 is whatever makes 2 * (-7 // 2) + (-7 % 2) == -7 true: 2 * -4 is -8, and -8 needs +1 to get back to -7. So -7 % 2 is 1.
  • Compare with positive 7. 7 / 2 is 3.5, the whole numbers around it are 3 and 4, and the smaller is 3. So 7 // 2 is 3. Same rule both times: always pick the smaller neighbour.
≈
SQL / Power BI

In SQL Server, integer division truncates: -7 / 2 is -3. Python's -7 // 2 is -4. Port a bucketing or week-number calculation from SQL and negative values land in a different bucket. In DAX, INT() rounds down like //, and TRUNC() behaves like int().

import math

Floats are stored in binary, so 0.1 is already slightly off before you add anything. Never compare floats with ==. Use math.isclose (in numpy np.isclose, in tests pytest.approx). round() rounds a tie to the nearest even number, called banker's rounding. And 2.675 is really stored as 2.67499999..., so it rounds down.

≈
Matching a SQL or Excel report

ROUND(2.5, 0) gives 3 in SQL Server and in Excel: both round a tie away from zero. Python gives 2. When a Python number has to match a finance report to the cent, use decimal.Decimal with ROUND_HALF_UP (problem 12).

** binds tighter than the minus sign in front of it, and it groups right to left: 2 ** 3 ** 2 is 2 ** 9. Comparisons chain: a < b < c means a < b and b < c. not is weaker than ==, so not 1 == 2 is not (1 == 2).

truthiness.py
for v in [0, 0.0, "", [], {}, None, "0", " ", [0], -1]:

    #   !r   show v the way you would type it in code (its repr),

    #        Without !r, "" and " " would print as nothing at all.

Output

  0.0 -> False
   '' -> False
   [] -> False
   {} -> False
 None -> False
  '0' -> True
  ' ' -> True
  [0] -> True

In the f-string, !r shows each value as its repr, the form you would type in code, so "0" appears as '0' and the empty string as ''. Without !r, the empty string and the space would print as blanks and you could not tell them apart. :>5 pads the text to 5 characters, aligned right. Compare print(f"{'0'}"), which prints 0, with print(f"{'0'!r}"), which prints '0'. Strings (Module 5) covers f-string formatting fully.

Falsy means "acts as False in an if": None, False, zero of any number type, and empty containers. Everything else is truthy, including the string "0", a space, and a list holding a zero.

and_or.py
print(0 or "default")
print("" and 5)
print(3 and 4)
print(None or 0 or [])
Output
default

4
[]

and and or return one of their operands, not True or False. or returns the first truthy value (or the last one if none are). and returns the first falsy value (or the last one). Both stop early, which is called short-circuit evaluation.

!
The COALESCE trap

x or default looks like SQL's COALESCE(x, default), but COALESCE only replaces NULL. or also replaces 0, "" and [], which are often valid values. The real COALESCE is default if x is None else x.

SolutionShow the solution and why
solution.py
def is_even(n):
    return n % 2 == 0

n % 2 is 0 for even numbers and 1 for odd ones, also for negatives, because the remainder takes the sign of the divisor (2). In C or Java, -3 % 2 is -1, so the common check n % 2 == 1 for "odd" breaks there on negatives. In Python it is safe, but n % 2 == 0 is safe everywhere.

6. The total that never matches

A reconciliation script checks that two amounts add up to an expected total. It reports a mismatch for 0.1 + 0.2 against 0.3. Fix totals_match so it compares the way floats should be compared.

TestsThe 4 checks Run tests uses
assert totals_match(0.1, 0.2, 0.3)
assert totals_match(1.5, 2.5, 4.0)
assert not totals_match(0.1, 0.2, 0.31)
assert totals_match(0.3, -(0.1 + 0.2), 0.0)
Hint 1Open a hint

Look in the math module for a function that compares with a tolerance.

Hint 2Open a hint

The last test compares against 0.0. A relative tolerance of a tiny number around zero is still tiny. Check the abs_tol argument.

SolutionShow the solution and why
solution.py
import math

def totals_match(a, b, expected):
    return math.isclose(a + b, expected, abs_tol=1e-9)

math.isclose uses a relative tolerance by default (rel_tol=1e-09), meaning "within a billionth of the size of the numbers". Near zero that window shrinks to nothing: 0.3 - (0.1 + 0.2) is about -5.6e-17, and no relative tolerance of 0.0 accepts that. abs_tol adds a fixed floor, which you need for anything that should be 0, like a residual or a difference. For money, the real fix is to store cents as int or use Decimal.

Hint 1Open a hint

What does 0 or 10 return?

Hint 2Open a hint

You want to replace only None, the way COALESCE replaces only NULL.

SolutionShow the solution and why
solution.py
def final_price(price, discount_pct=None):
    pct = 10 if discount_pct is None else discount_pct
    return round(price * (1 - pct / 100), 2)

0 or 10 is 10 because 0 is falsy. "Missing" and "zero" are different things, so test for None directly. The same bug shows up in pandas as df["x"].fillna(...) versus df["x"].replace(0, ...): decide which one you mean.

def age_band(age):
    if age < 0:
        return "invalid"
    if age < 13:
        return "child"
    if 13 <= age < 18:
        return "teen"
    if 18 <= age < 65:

Write round_half_up(x, digits=0) that rounds the way Excel and SQL Server do: ties go away from zero. Return a float. round_half_up(2.675, 2) must give 2.68, even though round(2.675, 2) gives 2.67.

assert round_half_up(7.0) == 7.0
Hint 1Open a hint

The decimal module has a rounding mode called ROUND_HALF_UP.

Hint 2Open a hint

Decimal(2.675) copies the binary error. Decimal(str(2.675)) starts from the text you see.

Hint 3Open a hint

Decimal.quantize(Decimal('0.01'), rounding=...) rounds to two places.

SolutionShow the solution and why
solution.py
from decimal import Decimal, ROUND_HALF_UP

def round_half_up(x, digits=0):
    step = Decimal(1).scaleb(-digits)        # 0 -> 1, 2 -> 0.01
    d = Decimal(str(x)).quantize(step, rounding=ROUND_HALF_UP)
    return float(d)

Two separate problems hide here. First, round uses banker's rounding, so round(2.5) is 2. Second, the float 2.675 is really 2.67499999..., so any rounding of the float itself goes down. Going through str(x) gives the short decimal text Python prints ('2.675'), and Decimal then does exact decimal arithmetic. ROUND_HALF_UP in the decimal module means "ties away from zero", so -2.5 becomes -3.

13. Min-max scaling

Write minmax_scale(xs) that rescales a list of numbers to the range 0 to 1: (x - min) / (max - min). An empty list gives []. If every value is the same, return all 0.0 instead of dividing by zero.

TestsThe 5 checks Run tests uses
import math
assert minmax_scale([10, 20, 30]) == [0.0, 0.5, 1.0]
assert minmax_scale([5, 5, 5]) == [0.0, 0.0, 0.0]
assert minmax_scale([]) == []
assert minmax_scale([-1, 1]) == [0.0, 1.0]
assert all(math.isclose(a, b) for a, b in zip(minmax_scale([0.1, 0.2, 0.3]), [0.0, 0.5, 1.0]))
Hint 1Open a hint

Handle the empty list first, before calling min or max (they fail on empty input).

Hint 2Open a hint

Compute span = max - min once. If it is 0, every output is 0.0.

SolutionShow the solution and why
solution.py
def minmax_scale(xs):
    if not xs:
        return []
    lo, hi = min(xs), max(xs)
    span = hi - lo
    if span == 0:
        return [0.0] * len(xs)
    return [(x - lo) / span for x in xs]

This is what scikit-learn's MinMaxScaler does per column, including the constant-column case: it outputs zeros instead of dividing by zero. Note the last test: 0.2 scaled is 0.5000000000000001, not 0.5, so it must use isclose. span == 0 is a safe float comparison here because subtracting a number from itself is exactly 0.

Hint 1Open a hint

divmod(n, base) gives the next quotient and the last digit.

Hint 2Open a hint

The digits come out last first, so collect them and reverse.

Hint 3Open a hint

Deal with the sign once at the start: work on abs(n).

SolutionShow the solution and why
solution.py
DIGITS = "0123456789abcdefghijklmnopqrstuvwxyz"

def to_base(n, base):
    if n == 0:
        return "0"
    sign = "-" if n < 0 else ""
    n = abs(n)
    out = []
    while n:
        n, r = divmod(n, base)
        out.append(DIGITS[r])
    return sign + "".join(reversed(out))

It is the digit-sum loop from the trace problem with base instead of 10. Taking abs(n) first matters: divmod(-10, 2) floors, so on a negative number the remainders come out in a form you do not want. Building a list and joining once is the standard way to build a string (Module 5 shows why += in a loop is slower). The last test checks against Python's own int(s, base), a good habit: test your code against a trusted version.

16. When is x or default wrong?

Say your answer out loud or write it down, then compare.

SolutionModel answer

When a falsy value is a valid input. or replaces every falsy value: 0, 0.0, "", [], {}, not just None. So timeout or 30 turns a timeout of 0 into 30, and name or "unknown" turns an empty string into "unknown". If only "missing" should get the default, write default if x is None else x. Interview

17. Why is 0.1 + 0.2 != 0.3, and how do you test float code?

SolutionModel answer

Floats are binary fractions. 0.1 has no exact binary form (like 1/3 has no exact decimal form), so it is stored as the nearest binary value, and the small errors add up: 0.1 + 0.2 is 0.30000000000000004. In code, compare with a tolerance: math.isclose, numpy.isclose / numpy.allclose for arrays, and pytest.approx in tests. For money, use integer cents or decimal.Decimal. Bonus point: in ML this is why you check a loss or a gradient with allclose, never ==.

Interview

18. -7 // 2 versus int(-7 / 2)

SolutionModel answer

-7 // 2 is -4: floor division rounds toward minus infinity. int(-7 / 2) is -3: -7 / 2 is -3.5, and int truncates toward zero. They agree for positive numbers and differ for negatives. Python chose floor so that a % b has the sign of b and (a // b) * b + a % b == a holds. That makes % safe for wrapping things like hours on a clock or array indexes even with negative inputs. C, Java and SQL Server truncate.

Interview

19. bool is a subclass of int. Where does that help, and where does it bite?

SolutionModel answer

It helps for counting: sum(x > 0 for x in xs) counts matches, and in pandas (df["x"] > 0).sum() and .mean() give the count and the share of rows. It bites in validation: isinstance(True, int) is True, so code that checks "is this an int" accepts True; check type(x) is int or exclude bool explicitly. It also bites in dict keys: True == 1 and they hash the same, so {1: "a", True: "b"} is {1: "b"}.

Recap

  • / gives a float. // floors toward minus infinity, and % takes the sign of the divisor. int() truncates toward zero.
  • Never compare floats with ==: use math.isclose, np.isclose or pytest.approx. Add abs_tol near zero.
  • round() is banker's rounding. To match Excel or SQL Server, use Decimal(str(x)) with ROUND_HALF_UP.
  • ** beats unary minus and groups right to left. Comparisons chain. not is weaker than ==.
  • Falsy: None, False, zeros, empty containers. and / or return an operand, and or is not COALESCE.
