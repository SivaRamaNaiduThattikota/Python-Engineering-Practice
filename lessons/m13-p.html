1How to use this page

Before writing a test, ask what would make it fail. Pick inputs that separate correct behaviour from plausible mistakes (13.1); give each test its own world through fixtures, tmp_path and monkeypatch (13.2); replace slow or random dependencies with fakes and mocks that match the real interface, and patch where names are looked up (13.3); and for numbers, randomness and models, test tolerances, seeds, properties and behaviour, leaving quality to evaluation (13.4).

The problems mix the lessons on purpose, and the mini project combines all four: it is the test suite you would be expected to write for a small production service.

# --- code under test (do not edit) ---
def normalize_email(raw):
    email = raw.strip().lower()
    if email.count("@") != 1:
        raise ValueError(f"invalid e-mail {raw!r}")
    local, domain = email.split("@")
    if not local or not domain:
        raise ValueError(f"invalid e-mail {raw!r}")
    local = local.split("+", 1)[0]
    if domain == "gmail.com":
        local = local.replace(".", "")
    return f"{local}@{domain}"


# --- tests ---
import pytest


@pytest.mark.parametrize("raw,expected", [
    ("  Ana.Lee@Shop.IO ", "ana.lee@shop.io"),
    ("ana.lee+news@gmail.com", "analee@gmail.com"),
    ("bo+promo@shop.io", "bo@shop.io"),
    ("CY@EXAMPLE.COM", "cy@example.com"),
])
def test_normalises(raw, expected):
    assert normalize_email(raw) == expected


@pytest.mark.parametrize("raw", ["no-at-sign", "a@b@c.io", "@shop.io", "ana@", ""])
def test_rejects_invalid(raw):
    with pytest.raises(ValueError, match="invalid e-mail"):
        normalize_email(raw)

Two tables cover the whole specification: valid inputs paired with their exact normal form, and invalid inputs that must raise. Each row is chosen to separate the correct rule from a plausible wrong one: the non-Gmail address with dots shows that dots are removed only for Gmail, the upper-case domain shows the whole address is lower-cased, the spaces show stripping, and two @ signs show the exact-count check. E-mail normalisation decides whether two accounts are the same customer, so its bugs merge or split identities in every downstream dataset.

# --- code under test (do not edit) ---
import time


class Stopwatch:
    def __init__(self, clock=time.perf_counter):
        self.clock = clock
        self._start = None

    def start(self):
        self._start = self.clock()

    def stop(self):
        if self._start is None:
            raise RuntimeError("stop() before start()")
        elapsed_ms = round((self.clock() - self._start) * 1000)
        self._start = None
        return elapsed_ms


# --- tests ---
import pytest
from unittest.mock import Mock


def test_measures_elapsed_in_ms():
    sw = Stopwatch(clock=Mock(side_effect=[10.0, 10.25]))
    sw.start()
    assert sw.stop() == 250


def test_stop_without_start_raises():
    with pytest.raises(RuntimeError):
        Stopwatch(clock=Mock(return_value=0.0)).stop()


def test_stop_resets():
    sw = Stopwatch(clock=Mock(side_effect=[1.0, 1.5]))
    sw.start()
    sw.stop()
    with pytest.raises(RuntimeError):
        sw.stop()

Sleeping makes a test slow (a suite of such tests takes minutes) and still flaky, because a loaded CI machine can oversleep beyond the range, and the range is so loose that a version measuring in seconds instead of milliseconds would only fail by luck. Feeding the clock exact values makes the expected result exact: 0.25 seconds is 250 milliseconds, and the seconds mutant returns 0. The same injection lets the tests cover the state rules (no stop before start, reset after stop) instantly.

# --- code under test (do not edit) ---
def fit_context(chunks, budget, count_tokens):
    kept, used = [], 0
    for chunk in chunks:
        n = count_tokens(chunk)
        if used + n > budget:
            break
        kept.append(chunk)
        used += n
    return kept, used


# --- tests ---
import pytest


def words(text):
    return len(text.split())


def test_everything_fits():
    assert fit_context(["a b", "c"], 10, words) == (["a b", "c"], 3)


def test_exact_fit_is_allowed():
    assert fit_context(["a b c", "d e"], 5, words) == (["a b c", "d e"], 5)


def test_stops_at_first_chunk_that_does_not_fit():
    chunks = ["one two", "three four five six", "seven"]
    assert fit_context(chunks, 4, words) == (["one two"], 2)


def test_uses_the_given_tokenizer():
    assert fit_context(["aaaaaaaaaa"], 1, words) == (["aaaaaaaaaa"], 1)


def test_empty_budget():
    assert fit_context(["a"], 0, words) == ([], 0)

The tokenizer is a dependency, so the tests inject a fake that is trivial to reason about (one token per word) instead of a real tokenizer whose counts would have to be looked up. Each case pins one decision: an exact fit is allowed (> not >=), the loop stops instead of skipping to a later small chunk (chunks are ranked by relevance, so skipping would put a less relevant chunk ahead of a more relevant, larger one), the count comes from the tokenizer and not from characters (a ten-letter word is one "token" here), and the returned total is the real one. Context packing bugs silently waste tokens or drop the best evidence.

# --- code under test (do not edit) ---
def check_budget(cost, limit):
    if cost > limit:
        raise ValueError(f"cost (${cost:.2f}) exceeds limit (${limit:.2f})")
    return limit - cost


# --- tests ---
import re
import pytest


def test_over_budget():
    with pytest.raises(ValueError, match=re.escape("cost ($12.50) exceeds limit ($10.00)")):
        check_budget(12.5, 10)


def test_within_budget():
    assert check_budget(4, 10) == 6

match runs re.search(pattern, str(exception)). In the literal message, ( and ) form a group, $ means "end of string" and . matches any character, so the pattern could never match a message that continues after $, and the test failed on correct code. re.escape turns the text into a pattern that matches it literally. An alternative that avoids regular expressions entirely is with pytest.raises(ValueError) as excinfo: followed by assert str(excinfo.value) == "...", which is also stricter, since search would accept the text anywhere in a longer message.

# --- code under test (do not edit) ---
def confusion_matrix(y_true, y_pred, labels):
    index = {label: i for i, label in enumerate(labels)}
    matrix = [[0] * len(labels) for _ in labels]
    for t, p in zip(y_true, y_pred, strict=True):
        if t not in index or p not in index:
            raise ValueError(f"unknown label in ({t!r}, {p!r})")
        matrix[index[t]][index[p]] += 1
    return matrix


# --- tests ---
import pytest

LABELS = ["spam", "ham"]


def test_asymmetric_errors():
    y_true = ["spam", "spam", "spam", "ham", "ham"]
    y_pred = ["spam", "ham", "ham", "spam", "ham"]
    assert confusion_matrix(y_true, y_pred, LABELS) == [[1, 2], [1, 1]]


def test_perfect_predictions_are_diagonal():
    assert confusion_matrix(["ham", "spam", "ham"], ["ham", "spam", "ham"], LABELS) == [[1, 0], [0, 2]]


def test_rows_follow_label_order():
    assert confusion_matrix(["spam"], ["ham"], ["ham", "spam"]) == [[0, 0], [1, 0]]


def test_unknown_label_raises():
    with pytest.raises(ValueError, match="unknown label"):
        confusion_matrix(["spam"], ["phish"], LABELS)


def test_length_mismatch_raises():
    with pytest.raises(ValueError):
        confusion_matrix(["spam", "ham"], ["spam"], LABELS)

An asymmetric example is essential: if spam-as-ham and ham-as-spam occurred equally often, a transposed matrix would look identical. The diagonal test exposes the classic list-multiplication bug, where every row is the same list object, so one increment shows up in all rows (2.4). Swapping the label order checks that rows and columns follow labels. The error tests pin the strictness: silently ignoring unknown labels or mismatched lengths would produce a matrix that looks plausible and hides a data problem.

8. A snapshot helper

Write snapshot(name, value, folder, update=False) for golden-file tests. It stores value as pretty JSON (indent=2, sorted keys) in folder / f"{name}.json". If the file does not exist, or update is true, it writes the file and returns "written". Otherwise it compares: equal values return "matched"; different values raise AssertionError whose message starts with f"snapshot {name!r} changed" and, for dicts, lists the added, removed and changed top-level keys ("added: ...", "removed: ...", "changed: ...", each comma-separated and sorted, omitted when empty).

Hint 2Open a hint

SolutionShow the solution and why
solution.py
import json
from pathlib import Path


def snapshot(name, value, folder, update=False):
    path = Path(folder) / f"{name}.json"
    text = json.dumps(value, indent=2, sort_keys=True, ensure_ascii=False)
    if update or not path.exists():
        path.parent.mkdir(parents=True, exist_ok=True)
        path.write_text(text + "\n", encoding="utf-8")
        return "written"
    old = json.loads(path.read_text(encoding="utf-8"))
    new = json.loads(text)
    if old == new:
        return "matched"
    parts = [f"snapshot {name!r} changed"]
    if isinstance(old, dict) and isinstance(new, dict):
        added = sorted(new.keys() - old.keys())
        removed = sorted(old.keys() - new.keys())
        changed = sorted(k for k in old.keys() & new.keys() if old[k] != new[k])
        for label, keys in (("added", added), ("removed", removed), ("changed", changed)):
            if keys:
                parts.append(f"{label}: {', '.join(keys)}")
    raise AssertionError("; ".join(parts))

Snapshot tests suit outputs that are large and structured and should change only deliberately: rendered prompts, request payloads sent to a model API, tool schemas, exported reports. The first run records the golden file, later runs compare, and an explicit update flag (usually a command-line option such as --snapshot-update in tools like syrupy) re-records after a reviewed change; the file lives in git, so the change shows up in code review. Sorted keys and indentation keep the files diff-friendly, comparing after a JSON round trip avoids false alarms from tuples versus lists, and a message that names added, removed and changed keys says what moved without a manual diff. Their weakness is that people update snapshots without reading them, so keep them small.

Interview

10. How would you structure the test suite of an LLM-backed service?

SolutionModel answer

As a pyramid that keeps the model out of most tests. At the base, unit tests for pure logic: prompt builders (structure, truncation within the token budget), output parsers and validators fed with real messy replies, chunking, scoring, caching keys, configuration parsing. Next, component tests with fakes and mocks that match the real interfaces (autospec): the retrieval-plus-model flow, retries with injected sleep, timeouts, tool loops, the no-context path that must not call the model, cache behaviour with tmp_path and a fake clock, logging with caplog. Then a few integration tests marked to run separately with real credentials and budgets, or replaying recorded responses, to catch API drift. Alongside, an evaluation suite with a versioned dataset and quality thresholds gates prompt and model changes. Shared fixtures live in conftest.py, everything is deterministic (seeded, injected clocks), and the fast layers run on every commit.

Interview

11. What would you check when reviewing someone else's tests?

SolutionModel answer

That they can fail for the right reasons: each test asserts a specific outcome (not just "no exception" or a truthy value), with inputs that would distinguish correct code from plausible bugs, including edge cases and error paths; a quick mental mutation ("if this line were wrong, would a test fail?") helps. That they are isolated: no shared mutable globals, real files only in tmp_path, environment changes through monkeypatch, no dependence on order, time, network or unseeded randomness. That doubles are used well: mocks at boundaries only, with spec, no patching of the code under test, assertions on all relevant calls rather than assert_called_with on the last one, patches applied where names are looked up. That they are readable: names describe behaviour, arrange-act-assert structure, fixtures and parametrisation instead of copy-paste. And that they are fast and precise: tolerances for floats, match= (escaped) for error messages, no sleeps.

  • The cache key ignores case and surrounding whitespace, so " Refund window? " and "refund window?" share one cached answer, stored as a JSON file in cache_dir.
  • A cache hit returns the stored result, logs INFO "cache hit ...", and does not call the retriever or the model.
  • The retriever is asked for max_chunks chunks. With no chunks, the result is {"answer": "I don't know.", "sources": [], "latency_ms": 0}, a WARNING is logged, the model is not called, and nothing is cached.
  • The prompt contains every chunk as [source] text and the question; the model's reply is stripped; sources are unique in retrieval order; latency_ms is measured around the model call with the clock, in whole milliseconds.
  • A model TimeoutError is logged at ERROR and re-raised, and nothing is cached.

# --- code under test (do not edit) ---
import hashlib, json, logging, time

log = logging.getLogger("answers")


class AnswerService:
    def __init__(self, retriever, llm, cache_dir, clock=time.monotonic, max_chunks=3):
        self.retriever, self.llm, self.cache_dir = retriever, llm, cache_dir
        self.clock, self.max_chunks = clock, max_chunks

    def _key(self, question):
        return hashlib.sha256(question.strip().lower().encode("utf-8")).hexdigest()[:16]

    def answer(self, question):
        if not question.strip():
            raise ValueError("empty question")
        key = self._key(question)
        path = self.cache_dir / f"{key}.json"
        if path.exists():
            log.info("cache hit %s", key)
            return json.loads(path.read_text(encoding="utf-8"))
        chunks = self.retriever.retrieve(question.strip(), k=self.max_chunks)
        if not chunks:
            log.warning("no context for %r", question.strip())
            return {"answer": "I don't know.", "sources": [], "latency_ms": 0}
        context = "\n".join(f"[{c['source']}] {c['text']}" for c in chunks)
        prompt = f"Answer from the context only.\n{context}\n\nQuestion: {question.strip()}"
        start = self.clock()
        try:
            reply = self.llm.complete(prompt)
        except TimeoutError:
            log.error("model timed out for %s", key)
            raise
        result = {
            "answer": reply.strip(),
            "sources": list(dict.fromkeys(c["source"] for c in chunks)),
            "latency_ms": round((self.clock() - start) * 1000),
        }
        path.write_text(json.dumps(result), encoding="utf-8")
        return result


class Retriever:
    def retrieve(self, question, k):
        raise NotImplementedError("real vector store")


class LLM:
    def complete(self, prompt):
        raise NotImplementedError("real model API")

import logging
import pytest
from unittest.mock import Mock

CHUNKS = [
    {"source": "faq.md", "text": "Refunds take 5 days."},
    {"source": "terms.md", "text": "No refunds after 30 days."},
    {"source": "faq.md", "text": "Refunds go to the original card."},
]


@pytest.fixture
def retriever():
    r = Mock(spec=Retriever)
    r.retrieve.return_value = CHUNKS
    return r


@pytest.fixture
def llm():
    m = Mock(spec=LLM)
    m.complete.return_value = "  Refunds take 5 days.\n"
    return m


@pytest.fixture
def clock():
    return Mock(side_effect=[10.0, 10.25, 20.0, 20.5])


@pytest.fixture
def service(retriever, llm, clock, tmp_path):
    return AnswerService(retriever, llm, cache_dir=tmp_path, clock=clock)


def test_answer_result(service):
    assert service.answer("How long do refunds take?") == {
        "answer": "Refunds take 5 days.", "sources": ["faq.md", "terms.md"], "latency_ms": 250}


def test_prompt_has_chunks_and_question(service, llm):
    service.answer("  How long do refunds take? ")
    prompt = llm.complete.call_args.args[0]
    for c in CHUNKS:
        assert f"[{c['source']}] {c['text']}" in prompt
    assert prompt.endswith("Question: How long do refunds take?")


def test_cache_ignores_case_and_spaces(service, llm, retriever, tmp_path):
    first = service.answer("Refund window?")
    second = service.answer("  REFUND window?  ")
    assert first == second
    assert llm.complete.call_count == 1 and retriever.retrieve.call_count == 1
    assert len(list(tmp_path.glob("*.json"))) == 1


def test_cache_hit_is_logged_and_skips_dependencies(service, llm, retriever, caplog):
    service.answer("Refund window?")
    llm.reset_mock()
    retriever.reset_mock()
    caplog.set_level(logging.INFO)
    service.answer("refund window?")
    llm.complete.assert_not_called()
    retriever.retrieve.assert_not_called()
    assert [r.levelname for r in caplog.records] == ["INFO"] and caplog.records[0].getMessage().startswith("cache hit ")


def test_retriever_asked_for_max_chunks(retriever, llm, clock, tmp_path):
    svc = AnswerService(retriever, llm, cache_dir=tmp_path, clock=clock, max_chunks=2)
    svc.answer("Refunds?")
    retriever.retrieve.assert_called_once_with("Refunds?", k=2)


def test_no_context(service, retriever, llm, tmp_path, caplog):
    retriever.retrieve.return_value = []
    caplog.set_level(logging.INFO)
    assert service.answer("Unknown topic") == {"answer": "I don't know.", "sources": [], "latency_ms": 0}
    llm.complete.assert_not_called()
    assert list(tmp_path.iterdir()) == []
    assert [(r.levelname, r.getMessage()) for r in caplog.records] == [("WARNING", "no context for 'Unknown topic'")]


def test_timeout_logged_reraised_and_not_cached(service, llm, tmp_path, caplog):
    llm.complete.side_effect = TimeoutError("slow model")
    with pytest.raises(TimeoutError):
        service.answer("Refunds?")
    assert [r.levelname for r in caplog.records] == ["ERROR"]
    assert list(tmp_path.iterdir()) == []


@pytest.mark.parametrize("question", ["", "   ", "\n\t"])
def test_blank_question(service, retriever, llm, question):
    with pytest.raises(ValueError):
        service.answer(question)
    retriever.retrieve.assert_not_called()
    llm.complete.assert_not_called()

Every lesson of the module has a job here:

  • pytest basics (13.1): exact expected results, pytest.raises for errors, and a parametrised table of blank questions.
  • Fixtures (13.2): small fixtures (retriever, llm, clock) compose into service, with tmp_path as the cache folder, so every test gets a fresh service and an empty cache, and caplog checks the log levels and messages.
  • Mocking (13.3): the retriever and model are Mock(spec=...) doubles of the real interfaces, configured per test (return_value, side_effect), and their call records prove the important side effects: no model call without context or on a cache hit, k passed through, one call for two spellings of a question. reset_mock separates the setup call from the call under test.
  • Deterministic tests (13.4): the clock is scripted, so latency is exactly 250 ms; nothing sleeps, nothing calls the network.

The ten mutants are the bugs such services really ship with: cache keys that miss case or spacing (paying twice for the same question), caches written but never read or never written, model calls on empty context, ignored settings, seconds reported as milliseconds, duplicated citations, swallowed timeouts and missing warnings. A suite that catches all of them is one you can refactor the service under with confidence.

Recap

  • Start every test from "what would make this fail?" and choose inputs that separate correct behaviour from plausible bugs.
  • Compose fixtures for setup; isolate files with tmp_path, environment with monkeypatch or patch.dict, and logs with caplog.
  • Use spec'd mocks at boundaries, fakes for behaviour, injected clocks and tokenizers for determinism, and never sleep in tests.
  • Remember that match= is a regular expression (re.escape literal text) and that snapshots must be updated deliberately.
  • A test suite is good when it catches realistic mutants of the code: that is the standard the grader of this module applied.
