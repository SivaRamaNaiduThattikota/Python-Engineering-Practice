9.6 Class methods and constructors

The three kinds of methods: instance methods, classmethods that receive the class, and staticmethods that receive nothing. Alternative constructors such as from_dict and from_env that keep working for subclasses, class-level state, __new__ and when it is needed, and copying your own objects with __copy__ and __deepcopy__. Applied to configs, messages, prompts and experiments.

1Three kinds of methods

An ordinary method receives the instance as its first argument (self, 9.1). Two decorators change what the method receives. @classmethod makes it receive the class instead, conventionally named cls, whether you call it on the class or on an instance. @staticmethod makes it receive nothing extra: it is a plain function that happens to live in the class's namespace. Both are descriptors (9.3) that change how the method is bound when you access it.

three_kinds.py
class Model:
    default_name = "small"

    def __init__(self, name):
        self.name = name

    def describe(self):                       # instance method: gets self
        return f"instance of {type(self).__name__} named {self.name}"

    @classmethod
    def default(cls):                         # class method: gets the class
        return cls(cls.default_name)

    @staticmethod
    def is_valid_name(name):                  # static method: gets nothing
        return name.isidentifier() and name.islower()

class LargeModel(Model):
    default_name = "large"

print(Model.default().describe())
print(LargeModel.default().describe())
print(Model.is_valid_name("small"), Model("x").is_valid_name("Big Model"))
m = Model("tiny")
print(m.default().name, type(Model.__dict__["default"]).__name__)
Output
instance of Model named small
instance of LargeModel named large
True False
small classmethod

LargeModel.default() returned a LargeModel named "large" although default is defined only on Model: because it receives cls, it builds an instance of whichever class it was called on, and reads that class's default_name. Calling a classmethod on an instance (m.default()) still passes the class. A staticmethod is called the same way from the class or an instance and never sees either; use one for a helper that belongs with the class conceptually but needs no state, such as a validation function. If it is not closely tied to the class, a plain module-level function is simpler and easier to test.

2Alternative constructors

A class has one __init__, but data arrives in many forms: a dict from JSON, environment variables, a file, a database row, an API response. The idiomatic solution is a set of alternative constructors: classmethods named from_<source> that parse the input, validate it and return cls(...). The standard library uses this everywhere: dict.fromkeys, datetime.fromisoformat, int.from_bytes, pandas.DataFrame.from_records. Keeping __init__ simple (just the fields) and putting parsing in named constructors makes each input path explicit and testable.

alt_constructors.py
import json

class Message:
    ROLES = ("system", "user", "assistant")

    def __init__(self, role, content):
        if role not in self.ROLES:
            raise ValueError(f"bad role {role!r}")
        self.role, self.content = role, content

    def __repr__(self):
        return f"{type(self).__name__}({self.role!r}, {self.content!r})"

    @classmethod
    def from_dict(cls, data):
        return cls(data["role"], data["content"])

    @classmethod
    def from_json(cls, text):
        return cls.from_dict(json.loads(text))

    @classmethod
    def user(cls, content):
        return cls("user", content)

    def to_dict(self):
        return {"role": self.role, "content": self.content}

m = Message.from_json('{"role": "assistant", "content": "Five days."}')
print(m, Message.user("Refund?"), Message.from_dict(m.to_dict()).to_dict() == m.to_dict())
Output
Message('assistant', 'Five days.') Message('user', 'Refund?') True

The constructors chain: from_json parses and delegates to from_dict, which delegates to cls(...), so validation in __init__ applies to every path. Writing cls(...) instead of Message(...) is the important detail: a subclass, class ToolMessage(Message), inherits from_dict and gets ToolMessage instances from it. Hard-coding the class name breaks that silently, returning base-class objects from a subclass's constructor (problem 3). That is also why alternative constructors are classmethods and not staticmethods: a staticmethod would have no cls to call.

3Class-level state and factories

Classmethods are also the natural home for operations on class-level state: a registry of subclasses, a count of created instances, a cache of shared resources, a default configuration. Inside a classmethod, cls is the class the method was called on, which can be a subclass, so the choice between cls.counter and Base.counter matters: cls.counter += 1 on a subclass reads the inherited value and creates a separate class attribute on the subclass (the shadowing rule of 9.1, applied to classes), while Base.counter += 1 always updates the shared one.

class_state.py
class Connection:
    _pool = {}                                  # shared by every class in the hierarchy
    created = 0

    def __init__(self, url):
        self.url = url
        type(self).created += 1                 # meant to count per class: see the output

    @classmethod
    def get(cls, url):
        key = (cls.__name__, url)
        if key not in Connection._pool:
            Connection._pool[key] = cls(url)
        return Connection._pool[key]

class ReadReplica(Connection):
    pass

a = Connection.get("db://main")
b = Connection.get("db://main")
r = ReadReplica.get("db://main")
print(a is b, type(r).__name__, r is a)
print(Connection.created, ReadReplica.created, sorted(k[0] for k in Connection._pool))
Output
True ReadReplica False
1 2 ['Connection', 'ReadReplica']

Look at the second line of output: ReadReplica.created is 2, although only one replica was made. On its first increment, type(self).created read the inherited Connection.created (already 1), added one, and stored 2 as a new attribute on ReadReplica. That is the shadowing rule biting at class level; to count each class from zero, keep the counts in one dict keyed by class, as problem 7 does.

get is a factory: callers ask the class for an object instead of constructing it, and the class decides whether to create a new one or return an existing one. Pools of database connections or HTTP clients, and caches of loaded models or tokenizers, are usually managed this way, often with a lock in threaded code (14.2).

4__new__: controlling creation itself

Class(args) actually performs two steps (9.1): __new__(cls, args) creates and returns the new object, then, if that object is an instance of cls, __init__(self, args) initialises it. You almost never override __new__. The two situations that need it are subclassing an immutable built-in (str, int, tuple), whose value must be set at creation because there is nothing to change afterwards, and controlling whether a new object is created at all, for example returning an existing instance (interning, singletons).

dunder_new.py
class Label(str):
    def __new__(cls, value):
        return super().__new__(cls, value.strip().lower())   # set the immutable value here

class Severity:
    _instances = {}

    def __new__(cls, name):
        if name not in cls._instances:
            obj = super().__new__(cls)
            obj.name = name
            cls._instances[name] = obj
        return cls._instances[name]

l = Label("  SPAM ")
print(repr(l), isinstance(l, str), l.upper())
print(Severity("high") is Severity("high"), Severity("low") is Severity("high"))
Output
'spam' True SPAM
True False

Beware one trap: when __new__ returns an existing instance of the class, Python still calls __init__ on it, every time. An __init__ that resets attributes would wipe the cached object's state on each "creation", which is why the interning example sets its attribute in __new__ and defines no __init__ (problem 16). For most "one shared object" needs, a module-level instance or a cached factory function (8.3) is simpler than overriding __new__.

5Copying your own objects

copy.copy(obj) and copy.deepcopy(obj) (2.3) work on your classes too. By default, a shallow copy creates a new instance and copies the instance's __dict__ shallowly: the new object has its own attribute dict, but the attribute values (lists, dicts, other objects) are shared with the original. A deep copy copies those values recursively. For most data-holding classes that default is fine. It becomes wrong when an object holds things that must not be duplicated, such as an API client, a database connection, a lock, a large read-only dataset or a loaded model, or when some state should be reset in a copy (counters, caches).

Define __copy__(self) and __deepcopy__(self, memo) to take control. __deepcopy__ receives memo, the dict that deepcopy uses to preserve shared references and handle cycles (2.3); pass it on when you deep-copy your own attributes: copy.deepcopy(self.config, memo). A common pattern copies the configuration deeply, shares the expensive or unshareable resource, and starts the copy with fresh statistics (problem 10).

custom_copy.py
import copy

class Client:                                   # stands in for an SDK client with a network session
    def __init__(self):
        self.session_id = "s-1"

class Agent:
    def __init__(self, client, config):
        self.client = client
        self.config = config
        self.history = []

    def __deepcopy__(self, memo):
        new = Agent.__new__(Agent)              # create without calling __init__
        memo[id(self)] = new
        new.client = self.client                # share the client: never duplicate a connection
        new.config = copy.deepcopy(self.config, memo)
        new.history = []                        # a copy starts with a clean history
        return new

a = Agent(Client(), {"model": "small", "stop": ["\n\n"]})
a.history.append("hi")
b = copy.deepcopy(a)
b.config["stop"].append("User:")
print(b.client is a.client, a.config["stop"], b.config["stop"], a.history, b.history)
shallow = copy.copy(a)
print(shallow.config is a.config, shallow.history is a.history)
Output
True ['\n\n'] ['\n\n', 'User:'] ['hi'] []
True True

Agent.__new__(Agent) builds an empty instance without running __init__, the usual way to construct a copy field by field. Registering the new object in memo before copying attributes is what makes cycles work (an attribute that points back to the agent finds the copy in memo). The shallow copy.copy, which uses the default behaviour here, shares everything, history included. scikit-learn's clone() takes a related approach: it builds a new estimator from the original's constructor parameters only, never copying fitted state.

solution.py
class Message:
    def __init__(self, role, content):
        self.role = role
        self.content = content

    def __repr__(self):
        return f"{type(self).__name__}({self.role!r}, {self.content!r})"

    def __eq__(self, other):
        if not isinstance(other, Message):
            return NotImplemented
        return (self.role, self.content) == (other.role, other.content)

    @classmethod
    def from_dict(cls, data):
        missing = {"role", "content"} - data.keys()
        if missing:
            raise KeyError(f"missing keys: {', '.join(sorted(missing))}")
        return cls(data["role"], data["content"].strip())

    @classmethod
    def from_pairs(cls, pairs):
        return [cls(role, content) for role, content in pairs]

    def to_dict(self):
        return {"role": self.role, "content": self.content}

__init__ stays a plain assignment of fields, and each input format gets a named constructor that does its own parsing. from_dict and to_dict are a round trip, which the test checks; that pair is how objects travel through JSON, databases and APIs. Checking all missing keys at once produces one useful message instead of failing on the first. cls(...) keeps both constructors correct for subclasses. Pydantic models provide exactly this pair as model_validate(dict) and model_dump() (11.4).

SolutionShow the solution and why
solution.py
class Config:
    defaults = {"debug": True, "workers": 1}

    def __init__(self, **values):
        self.values = {**self.defaults, **values}

    @classmethod
    def from_dict(cls, data):
        return cls(**data)

    def is_prod(self):
        return False

    defaults = {"debug": False, "workers": 8}

    def is_prod(self):
        return True

solution.py
class ModelSettings:
    def __init__(self, model, temperature, max_tokens):
        if not 0 <= temperature <= 2:
            raise ValueError(f"temperature must be in [0, 2], got {temperature}")
        if max_tokens < 1:
            raise ValueError(f"max_tokens must be positive, got {max_tokens}")
        self.model = model
        self.temperature = temperature
        self.max_tokens = max_tokens

    def __repr__(self):
        return f"ModelSettings(model={self.model!r}, temperature={self.temperature}, max_tokens={self.max_tokens})"

    def __eq__(self, other):
        if not isinstance(other, ModelSettings):
            return NotImplemented
        return vars(self) == vars(other)

    @classmethod
    def from_env(cls, environ, prefix="LLM_"):
        def read(name, convert, default):
            key = prefix + name
            if key not in environ:
                return default
            try:
                return convert(environ[key])
            except ValueError:
                raise ValueError(f"{key}: cannot parse {environ[key]!r}") from None

        model = read("MODEL", str, "small")
        temperature = read("TEMPERATURE", float, 0.0)
        max_tokens = read("MAX_TOKENS", int, 512)
        try:
            return cls(model, temperature, max_tokens)
        except ValueError as e:
            var = prefix + ("TEMPERATURE" if "temperature" in str(e) else "MAX_TOKENS")
            raise ValueError(f"{var}: {e}") from None

    def with_overrides(self, **changes):
        unknown = changes.keys() - vars(self).keys()
        if unknown:
            raise TypeError(f"unknown settings: {sorted(unknown)}")
        return type(self)(**{**vars(self), **changes})

Environment variables are always strings, so from_env owns the parsing and turns every failure into an error that names the variable a person must fix; validation of ranges stays in __init__, so settings created any other way obey the same rules. The environment is passed in as a dict, so tests never touch the real os.environ (9.5), and the prefix makes the same class usable for several components. with_overrides returns a new object instead of mutating, so a per-request tweak cannot leak into shared settings (9.1), and it builds through type(self)(...), keeping subclasses and validation. Pydantic's BaseSettings does all of this declaratively (11.4).

6. A helper that receives self by accident

Tokenizer.normalise was meant to be a static helper, but called on an instance it receives the instance as text and fails. Fix the class so normalise works from the class and from instances, and tokenize uses it.

HintOpen a hint

Without a decorator, a function in a class is an instance method: self.normalise(text) passes two arguments.

SolutionShow the solution and why
solution.py
class Tokenizer:
    def __init__(self, stop_words):
        self.stop_words = set(stop_words)

    @staticmethod
    def normalise(text):
        return " ".join(text.lower().split())

    def tokenize(self, text):
        return [w for w in self.normalise(text).split() if w not in self.stop_words]

Every function defined in a class becomes an instance method unless decorated, so self.normalise(text) called it with the instance as the first argument and the text as a second, unexpected one: "takes 1 positional argument but 2 were given". @staticmethod stops the binding, so the function receives exactly the arguments written, from the class or an instance. Keeping a pure helper like this static (or a module function) also makes it trivial to test alone.

class Component:
    _counts = {}

    def __init__(self, name):
        self.name = name
        key = type(self).__name__
        Component._counts[key] = Component._counts.get(key, 0) + 1

    pass

    pass

One shared dict, deliberately written as Component._counts (never self._counts or cls._counts with assignment), holds all counts, and type(self).__name__ picks the right key for every subclass without subclasses writing any code. count uses cls to answer for the class it was called on, so the same method serves every class in the hierarchy. summary returns a sorted copy, so callers cannot alter the counts. Counting created components like this is a cheap way to spot accidental re-creation of expensive objects (a model loaded per request instead of once).

solution.py
import re

class PromptTemplate:
    def __init__(self, name, body, meta=None):
        self.name = name
        self.body = body
        self.meta = dict(meta) if meta else {"name": name}

    @classmethod
    def from_text(cls, text):
        lines = text.splitlines()
        if "---" not in [l.strip() for l in lines]:
            raise ValueError("template needs a '---' line between header and body")
        sep = [l.strip() for l in lines].index("---")
        meta = {}
        for line in lines[:sep]:
            key, _, value = line.partition(":")
            if key.strip():
                meta[key.strip()] = value.strip()
        if "name" not in meta:
            raise ValueError("template header needs a name")
        body = "\n".join(lines[sep + 1:]).strip()
        return cls(meta["name"], body, meta)

    @property
    def variables(self):
        return list(dict.fromkeys(re.findall(r"\{(\w+)\}", self.body)))

    def render(self, **values):
        missing = sorted(set(self.variables) - values.keys())
        if missing:
            raise KeyError(f"missing variables: {', '.join(missing)}")
        return self.body.format(**values)

The file format is parsed in one named constructor, and __init__ accepts already-parsed parts, so templates can also be built directly in code or tests (the last assertion). Keeping the header as meta preserves information such as the version for logging which prompt produced an answer (8.P). variables is derived from the body, so it cannot drift. Checking missing variables before formatting gives one complete error instead of str.format's first KeyError. A real template would also escape literal braces ({{), as 5.2 and 5.5 discussed.

import copy

class Experiment:
    def __init__(self, name, config, dataset):
        self.name = name
        self.config = config
        self.dataset = dataset
        self.results = []

    @classmethod
    def from_config(cls, data, dataset):
        missing = {"name", "params"} - data.keys()
        if missing:
            raise KeyError(f"missing keys: {', '.join(sorted(missing))}")
        return cls(data["name"], copy.deepcopy(data["params"]), dataset)

    def __deepcopy__(self, memo):
        new = type(self).__new__(type(self))
        memo[id(self)] = new
        new.name = self.name
        new.config = copy.deepcopy(self.config, memo)
        new.dataset = self.dataset
        new.results = []
        return new

    def clone(self, name, **param_changes):
        unknown = param_changes.keys() - self.config.keys()
        if unknown:
            raise KeyError(f"unknown parameters: {', '.join(sorted(unknown))}")
        new = copy.deepcopy(self)
        new.name = name
        new.config.update(param_changes)
        return new

    def record(self, metric, value):
        self.results.append((metric, value))

Two constructors with distinct jobs: from_config turns external data into an experiment (copying the params so the caller's dict cannot change the experiment later), and clone derives a variant from an existing one. Both rely on one copying rule in __deepcopy__: the dataset is shared because copying it would multiply memory, the config is independent because variants change it, and results start empty because a variant has not run yet. Writing that rule once means copy.deepcopy(exp) from any other code (a sweep library, a test) behaves the same as clone. The unknown-parameter check stops a typo like momentun=0.9 from silently creating a useless run. This is the shape of hyperparameter sweeps: one base experiment, many cheap clones.

solution.py
import json


class Document:
    def __init__(self, id, text, tags=None):
        self.id = id
        self.text = text
        self.tags = list(tags) if tags is not None else []

    @staticmethod
    def check_text(text):
        if not text.strip():
            raise ValueError("empty text")
        return text.strip()

    @classmethod
    def _extra_fields(cls, data):
        return {}

    @classmethod
    def from_json(cls, line):
        data = json.loads(line)
        text = cls.check_text(data["text"])
        return cls(data["id"], text, data.get("tags"), **cls._extra_fields(data))


class SourcedDocument(Document):
    def __init__(self, id, text, tags=None, source="unknown"):
        super().__init__(id, text, tags)
        self.source = source

    @classmethod
    def _extra_fields(cls, data):
        return {"source": data["source"]} if "source" in data else {}

Four bugs from this lesson. from_json built Document(...) by name, so the subclass's constructor produced base objects without a source; it must build cls(...). Building the right class is not enough, though: the subclass needs its extra field from the JSON, so a classmethod hook, _extra_fields, lets each class say which extra keyword arguments it reads, while the base handles everything common. check_text lacked @staticmethod, so calling it on the class worked by accident but calling it on an instance would pass the instance as text. The unused extra method was dead code and is removed.

Hint 1Open a hint

In __new__, normalise, then look up the cache; create with super().__new__(cls) and set the name with object.__setattr__ (9.3).

Hint 2Open a hint

Do not define __init__: it would run on every call, even for cached instances.

SolutionShow the solution and why
solution.py
class Label:
    _cache = {}

    def __new__(cls, name):
        key = name.strip().lower()
        obj = cls._cache.get(key)
        if obj is None:
            obj = super().__new__(cls)
            object.__setattr__(obj, "name", key)
            cls._cache[key] = obj
        return obj

    def __setattr__(self, name, value):
        raise AttributeError("Label is immutable")

    def __repr__(self):
        return f"Label({self.name!r})"

    @classmethod
    def known(cls):
        return sorted(cls._cache)

    @classmethod
    def clear(cls):
        cls._cache.clear()

__new__ decides whether a new object is created at all: for a name it has seen, it returns the cached instance, so millions of rows share a handful of label objects and comparisons are identity checks. That is safe only because the objects are immutable, which __setattr__ enforces (setting the name once through object.__setattr__). There is deliberately no __init__: Python calls __init__ after __new__ whenever the returned object is an instance of the class, including cached ones, so an initialiser would run again on every lookup. sys.intern (2.1) does the same for strings, and pandas' category dtype achieves the memory saving for whole columns. clear exists mainly for tests, so each test starts from an empty cache.

Interview

17. What is the difference between classmethod and staticmethod?

SolutionModel answer

A classmethod receives the class as its first argument (cls), whether called on the class or on an instance, and when called on a subclass it receives the subclass. That makes it the tool for alternative constructors (return cls(...)), factories and operations on class-level state, all of which stay correct under inheritance. A staticmethod receives no implicit argument; it is a plain function placed in the class namespace for organisation, suited to helpers related to the class that need neither instance nor class state, such as validators or parsers. Without either decorator, a function in a class is an instance method and receives the instance. If a static method has no real connection to the class, a module-level function is usually simpler.

Interview

18. Why are alternative constructors written as classmethods, and why use cls(...) inside them?

SolutionModel answer

A class has a single __init__, but objects are built from many sources: dicts, JSON, environment variables, files, database rows. Named constructors such as from_dict and from_env keep __init__ simple (just the fields) and give each input format its own parsing, validation and error messages, as in datetime.fromisoformat or DataFrame.from_records. They must be classmethods so they receive the class they were called on, and they should construct with cls(...) rather than the class name, so a subclass inherits a factory that returns instances of the subclass with its overrides and defaults; hard-coding the name silently returns base-class objects. Subclasses should keep the base __init__ signature compatible (only adding optional parameters) so inherited constructors keep working.

Interview

19. How should copying work for objects that hold external resources such as API clients, connections or models?

SolutionModel answer

Decide per attribute what a copy means. Configuration and other plain data that a copy may change should be deep-copied; immutable or read-only data can be shared; per-object state such as histories, caches and counters often should be reset; and external resources (an HTTP session, a database connection, a lock, a GPU-resident model, an open file) must usually be shared or recreated, never duplicated by deepcopy, which may fail outright or produce two objects fighting over one socket. Implement that rule in __deepcopy__ (creating the new object with __new__, registering it in memo before copying attributes, and passing memo on) and __copy__, so every caller gets the same behaviour. For configuration-driven objects, a cleaner alternative is to rebuild from parameters, as scikit-learn's clone does, or to keep resources outside the object and inject them (9.5), so the objects themselves hold only data and copy trivially.

Recap

  • Instance methods get self; @classmethod gets cls (the class it was called on); @staticmethod gets nothing.
  • Alternative constructors are classmethods named from_<source> that parse, validate and return cls(...), so subclasses inherit working factories.
  • Class-level state belongs in classmethods and is updated through the base class name when it is shared; type(self)(...) builds same-class objects in instance methods.
  • __new__ creates, __init__ initialises; override __new__ only for immutable subclasses or controlled creation, and remember __init__ reruns on returned instances.
  • Customise __copy__ and __deepcopy__(memo) to share resources, deep-copy configuration and reset per-object state.
