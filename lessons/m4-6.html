4.6 Dict tools: counting and grouping

Counter for counting, defaultdict for creating entries on first use, and the GROUP BY patterns built on them: grouping, multi-key grouping and several aggregates in one pass. Plus an LRU cache with OrderedDict and rank fusion for hybrid search.

1Counting with Counter

Counter(iterable) counts how many times each hashable item appears. It is a dict subclass, so everything from 4.5 works, with a few changes that make counting painless. Step by step: building it walks the iterable once (in C, which is fast) and adds 1 for each item. Reading a missing item returns 0 instead of raising, and does not insert it. most_common(n) returns the top n pairs, highest count first, with ties in first-seen order.

counter_basics.py
from collections import Counter

labels = ["spam", "ham", "spam", "eggs", "ham", "spam"]
c = Counter(labels)
print(c, c["spam"], c["unknown"])           # missing items count as 0
print(c.most_common(2), c.total())
c.update(["eggs", "eggs"])                  # update ADDS counts (unlike dict.update)
c["ham"] -= 1
print(c.most_common(), "unknown" in c)
Output
Counter({'spam': 3, 'ham': 2, 'eggs': 1}) 3 0
[('spam', 3), ('ham', 2)] 6
[('spam', 3), ('eggs', 3), ('ham', 1)] False

Counters also do arithmetic, which turns many comparisons into one line: c1 + c2 adds counts, c1 - c2 subtracts and drops anything that ends at zero or below, c1 & c2 keeps the minimum of each count and c1 | c2 the maximum. Note that update and + add counts, the opposite of dict.update, which replaces values.

counter_math.py
from collections import Counter

train = Counter({"spam": 600, "ham": 400})
test = Counter({"spam": 50, "ham": 150, "eggs": 5})
print(train + test)
print(test - train, train - test)           # zero or negative results disappear
print(test & train, sorted((train | test).items()))
Output
Counter({'spam': 650, 'ham': 550, 'eggs': 5})
Counter({'eggs': 5}) Counter({'spam': 550, 'ham': 250})
Counter({'ham': 150, 'spam': 50}) [('eggs', 5), ('ham', 400), ('spam', 600)]

2defaultdict: values created on first access

A defaultdict(factory) behaves like a dict, except that accessing a missing key with d[key] calls factory() (with no arguments), stores the result under that key, and returns it. So defaultdict(list) gives every new key an empty list, defaultdict(int) a 0, defaultdict(set) an empty set. That removes the "if the key is not there yet, create it" step from every grouping and counting loop.

defaultdict_basics.py
from collections import defaultdict

by_team = defaultdict(list)
for ticket, team in [("T1", "billing"), ("T2", "auth"), ("T3", "billing")]:
    by_team[team].append(ticket)             # no need to create the list first
print(by_team["billing"], dict(by_team))

tokens = defaultdict(int)
for model, n in [("small", 120), ("large", 300), ("small", 30)]:
    tokens[model] += n
print(dict(tokens))
Output
['T1', 'T3'] {'billing': ['T1', 'T3'], 'auth': ['T2']}
{'small': 150, 'large': 300}

The trap: any d[key] on a missing key creates an entry, including reads that were only meant to check. A report that does if d[key]: for keys that may not exist quietly fills the dict with empty entries, which then show up in counts, JSON output and plots. Use key in d or d.get(key) to read without creating (problem 9). And convert to a plain dict before returning or serialising, so callers do not inherit the auto-creating behaviour.

phantom_keys.py
from collections import defaultdict

seen = defaultdict(list)
seen["a"].append(1)
if seen["b"]:                 # a "harmless" read...
    pass
print(dict(seen), "c" in seen, seen.get("c"), dict(seen))   # in and get do not create
Output
{'a': [1], 'b': []} False None {'a': [1], 'b': []}

3get, setdefault, defaultdict or Counter?

ToolBest forWatch out for
d.get(k, 0) + 1an occasional count in a plain dictverbose when repeated everywhere
d.setdefault(k, []).append(x)grouping into a plain dict, one place in the codebuilds the default object on every call, even when unused
defaultdict(list)grouping or accumulating in a whole loopreads create entries; convert with dict() before returning
Counter(items)counting, top-k by count, comparing distributionsupdate adds; subtraction drops non-positive counts

All four give O(1) work per item. The choice is about clarity and the behaviour on missing keys: a plain dict raises or needs a default every time, defaultdict creates silently, Counter treats missing as zero without creating. In function signatures and return values, prefer plain dicts (or Counter, which callers understand); keep defaultdict as an implementation detail inside the function.

4GROUP BY patterns

Most "per something" questions in data code are a group-by: a key that decides the group, and something computed per group. Built on a dict, every variant is one pass over the data, O(n):

  • Collect members: defaultdict(list), appending each item under its key.
  • Several keys: use a tuple as the key, (region, month) (4.3), or nested dicts when you want to look up level by level.
  • Aggregates: keep running values per group (count, sum, min, max) and compute derived ones like the mean at the end, so you never store all the members (problem 13).
group_by.py
from collections import defaultdict

sales = [("eu", "jan", 120.0), ("us", "jan", 80.0), ("eu", "feb", 60.0), ("eu", "jan", 30.0)]

totals = defaultdict(float)
for region, month, amount in sales:
    totals[(region, month)] += amount
print(dict(totals))

nested = defaultdict(lambda: defaultdict(float))
for region, month, amount in sales:
    nested[region][month] += amount
print({r: dict(m) for r, m in nested.items()})
Output
{('eu', 'jan'): 150.0, ('us', 'jan'): 80.0, ('eu', 'feb'): 60.0}
{'eu': {'jan': 150.0, 'feb': 60.0}, 'us': {'jan': 80.0}}

itertools.groupby sounds like the same thing but is not: it groups only consecutive items with equal keys, so unsorted input produces several groups for the same key. Use it on data that is already sorted by the key (a sorted log, a query with ORDER BY), or sort first; otherwise use the dict patterns above.

itertools_groupby.py
from itertools import groupby

events = ["login", "query", "query", "login", "query"]
print([(k, len(list(g))) for k, g in groupby(events)])           # consecutive runs
print([(k, len(list(g))) for k, g in groupby(sorted(events))])   # true groups
Output
[('login', 1), ('query', 2), ('login', 1), ('query', 1)]
[('login', 2), ('query', 3)]

5OrderedDict for caches, and ChainMap for layered lookups

Plain dicts keep insertion order, so OrderedDict is rarely needed today. It still has two methods that plain dicts lack and that make it the classic building block of an LRU cache: move_to_end(key) marks a key as most recently used in O(1), and popitem(last=False) removes the oldest entry in O(1). An LRU cache keeps the n most recently used results and evicts the least recently used when full (problem 14).

ordered_dict.py
from collections import OrderedDict

cache = OrderedDict()
for key in ["a", "b", "c"]:
    cache[key] = key.upper()
cache.move_to_end("a")          # "a" was just used: it is now the newest
oldest = cache.popitem(last=False)
print(oldest, list(cache))
Output
('b', 'B') ['c', 'a']

collections.ChainMap(user, env, defaults) looks a key up in each mapping in order and returns the first hit, without copying or merging anything. Later changes to the underlying dicts show through immediately, which suits layered configuration that can change at run time. For a one-off merged snapshot, defaults | env | user (4.5) is simpler.

from collections import defaultdict

def group_by_status(tickets):
    groups = defaultdict(list)
    for t in tickets:

6. Balanced class weights

HintOpen a hint

Count once with Counter. n_samples is len(labels) and n_classes is len(counts).

SolutionShow the solution and why
solution.py
from collections import Counter

def class_weights(labels):
    counts = Counter(labels)
    n, k = len(labels), len(counts)
    return {c: round(n / (k * counts[c]), 4) for c in sorted(counts)}

The rare class gets a weight above 1 and the common class one below 1, so each class contributes equally to the loss in total: 8 × 0.625 = 2 × 2.5 = 5. This is scikit-learn's class_weight="balanced" (compute_class_weight), used when a model would otherwise learn to always predict the majority class. With no labels, counts is empty and the comprehension returns {} without dividing by zero.

from collections import defaultdict

    for t in tickets:

HintOpen a hint

SolutionShow the solution and why
solution.py
from collections import Counter, defaultdict

def summarise_errors(logs):
    examples = defaultdict(list)
    for line in logs:
        level, msg = line.split(": ", 1)
        examples[level].append(msg)
    counts = Counter({level: len(msgs) for level, msgs in examples.items()})
    return counts, dict(examples)

The two hand-written "create if missing" branches collapse into one defaultdict(list), and the counts do not need their own bookkeeping because they are derivable from the groups. Keeping one source of truth removes the chance of the two dicts disagreeing. split(": ", 1) splits only at the first separator, so messages may contain ": " (lesson 5.2). A Counter compares equal to a plain dict with the same counts, which is why the test passes.

13. Several aggregates per group in one pass

Write group_stats(rows, by, value) for a list of dicts: group by the field by and return a dict from group to {"count": ..., "sum": ..., "mean": ..., "min": ..., "max": ...} for the field value, groups in sorted order. Rows missing the value field are skipped. Do it in one pass without storing the values of each group.

TestsThe 2 checks Run tests uses
rows = [{"model": "small", "ms": 120}, {"model": "large", "ms": 900}, {"model": "small", "ms": 80},
        {"model": "small"}, {"model": "large", "ms": 700}]
assert group_stats(rows, "model", "ms") == {
    "large": {"count": 2, "sum": 1600, "mean": 800.0, "min": 700, "max": 900},
    "small": {"count": 2, "sum": 200, "mean": 100.0, "min": 80, "max": 120},
}
assert group_stats([], "model", "ms") == {}
Hint 1Open a hint

Keep running count, sum, min and max per group in a dict of dicts; compute mean at the end.

Hint 2Open a hint

For the first value of a group, min and max start from that value.

SolutionShow the solution and why
solution.py
def group_stats(rows, by, value):
    acc = {}
    for row in rows:
        if value not in row:
            continue
        v = row[value]
        s = acc.get(row[by])
        if s is None:
            acc[row[by]] = {"count": 1, "sum": v, "min": v, "max": v}
        else:
            s["count"] += 1
            s["sum"] += v
            s["min"] = min(s["min"], v)
            s["max"] = max(s["max"], v)
    return {g: {**s, "mean": s["sum"] / s["count"]} for g, s in sorted(acc.items())}

Each aggregate is updated in O(1) per row, so the whole function is O(n) time and O(number of groups) memory: the values of a group are never stored, which is what lets this run over a stream or a huge file. The mean is derived from sum and count at the end instead of being averaged incrementally. This is exactly how a database executes SELECT model, COUNT(ms), SUM(ms), AVG(ms), MIN(ms), MAX(ms) FROM rows GROUP BY model with hash aggregation, and what df.groupby("model")["ms"].agg(["count", "sum", "mean", "min", "max"]) does in pandas. Note that rows missing the value are skipped, which matches SQL's behaviour of ignoring NULLs in aggregates.

solution.py
from collections import OrderedDict


def make_embedding_cache(embed, capacity):
    store = OrderedDict()
    stats = {"hits": 0, "misses": 0}

    def get(text):
        if text in store:
            stats["hits"] += 1
            store.move_to_end(text)
            return store[text]
        stats["misses"] += 1
        vector = embed(text)
        store[text] = vector
        if len(store) > capacity:
            store.popitem(last=False)
        return vector

    return get, stats

Three bugs. A hit did not refresh the entry, so the order was "first inserted" rather than "last used", which is FIFO, not LRU. popitem() defaults to last=True and removed the entry just inserted, so a full cache threw away every new vector; last=False removes the oldest. And stats["hits"] =+ 1 is = +1: it sets the counter to 1 instead of adding, a typo Python accepts silently. Walking the test: after a, bb, a, the order is bb, a; inserting ccc evicts bb; a is a hit; bb is a miss again. solution.py
from collections import defaultdict

def rrf(rankings, k=60):
    scores = defaultdict(float)
    for ranking in rankings:
        for rank, doc in enumerate(ranking, start=1):
            scores[doc] += 1 / (k + rank)
    return sorted(scores, key=lambda doc: (-scores[doc], doc))

RRF only uses ranks, not raw scores, which is why it works for combining BM25 scores and cosine similarities that live on completely different scales. A document ranked well by both lists (d1: 2nd and 1st) beats one ranked first by only one list. The constant k = 60 comes from the original paper (Cormack and others, 2009) and dampens the advantage of the very top ranks. defaultdict(float) accumulates scores for documents seen in any list, and the tuple key makes ties deterministic. Elasticsearch, OpenSearch and many vector databases offer RRF for hybrid search.

Interview

17. Counter, defaultdict(int) or a plain dict with get: how do you choose for counting?

SolutionModel answer

All three are O(1) per item. Counter is the most expressive: it counts a whole iterable in one call (implemented in C, so it is fastest for bulk counting), treats missing items as 0 without inserting them, and adds most_common, total and count arithmetic. defaultdict(int) is best when counting is mixed with other per-key logic in a loop; its catch is that any read of a missing key inserts it. A plain dict with d.get(k, 0) + 1 needs no import and has no hidden behaviour, which suits small or one-off code. Mention returning plain dicts or Counters from functions, never a defaultdict, so callers do not inherit auto-creation.

Interview

18. How would you compute GROUP BY with several aggregates in pure Python, and when would you switch to pandas?

SolutionModel answer

One pass with a dict keyed by the group (a tuple for several columns): keep running aggregates per group (count, sum, min, max, and for variance also a sum of squares, or Welford's online algorithm), and derive the mean and other statistics at the end. That is O(n) time and O(number of groups) memory, and it works on streams that do not fit in memory. Switch to pandas (or SQL, or Polars) when the data fits in memory as columns and you want vectorised speed, many aggregates, joins and readable code: df.groupby(["region", "month"]).agg(...). Stay in pure Python for streaming logs, small data in a service, or when you cannot add a dependency. Mention that SQL engines implement GROUP BY with exactly this hash-aggregation idea.

Interview

19. Design an LRU cache. What data structures do you use, and what is the cost of each operation?

SolutionModel answer

You need O(1) lookup by key and O(1) "move this entry to most recent" and "remove the least recent". The classic design combines a hash map from key to node with a doubly linked list ordered by recency: a hit moves the node to the front, an insert adds at the front, and eviction removes from the back, all O(1). In Python, OrderedDict provides exactly that combination internally, with move_to_end and popitem(last=False), and functools.lru_cache gives it for pure functions as a decorator. Discuss capacity and memory (cache entries keep objects alive), thread safety (a lock around updates, Module 14), what to use as the key (normalise and hash inputs, 2.2), and when a shared cache such as Redis is needed instead because several processes serve requests.

Recap

  • Counter counts in one call, treats missing items as 0, and gives most_common, total and count arithmetic. update adds.
  • defaultdict(factory) creates values on first access. Reads with d[k] create entries too: use in or get, and return plain dicts.
  • GROUP BY in Python: a dict keyed by the group (a tuple for several columns) with running aggregates, one pass, O(n).
  • itertools.groupby only groups consecutive items: sort by the key first, and consume each group immediately.
  • OrderedDict.move_to_end and popitem(last=False) make an O(1) LRU cache; RRF fuses ranked lists using ranks only.
