9.5 Composition and protocols

Building objects from other objects instead of inheriting from them. Composition and delegation, passing collaborators in (dependency injection) so code is testable, duck typing, abstract base classes that enforce an interface, collections.abc mixins, and typing.Protocol for structural interfaces. Applied to one interface for many LLM providers, wrappers that add caching and fallbacks, and RAG pipelines with swappable parts.

19 problems4 easy · 10 medium · 5 hard

1Composition: has a, uses a

With composition, an object holds other objects as attributes and calls them to do parts of its work. A chat session has a client; a cached retriever uses a retriever; a RAG pipeline has an embedder, a vector store and a model. Instead of inheriting behaviour, the outer object delegates: its method calls the inner object's method and adds something around it. The inner object can be anything with the right methods, so one wrapper works for every implementation, and the parts can be swapped at run time.

composition.py
class KeywordRetriever:
    def __init__(self, docs):
        self.docs = docs
    def retrieve(self, query, k=2):
        words = set(query.lower().split())
        hits = [d for d in self.docs if words & set(d.lower().split())]
        return hits[:k]

class CachedRetriever:
    """Adds caching to ANY object with a retrieve(query, k) method."""
    def __init__(self, inner):
        self.inner = inner
        self._cache = {}
        self.hits = 0

    def retrieve(self, query, k=2):
        key = (query.lower().strip(), k)
        if key in self._cache:
            self.hits += 1
        else:
            self._cache[key] = self.inner.retrieve(query, k)   # delegate on a miss
        return list(self._cache[key])

docs = ["Refund policy", "Refund window", "Reset password"]
r = CachedRetriever(KeywordRetriever(docs))
print(r.retrieve("refund"), r.retrieve("Refund "), r.hits)
Output
['Refund policy', 'Refund window'] ['Refund policy', 'Refund window'] 1

Compare this with the caching subclass of 9.4: the subclass works only for the one retriever class it extends, while the wrapper works for a keyword retriever, a vector retriever or a hybrid one, including classes written later, and it can wrap another wrapper (CachedRetriever(FallbackRetriever(...))). Composition also keeps each class small and focused, and its dependencies visible in __init__. Its cost is a little forwarding code, and the wrapper only exposes the methods it chooses to.

2Dependency injection: pass collaborators in

A class that creates its collaborators inside, self.client = OpenAIClient() or time.time() in a method, is welded to them: you cannot test it without calling the real API, and you cannot switch provider without editing it. Dependency injection means passing collaborators in, usually through __init__: ChatService(client, clock). Production code passes the real client and time.monotonic; tests pass a fake, a tiny object with the same methods that returns canned answers, records calls, or raises on demand. You have used this idea since 7.3 with injected clock, sleep and rng; here it is applied to whole objects (problem 14).

injection.py
class FakeClient:
    def __init__(self, replies):
        self.replies = list(replies)
        self.prompts = []
    def complete(self, prompt):
        self.prompts.append(prompt)
        reply = self.replies.pop(0)
        if isinstance(reply, Exception):
            raise reply
        return reply

class Summariser:
    def __init__(self, client, max_words=5):
        self.client = client                 # injected: real or fake
        self.max_words = max_words
    def summarise(self, text):
        reply = self.client.complete(f"Summarise in {self.max_words} words: {text}")
        return " ".join(reply.split()[: self.max_words])

fake = FakeClient(["Refunds take five business days usually", TimeoutError("slow")])
s = Summariser(fake)
print(s.summarise("long refund policy text"), "|", fake.prompts[0][:25])
try:
    s.summarise("again")
except TimeoutError:
    print("timeout path tested without a network")
Output
Refunds take five business days | Summarise in 5 words: lon
timeout path tested without a network

Notice that FakeClient does not inherit from any client class. Summariser only ever calls client.complete(prompt), so any object with that method works: that is duck typing, the next section. Injection pays off three times: tests are fast and deterministic, the failure paths can be exercised on purpose, and swapping implementations is a configuration change at the place where objects are created (often a small "composition root" function or the app's start-up code).

3Duck typing

Python does not check types when you call a method: obj.read() works if obj has a read method, whatever its class. Duck typing designs code around that: a function that needs "something with read()" accepts files, io.StringIO objects, network streams and fakes alike. Built-in functions work the same way: sum, sorted and for accept any iterable, len anything with __len__ (9.2). Checking isinstance(x, list) before using x throws that flexibility away: it rejects tuples, generators, NumPy arrays and every custom sequence that would have worked (problem 10).

import io

print(count_lines(io.StringIO("a\n\nb\nc\n")), count_lines(["x", " ", "y"]), count_lines(FakeStream()))

        name = model.name
    except AttributeError:

The price of duck typing is that mistakes surface at run time, when a missing method is finally called, and that the expected interface is implicit. The next two tools make the interface explicit: abstract base classes enforce it at instantiation, and protocols let type checkers verify it before the program runs.

4Abstract base classes

An abstract base class (ABC) declares an interface that subclasses must implement. Inherit from abc.ABC and mark the required methods with @abstractmethod. Python then refuses to instantiate any class that still has unimplemented abstract methods, with a TypeError naming them, which is earlier and clearer than a NotImplementedError raised on first use (9.4). Abstract methods can contain a default implementation that subclasses call with super(), and the ABC can provide ordinary concrete methods built on the abstract ones.

abc.py
from abc import ABC, abstractmethod

class LLMProvider(ABC):
    def __init__(self, model):
        self.model = model

    @abstractmethod
    def _complete(self, prompt):
        """Return the model's text for one prompt."""

    def complete(self, prompt):                    # concrete method built on the abstract one
        if not prompt.strip():
            raise ValueError("empty prompt")
        return {"model": self.model, "text": self._complete(prompt).strip()}

class Echo(LLMProvider):
    def _complete(self, prompt):
        return prompt

class Forgetful(LLMProvider):
    pass

print(Echo("echo-1").complete(" hi "))
for cls in (LLMProvider, Forgetful):
    try:
        cls("x")
    except TypeError as e:
        print("TypeError:", e)
Output
{'model': 'echo-1', 'text': 'hi'}
TypeError: Can't instantiate abstract class LLMProvider without an implementation for abstract method '_complete'
TypeError: Can't instantiate abstract class Forgetful without an implementation for abstract method '_complete'

The standard library's collections.abc module defines ABCs for Python's protocols: Iterable, Sequence, Mapping, MutableMapping, Callable and more. They serve two purposes. isinstance(x, Iterable) checks for the protocol rather than a specific type. And subclassing one gives you mixin methods: inherit collections.abc.Mapping, implement just __getitem__, __iter__ and __len__, and you get keys, items, values, get, __contains__ and __eq__ for free, all consistent with your three methods (problem 7).

collections_abc.py
from collections.abc import Mapping, Iterable, Sequence

class Settings(Mapping):
    def __init__(self, raw):
        self._data = {k.lower(): v for k, v in raw.items()}
    def __getitem__(self, key):
        return self._data[key.lower()]
    def __iter__(self):
        return iter(self._data)
    def __len__(self):
        return len(self._data)

s = Settings({"MODEL": "small", "Temperature": 0.2})
print(s["model"], s.get("TOP_P", 1.0), "temperature" in s, sorted(s.items()), dict(s) == {"model": "small", "temperature": 0.2})
print(isinstance([1], Iterable), isinstance((x for x in []), Sequence), isinstance("ab", Sequence), isinstance(s, Mapping))
Output
small 1.0 True [('model', 'small'), ('temperature', 0.2)] True
True False True True

5Protocols: interfaces without inheritance

ABCs are nominal: a class matches only if it inherits from the ABC (or is explicitly registered). Duck typing is structural: anything with the right methods matches. typing.Protocol brings structural typing to type hints. You describe the interface as a class whose methods have bodies of ..., and any class with matching methods counts as implementing it, without importing or inheriting from it. Type checkers such as mypy and pyright (11.1) then verify, before the program runs, that what you pass has those methods with compatible signatures. Decorating the protocol with @runtime_checkable also allows isinstance checks, which test only that the methods exist, not their signatures.

protocols.py
from typing import Protocol, runtime_checkable

@runtime_checkable
class Embedder(Protocol):
    def embed(self, texts: list[str]) -> list[list[float]]:
        ...

class LengthEmbedder:                         # no inheritance at all
    def embed(self, texts):
        return [[float(len(t)), float(t.count(" "))] for t in texts]

class NotAnEmbedder:
    def encode(self, texts):
        return []

def nearest(embedder: Embedder, query: str, docs: list[str]) -> str:
    q, *vectors = embedder.embed([query, *docs])
    distance = lambda v: sum((a - b) ** 2 for a, b in zip(q, v))
    return min(zip(docs, vectors), key=lambda pair: distance(pair[1]))[0]

print(nearest(LengthEmbedder(), "refund window", ["refund policy", "reset password now", "hi"]))
print(isinstance(LengthEmbedder(), Embedder), isinstance(NotAnEmbedder(), Embedder))
Output
refund policy
True False

Protocols fit code you do not control: your function can require "an embedder" and accept a class from any library that happens to have embed, without that library knowing about your protocol. ABCs fit hierarchies you own, where you want shared concrete methods and instantiation-time checks. Many projects use both: an ABC as the base for their own implementations, and a protocol in the type hints of the code that consumes them.

6Wrappers, strategies and delegation

Composition gives you a handful of patterns that cover most designs. A wrapper (or decorator object) has the same interface as what it wraps and adds behaviour: caching, retries, fallbacks, logging, rate limiting, each a small class, stacked like decorators in 8.2. A strategy is a swappable part: a pipeline holds a chunker, a retriever and a reranker, each chosen by configuration. Plain functions are often the simplest strategy (key=, score=), and classes take over when the strategy has state or settings.

When a wrapper should forward everything it does not handle itself, __getattr__ helps: Python calls obj.__getattr__(name) only when normal lookup fails, so a proxy can define the few methods it changes and forward the rest with return getattr(self._inner, name) (problem 15). Use it sparingly: forwarded attributes are invisible to IDEs and type checkers, typos turn into confusing errors from the inner object, and every forwarded access is slower than a normal one (problem 8).

wrappers.py
class FallbackProvider:
    def __init__(self, *providers, on=(TimeoutError, ConnectionError)):
        self.providers = providers
        self.on = on
        self.last_used = None

    def complete(self, prompt):
        last_error = None
        for p in self.providers:
            try:
                result = p.complete(prompt)
            except self.on as e:
                last_error = e
                continue
            self.last_used = type(p).__name__
            return result
        raise last_error

class Down:
    def complete(self, prompt):
        raise TimeoutError("primary timed out")

class Up:
    def complete(self, prompt):
        return f"answer to {prompt}"

fp = FallbackProvider(Down(), Up())
print(fp.complete("refund?"), fp.last_used)
Output
answer to refund? Up

solution.py
class CachedRetriever:
    def __init__(self, inner, max_entries=256):
        self.inner = inner
        self.max_entries = max_entries
        self._cache = {}
        self.hits = 0
        self.misses = 0

    def retrieve(self, query, k):
        key = (query, k)
        if key in self._cache:
            self.hits += 1
        else:
            self.misses += 1
            if len(self._cache) >= self.max_entries:
                del self._cache[next(iter(self._cache))]
            self._cache[key] = list(self.inner.retrieve(query, k))
        return list(self._cache[key])

    def clear(self):
        self._cache.clear()

The wrapper depends only on the inner object's retrieve method, so it works with every retriever, including another CachedRetriever (the last test), which is what makes wrappers composable like decorators. Eviction removes the oldest key, the first in a dict's insertion order (8.3). Copies in and out protect the cache from callers changing lists. Because nothing is inherited, the wrapper's behaviour is entirely visible in this class: no inherited methods it might accidentally expose.

4. Duck typing and runtime protocols

from typing import Protocol, runtime_checkable

@runtime_checkable
class Closeable(Protocol):
    def close(self) -> None: ...

class File:
    def close(self):
        return "closed file"

class Conn:
    def close(self, force):
        return "closed conn"

class Nothing:
    pass

print([isinstance(x, Closeable) for x in (File(), Conn(), Nothing())])

def shutdown(items):
    out = []
    for item in items:
        try:
            out.append(item.close())
        except AttributeError:
            out.append("skipped")
        except TypeError:
            out.append("bad signature")
    return out

print(shutdown([File(), Nothing(), Conn()]))

solution.py
from collections import Counter

class FallbackProvider:
    def __init__(self, *providers, on=(TimeoutError, ConnectionError)):
        if not providers:
            raise ValueError("at least one provider is required")
        self.providers = providers
        self.on = on
        self.used = []
        self.failures = Counter()

    def complete(self, prompt):
        last_error = None
        for p in self.providers:
            try:
                result = p.complete(prompt)
            except self.on as e:
                self.failures[type(e).__name__] += 1
                last_error = e
                continue
            self.used.append(type(p).__name__)
            return result
        last_error.add_note("tried: " + ", ".join(type(p).__name__ for p in self.providers))
        raise last_error

Because FallbackProvider exposes the same complete method as what it holds, callers cannot tell it apart from a single provider, and it can itself be wrapped (by a cache, by another fallback): composition of objects with one shared interface. The failure counter turns degradation into data: a dashboard showing many TimeoutErrors for the primary tells you it is struggling before users notice. Only the listed transient errors trigger the fallback; a KeyError is a bug and propagates at once (7.3). The note on the final error records the whole path without changing its type.

solution.py
class UndoStack:
    def __init__(self):
        self._items = []

    def push(self, action):
        self._items.append(action)

    def pop(self):
        if not self._items:
            raise IndexError("undo stack is empty")
        return self._items.pop()

    def peek(self):
        if not self._items:
            raise IndexError("undo stack is empty")
        return self._items[-1]

    def __len__(self):
        return len(self._items)

Inheriting from list made the stack promise the whole list interface: insert, sort, slicing, del s[0], any of which destroys the undo order. A stack is not a list; it uses one. Composition exposes exactly the five operations the stack should have, so its rule ("last in, first out") cannot be broken from outside, and the error message can speak the stack's language. __len__ gives both len(s) and truthiness (9.2). This is the substitution test from 9.4 applied in reverse: if the subclass would have to disable base methods, use composition.

solution.py
from collections.abc import Mapping

class EnvConfig(Mapping):
    def __init__(self, environ, prefix):
        self._environ = environ
        self._prefix = prefix

    def __getitem__(self, key):
        return self._environ[self._prefix + key.upper()]

    def __iter__(self):
        for k in self._environ:
            if k.startswith(self._prefix):
                yield k[len(self._prefix):].lower()

    def __len__(self):
        return sum(1 for _ in self)

    def __repr__(self):
        return f"EnvConfig(prefix={self._prefix!r}, keys={sorted(self)})"

Mapping builds get, __contains__, keys, items, values and __eq__ from the three methods, all consistent with them: get catches the KeyError from __getitem__, in uses __getitem__ too, and items pairs __iter__ with __getitem__. Writing just the three core methods is less code and fewer chances for inconsistency than implementing all of them by hand. Holding a reference to environ rather than a copy makes it a live view, like dict views (4.5); pass os.environ in production and a plain dict in tests, which is dependency injection again. Being a Mapping (not a MutableMapping) also documents that configuration is read-only here.

from collections.abc import Iterable

def normalise_scores(scores):
    if isinstance(scores, (str, bytes)) or not isinstance(scores, Iterable):
        raise TypeError(f"scores must be an iterable of numbers, got {type(scores).__name__}")
    values = list(scores)
    top = max(values) if values else 0
    return [v / top for v in values] if top else [0.0 for _ in values]

The function only iterates over its input once (by converting it to a list), so requiring a list was an arbitrary restriction that broke tuples, generators, range and NumPy arrays, the duck-typing mistake. collections.abc.Iterable checks the capability instead of the type. An integer is not iterable and is rejected with a clear message instead of failing inside list().

Hint 2Open a hint

Cosine: dot / (norm_a * norm_b), treating a zero norm as similarity 0.

SolutionShow the solution and why
solution.py
import math
from typing import Protocol, runtime_checkable


@runtime_checkable
class VectorStore(Protocol):
    def add(self, ids: list[str], vectors: list[list[float]]) -> None: ...
    def query(self, vector: list[float], k: int) -> list[str]: ...


class MemoryStore:
    def __init__(self):
        self._ids, self._vectors = [], []

    def add(self, ids, vectors):
        self._ids.extend(ids)
        self._vectors.extend(vectors)

    @staticmethod
    def _cosine(a, b):
        na, nb = math.sqrt(sum(x * x for x in a)), math.sqrt(sum(x * x for x in b))
        return sum(x * y for x, y in zip(a, b)) / (na * nb) if na and nb else 0.0

    def query(self, vector, k):
        scored = [(self._cosine(vector, v), i) for i, v in zip(self._ids, self._vectors)]
        ranked = sorted(scored, key=lambda p: p[0], reverse=True)
        return [i for _, i in ranked[:k]]


def index_and_search(store, embed, docs, query, k):
    if not isinstance(store, VectorStore):
        raise TypeError(f"{type(store).__name__} does not implement VectorStore")
    store.add([f"d{i}" for i in range(len(docs))], embed(docs))
    return store.query(embed([query])[0], k)

index_and_search depends only on the two methods of the protocol, so it works with this in-memory store, with a client for Chroma, Qdrant or pgvector wrapped to have add and query, or with a test fake, and MemoryStore never imports or inherits the protocol (the last assertion). The isinstance check gives an early, clear error, though it only verifies that the methods exist. Stable sorting keeps ties in insertion order. Passing embed as a plain function is the simplest strategy object; if the embedder needed state (a model, a cache), it would be an object satisfying an Embedder protocol instead.

solution.py
class Pipeline:
    def __init__(self, steps, clock):
        self.steps = list(steps)
        self.clock = clock
        self.trace = []

    def run(self, state):
        self.trace = []
        state = dict(state)
        for name, step in self.steps:
            start = self.clock()
            try:
                state = step(state)
            except Exception as e:
                e.add_note(f"in step {name}")
                raise
            self.trace.append((name, self.clock() - start))
        return state

    def replace(self, name, step):
        names = [n for n, _ in self.steps]
        if name not in names:
            raise KeyError(name)
        new_steps = [(n, step if n == name else s) for n, s in self.steps]
        return Pipeline(new_steps, self.clock)

The pipeline knows nothing about retrieval or generation: it composes callables that share one contract (state in, state out), so every step can be a function, a callable object (9.2) or a wrapper, and swapping one is a configuration change. replace returns a new pipeline, so experiments (a different reranker) cannot affect the original, the immutable-update style of 2.3. Copying the input state keeps the caller's dict untouched, and steps return new dicts rather than mutating. The trace with an injected clock gives exact per-step timings in tests, and the note on failures names the step without changing the exception type (7.2). LangChain's runnables and Haystack pipelines are this idea with many more features.

import time


class RealClient:
    def raw_request(self, payload):
        raise RuntimeError("network not available in tests")

    def complete(self, prompt):
        return self.raw_request({"prompt": prompt})


class AnswerService:
    def __init__(self, client, clock=time.monotonic, max_chars=200):

        self.clock = clock
        self.max_chars = max_chars
        self.history = []

from collections import Counter

class Metered:
    _OWN = ("_inner", "calls")

    def __init__(self, inner):
        object.__setattr__(self, "_inner", inner)
        object.__setattr__(self, "calls", Counter())

    def __getattr__(self, name):
        attr = getattr(self._inner, name)
        if not callable(attr):
            return attr

        def counted(*args, **kwargs):
            self.calls[name] += 1
            return attr(*args, **kwargs)
        return counted

    def __setattr__(self, name, value):
        if name in self._OWN:
            object.__setattr__(self, name, value)
        else:
            setattr(self._inner, name, value)

__getattr__ is only consulted when normal lookup fails, so the proxy's real attributes (_inner, calls, its methods) are found normally and never forwarded, while everything else, complete, embed, model and any method added to the client later, is fetched from the inner object. Wrapping callables in a small closure lets the proxy count calls without knowing the inner object's interface. Overriding __setattr__ makes assignments go to the inner object too, which is why __init__ must bypass it with object.__setattr__. A missing attribute raises the inner object's AttributeError naturally. Proxies like this are how libraries add instrumentation to SDK clients (OpenTelemetry's auto-instrumentation, request-recording test tools); the trade-off is that IDEs and type checkers cannot see the forwarded attributes.

17. Compare duck typing, abstract base classes and typing.Protocol.

SolutionModel answer

All three describe "an object with these methods", with different enforcement. Duck typing has no declaration at all: code simply calls the methods it needs, so any object with them works, and mistakes surface at run time when a method is missing. An ABC (abc.ABC with @abstractmethod) is nominal: implementations inherit from it (or are registered), Python refuses to instantiate subclasses missing abstract methods, and the ABC can supply shared concrete methods, like collections.abc.Mapping deriving get and items. A Protocol is structural: any class with matching methods satisfies it without inheriting, and type checkers verify signatures before running; @runtime_checkable adds isinstance support that checks only method names. Use ABCs for hierarchies you own and want enforced at instantiation, protocols to type the code that consumes interfaces (especially from third-party classes), and plain duck typing for small internal code.

Interview

18. What is dependency injection, and why does it matter for testing LLM applications?

SolutionModel answer

Dependency injection means a component receives the objects it depends on (an LLM client, a vector store, a clock, a random generator, a logger) instead of constructing them itself, usually through __init__ parameters with production defaults. The wiring happens in one place at start-up. For LLM applications it is what makes tests possible and cheap: a fake client returns scripted replies, raises timeouts or rate limits on demand, and records the prompts it received, so tests can assert on exact prompts, retries, fallbacks and parsing without network calls, cost or non-determinism; a fake clock makes timing and backoff checks instant. It also makes swapping providers, models or stores a configuration change rather than a code change. The sign it is missing: classes that call OpenAI(), time.time() or random.random() deep inside their methods.

19. Design the components of a pluggable RAG system. Where do you use composition, protocols and inheritance?

SolutionModel answer

Define small interfaces as protocols for each role: a Loader (path to documents), a Chunker (document to chunks), an Embedder (texts to vectors), a VectorStore (add, query, delete by id), a Reranker (query and candidates to ordered candidates), and an LLM (messages to a response). The RAG service is composed of one object per role, all injected, so each can be swapped by configuration (a different embedding model, Qdrant instead of an in-memory store) and faked in tests. Cross-cutting behaviour is added by composition as wrappers with the same interface: a caching embedder, a retrying LLM, a fallback between providers, a tracing layer around every component. Inheritance is kept shallow and local: an ABC or base class for your own implementations of one role when they share real code (common validation and batching in embedders), and exception hierarchies. Plain functions serve as simple strategies (chunking rules, scoring). The design makes each component testable alone, lets evaluations compare variants by swapping one component, and keeps vendor SDKs at the edges behind adapters.

Recap

  • Composition (has a, uses a) builds objects from other objects and delegates to them; wrappers with the same interface stack like decorators.
  • Inject collaborators (clients, stores, clocks) through __init__; tests then pass fakes and check prompts, timings and failure paths.
  • Duck typing: rely on the methods you call, not on the type; check capabilities (collections.abc.Iterable) rather than isinstance(x, list).
  • ABCs with @abstractmethod enforce an interface at instantiation and can supply concrete methods; collections.abc mixins derive many methods from a few.
  • typing.Protocol defines structural interfaces checked by type checkers; prefer composition to inheritance unless there is a real "is a".
