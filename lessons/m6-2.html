6.2 Dict, set and nested comprehensions

The same comprehension syntax builds dicts and sets. Duplicate keys and how the last one wins, inverting a mapping safely, why grouping is the job comprehensions do badly, ordering and determinism, and the dict.fromkeys trap. Applied to label maps, vocabularies, configs, inverted indexes and confusion matrices.

1Dict comprehensions

A dict comprehension has the same shape as a list comprehension, with curly braces and a key: value pair in front: {key_expr: value_expr for name in iterable if condition}. It means exactly this loop: start with an empty dict, and for every item that passes the condition, evaluate both expressions and assign d[key] = value. The word "assign" matters, as you will see in a moment.

dict_comp.py
prices = {"gpt-small": 0.15, "gpt-large": 2.50, "embed": 0.02}

cheap = {}
for name, price in prices.items():          # the loop
    if price < 1:
        cheap[name] = price * 1000
cheap2 = {name: price * 1000 for name, price in prices.items() if price < 1}
print(cheap == cheap2, cheap2)

words = ["refund", "policy", "reset"]
print({w: len(w) for w in words}, {i: w for i, w in enumerate(words)})
print(dict(zip(words, [3, 1, 2])))
Output
True {'gpt-small': 150.0, 'embed': 20.0}
{'refund': 6, 'policy': 6, 'reset': 5} {0: 'refund', 1: 'policy', 2: 'reset'}
{'refund': 3, 'policy': 1, 'reset': 2}

The most common sources are d.items() (to transform or filter an existing dict, unpacking each pair into two names), enumerate (to number things) and zip (to pair two lists). For a plain pairing with no transformation, dict(zip(keys, values)) is shorter than a comprehension and says the same thing. Remember from 4.1 that zip stops at the shorter input silently; pass strict=True when the lengths must match.

Because each item does d[key] = value, a repeated key overwrites the earlier value: the last one wins. The key keeps the position where it was first inserted, though, because assigning to an existing key does not move it (4.5). This is the source of a classic bug: inverting a dict whose values are not unique silently loses entries.

last_wins.py
pairs = [("a", 1), ("b", 2), ("a", 3)]
print({k: v for k, v in pairs})
category = {"faq.md": "billing", "terms.md": "legal", "invoice.md": "billing"}
print({cat: doc for doc, cat in category.items()})       # loses faq.md
print(len(category), len({cat: doc for doc, cat in category.items()}))
Output
{'a': 3, 'b': 2}
{'billing': 'invoice.md', 'legal': 'terms.md'}
3 2

The inverted dict has two keys for three documents: faq.md was overwritten by invoice.md, with no error. When values can repeat, inverting is really grouping (one key, several values), which needs a list per key; the next sections show why a comprehension is the wrong tool for that and what to use instead (problem 3).

2Set comprehensions

A set comprehension uses curly braces with a single expression: {expr for name in iterable if condition}. It builds a set, so duplicates disappear and membership checks are O(1) (4.4). It is the natural way to transform and deduplicate at once: the distinct domains of a list of emails, the distinct lower-cased words of a text, the ids that appear in a log.

set_comp.py
emails = ["ana@Example.com", "bo@example.com", "cy@test.io", "dee@EXAMPLE.com"]
domains = {e.split("@")[1].lower() for e in emails}
print(sorted(domains), len(domains))
text = "Refund the refund, then REFUND it"
print(sorted({w.strip(",").lower() for w in text.split()}))
print(type({}).__name__, type({1}).__name__, type(set()).__name__, type({x for x in ""}).__name__)
Output
['example.com', 'test.io'] 2
['it', 'refund', 'the', 'then']
dict set set set

Two details catch people. {} is an empty dict, not an empty set, because dicts came first in Python; an empty set is written set(). And a set has no meaningful order: for strings, the order even changes between runs of the program, because string hashes are randomised per process for security (hash randomisation, controlled by the PYTHONHASHSEED environment variable). So never number, save or display a set without sorting it first; the examples on this page always print sorted(...). Building anything from a set, such as ids for labels, without sorting makes the result different on every run, which is a real bug in ML code (problem 19).

Equality also decides what counts as a duplicate: {1, 1.0, True} has one element, because 1 == 1.0 == True and they hash the same, while 0.1 + 0.2 and 0.3 are two elements, because they are not equal (1.1). Normalise values (case, whitespace, rounding) inside the comprehension when "the same" should mean more than ==.

3Grouping: the job comprehensions do badly

A frequent wish is "a dict from each category to the list of its items". You can write it as a nested comprehension, {c: [x for x in items if key(x) == c] for c in categories}, and it gives the right answer. But look at what it does: for every category, it scans all items. With n items and k categories that is n x k checks, where a single pass with a defaultdict(list) does n (4.6). With 100,000 items and 50 categories, that is 5,000,000 checks instead of 100,000 (problem 8).

grouping.py
from collections import defaultdict

docs = [("faq.md", "billing"), ("terms.md", "legal"), ("invoice.md", "billing"), ("gdpr.md", "legal")]

cats = sorted({cat for _, cat in docs})
slow = {c: [d for d, cat in docs if cat == c] for c in cats}     # scans docs once per category

groups = defaultdict(list)                                       # one pass
for doc, cat in docs:
    groups[cat].append(doc)
print(slow, dict(groups), slow == dict(groups))
Output
{'billing': ['faq.md', 'invoice.md'], 'legal': ['terms.md', 'gdpr.md']} {'billing': ['faq.md', 'invoice.md'], 'legal': ['terms.md', 'gdpr.md']} True

So the rule is: a comprehension transforms or filters one item at a time; grouping and counting accumulate across items, which is what defaultdict and Counter are for. Comprehensions combine well with the result, though: after grouping, a dict comprehension can turn each group into a summary, such as its size or mean, in one readable line.

group_then_summarise.py
from collections import defaultdict

latencies = [("rag-api", 120), ("auth", 30), ("rag-api", 340), ("auth", 50), ("rag-api", 200)]
groups = defaultdict(list)
for service, ms in latencies:
    groups[service].append(ms)
summary = {s: {"n": len(v), "mean": sum(v) / len(v), "max": max(v)} for s, v in sorted(groups.items())}
print(summary)
Output
{'auth': {'n': 2, 'mean': 40.0, 'max': 50}, 'rag-api': {'n': 3, 'mean': 220.0, 'max': 340}}

4dict.fromkeys, merging, and initial values

dict.fromkeys(keys, value) builds a dict with every key mapped to the same value. For an immutable value like 0 or None that is fine. For a mutable value like [] or {} it is a trap, exactly like [[]] * 3 in 6.1: there is one list, and every key refers to it, so appending under one key appends under all of them. A dict comprehension evaluates the value expression once per key, creating a separate list each time (problem 11).

fromkeys.py
classes = ["ham", "spam"]
shared = dict.fromkeys(classes, [])
shared["spam"].append(0.9)
separate = {c: [] for c in classes}
separate["spam"].append(0.9)
print(shared, separate)
print(dict.fromkeys(["b", "a", "b"]), list(dict.fromkeys(["b", "a", "b"])))
Output
{'ham': [0.9], 'spam': [0.9]} {'ham': [], 'spam': [0.9]}
{'b': None, 'a': None} ['b', 'a']

The last line is the good use of fromkeys you saw in 4.5: deduplicating while keeping order, since every value is None. For merging dicts, you rarely need a comprehension. {**defaults, **overrides} and defaults | overrides (Python 3.9+) both build a new dict where later keys win, and |= updates in place. A comprehension is for when the merge has a rule, such as ignoring overrides that are None, or rejecting unknown keys (problem 6).

merging.py
defaults = {"model": "small", "temperature": 0.7, "max_tokens": 256}
overrides = {"temperature": 0, "max_tokens": None}
print({**defaults, **overrides})
print(defaults | overrides == {**defaults, **overrides})
print({k: overrides[k] if overrides.get(k) is not None else v for k, v in defaults.items()})
print({k: overrides.get(k) or v for k, v in defaults.items()})      # wrong: drops temperature 0
Output
{'model': 'small', 'temperature': 0, 'max_tokens': None}
True
{'model': 'small', 'temperature': 0, 'max_tokens': 256}
{'model': 'small', 'temperature': 0.7, 'max_tokens': 256}

The last line shows the falsy trap of 1.2 inside a comprehension: x or default replaces any falsy value, so a deliberate temperature=0 (deterministic output) is silently turned back into 0.7. Test for None explicitly when 0, "" or False are valid values.

5Nested dict comprehensions

The value expression of a dict comprehension can be another comprehension, which builds nested structures: a dict of lists, a dict of dicts, a dict of sets. Read it from the outside in: the outer for decides the keys, and the inner comprehension builds the value for each key. Two typical ML uses are a confusion matrix as a dict of dicts, {actual: {predicted: count}}, and per-document sets of words for keyword search.

confusion.py
from collections import Counter

y_true = ["spam", "ham", "spam", "ham", "spam"]
y_pred = ["spam", "spam", "ham", "ham", "spam"]
classes = sorted(set(y_true) | set(y_pred))
pairs = Counter(zip(y_true, y_pred))
matrix = {a: {p: pairs[(a, p)] for p in classes} for a in classes}
print(matrix)
recall = {c: matrix[c][c] / sum(matrix[c].values()) for c in classes}
print({c: round(r, 3) for c, r in recall.items()})
Output
{'ham': {'ham': 1, 'spam': 1}, 'spam': {'ham': 1, 'spam': 2}}
{'ham': 0.5, 'spam': 0.667}

Notice the division of labour: Counter does the counting in one pass, then the comprehension only looks up counts, which is cheap. A Counter returns 0 for a missing pair instead of raising, which is why pairs[("ham", "ham")] works even if that pair never occurred. Using classes for both loops gives every row every column, in a fixed order, which is what makes the matrix printable and comparable between runs.

word_sets.py
docs = {"faq": "Refunds take 5 days.", "terms": "No refunds after 30 days.", "auth": "Reset your password."}
words = {doc_id: {w.strip(".,").lower() for w in text.split()} for doc_id, text in docs.items()}
print(sorted(words["terms"]))
query = {"refunds", "days"}
print([doc_id for doc_id, ws in words.items() if query <= ws])
Output
['30', 'after', 'days', 'no', 'refunds']
['faq', 'terms']

query <= ws is the subset test of 4.4: the document contains every query word. This is the core of keyword (lexical) search, the half of hybrid retrieval that catches exact terms such as product codes, which embeddings can miss (problem 7). Beyond two levels of nesting, write a function for the inner part and call it in the comprehension; three nested comprehensions are hard for anyone to check.

6Label maps and vocabularies: comprehensions in model code

Models work with integers, people with names. Every classification project therefore has a label map: label2id from class name to integer and id2label back. Hugging Face models store exactly these two dicts in their config.json. Both are one dict comprehension over a sorted list of unique labels, and the sorting is what makes the ids the same on every machine and every run.

label_maps.py
raw_labels = ["spam", "ham", "phishing", "spam", "ham"]
classes = sorted(set(raw_labels))
label2id = {label: i for i, label in enumerate(classes)}
id2label = {i: label for label, i in label2id.items()}
print(label2id, id2label)
print([label2id[l] for l in raw_labels], [id2label[i] for i in [2, 0]])
Output
{'ham': 0, 'phishing': 1, 'spam': 2} {0: 'ham', 1: 'phishing', 2: 'spam'}
[2, 0, 1, 2, 0] ['spam', 'ham']

Inverting is safe here because the ids are unique by construction. A vocabulary works the same way, with a filter for rare words and special entries for padding and unknown tokens. Note the order of the comprehension's parts: the specials come first so their ids are fixed (0 and 1), and the real words are numbered after them with enumerate(..., start=2).

vocab.py
from collections import Counter

corpus = ["refund my order", "refund policy", "order status", "my refund"]
counts = Counter(w for line in corpus for w in line.split())
specials = ["<pad>", "<unk>"]
words = sorted(w for w, n in counts.items() if n >= 2)
vocab = {**{s: i for i, s in enumerate(specials)}, **{w: i for i, w in enumerate(words, start=len(specials))}}
print(vocab)
print([vocab.get(w, vocab["<unk>"]) for w in "refund status please".split()])
Output
{'<pad>': 0, '<unk>': 1, 'my': 2, 'order': 3, 'refund': 4}
[4, 1, 1]

vocab.get(w, vocab["<unk>"]) maps unseen words to the unknown id instead of raising, which is what a model needs at serving time, when users type words that were never in the training data. The vocabulary and label maps must be saved with the model and loaded at serving time, never rebuilt from new data, or the ids will not mean what the model learned (problem 19).

def label_maps(labels):
    classes = sorted(set(labels))
    label2id = {label: i for i, label in enumerate(classes)}
    id2label = {i: label for label, i in label2id.items()}

SolutionShow the solution and why
solution.py
from collections import defaultdict

def docs_by_category(category):
    groups = defaultdict(list)
    for doc, cat in category.items():
        groups[cat].append(doc)
    return {cat: sorted(docs) for cat, docs in groups.items()}

Each billing document assigned a new one-item list to the same key, so only the last survived. A comprehension is still the right tool for the second step, turning each group into its sorted form. Dict equality ignores key order, so the test passes whatever order the categories were first seen in.

def costs(usage, prices):
    raw = {
        m: round((u["in"] * prices[m]["in"] + u["out"] * prices[m]["out"]) / 1_000_000, 4)
        for m, u in usage.items()

    }

Prices per million tokens is how LLM providers quote them, which is why the division by 1,000,000 happens once at the end.

def merge(defaults, overrides):
    unknown = overrides.keys() - defaults.keys()
    if unknown:
        raise KeyError(f"unknown settings: {sorted(unknown)}")
    return {k: v if overrides.get(k) is None else overrides[k] for k, v in defaults.items()}

Two bugs. or treats 0 and False as missing, so a deterministic temperature=0 and stream=False were silently replaced by the defaults (1.2); is None distinguishes "not given" from "given as a falsy value". Rejecting unknown keys is the behaviour of Pydantic models with extra="forbid" (Module 11), which is what production config loaders use.

Hint 2Open a hint

SolutionShow the solution and why
solution.py
def words(text):
    return {w.strip(".,!?").lower() for w in text.split()} - {""}

def keyword_search(docs, query):
    q = words(query)
    if not q:
        return []
    index = {doc_id: words(text) for doc_id, text in docs.items()}
    return sorted(doc_id for doc_id, ws in index.items() if q <= ws)

Using the same words function for documents and query guarantees both are normalised the same way; tokenising them differently is the classic reason keyword search "misses" obvious matches. Subtracting {""} removes the empty string a bare punctuation token would leave. The subset test q <= ws is "all query words present" (4.4). Note that refund does not match refunds: exact-word search needs stemming or a proper analyser for that, which is what BM25 libraries and search engines add. Without the empty-query check, set() <= ws would be true for every document.

solution.py
def ratio(num, den):
    return round(num / den, 3) if den else 0.0

def precision_recall(tp, fp, fn):
    classes = sorted(tp.keys() | fp.keys() | fn.keys())
    return {
        c: {
            "precision": ratio(tp.get(c, 0), tp.get(c, 0) + fp.get(c, 0)),
            "recall": ratio(tp.get(c, 0), tp.get(c, 0) + fn.get(c, 0)),
        }
        for c in classes
    }

The repeated "divide unless the denominator is 0" logic moves into one named helper, which is what makes the comprehension short enough to read. Key views support | directly, so there is no need to build sets first. The class phish has only a false positive: its precision is 0 out of 1, and its recall has a denominator of 0, which the helper turns into 0.0 instead of a ZeroDivisionError. scikit-learn's classification_report computes the same numbers, and its zero_division parameter is exactly this helper's choice of 0.0.

solution.py

    for label, score in preds:

Hint 1Open a hint

For each key, value: if value is a dict, flatten it recursively and prefix each of its keys; otherwise yield the pair as it is.

Hint 2Open a hint

A dict comprehension with two for clauses can walk the pairs that the inner call returns: {f"{k}{sep}{ik}": iv for k, v in ... for ik, iv in flatten(v, sep).items()}. Handle non-dict values by wrapping them as a one-item dict.

SolutionShow the solution and why
solution.py
def flatten(config, sep="."):
    return {
        f"{key}{sep}{inner_key}" if inner_key else key: inner_value
        for key, value in config.items()
        for inner_key, inner_value in (flatten(value, sep).items() if isinstance(value, dict) else [("", value)])
    }

Each item either is a leaf, represented as one pair with an empty inner key, or a nested dict, whose already-flattened pairs are walked by the second for clause and prefixed with the outer key. The recursion ends at leaves, and an empty nested dict produces no pairs at all, so it disappears. The conditional expression in the key position decides between key and key.inner_key. Iteration order follows the original dict, so the flat keys stay in a readable order. This is compact, and near the limit of what a comprehension should hold; a written generator function (6.3) is the more readable version for a team. Trackers like MLflow and Weights & Biases flatten configs this way to make them searchable.

14. A confusion matrix as a nested dict

Write confusion(y_true, y_pred) returning (matrix, recall). matrix[actual][predicted] is the count of each pair, with every class (from both lists, sorted) present in both levels, including zeros. recall[c] is the diagonal count divided by the row total, rounded to 3 decimals, or 0.0 for a class with no true examples. Hint 1Open a hint

Count pairs once with Counter(zip(y_true, y_pred)), then look counts up in a nested comprehension.

Hint 2Open a hint

The row total is sum(matrix[c].values()).

SolutionShow the solution and why
solution.py
from collections import Counter

def confusion(y_true, y_pred):
    if len(y_true) != len(y_pred):
        raise ValueError("y_true and y_pred must have the same length")
    classes = sorted(set(y_true) | set(y_pred))
    pairs = Counter(zip(y_true, y_pred))
    matrix = {a: {p: pairs[(a, p)] for p in classes} for a in classes}
    recall = {
        c: round(matrix[c][c] / total, 3) if (total := sum(matrix[c].values())) else 0.0
        for c in classes
    }
    return matrix, recall

Counting happens once, in O(n), and the nested comprehension only looks up counts, O(k^2) for k classes, which is small. A Counter returns 0 for a pair that never occurred, so every cell exists. Taking classes from both lists matters: phish was only ever predicted, and a matrix built from y_true alone would hide that the model invents a class. The walrus computes each row total once for both the test and the division. The length check runs first because zip would otherwise silently drop the extra items (4.1). This is sklearn.metrics.confusion_matrix with labels=, returned as named rows instead of a bare array.

Hint 1Open a hint

{r["model"]: r for r in runs} keeps the last run per model, not the best.

Hint 2Open a hint

SolutionShow the solution and why
solution.py
def summarize(runs):
    f1s = {}
    for r in runs:
        f1s.setdefault(r["model"], []).append(r["f1"])
    return [
        (m, max(scores), round(sum(scores) / len(scores), 3), len(scores))
        for m, scores in sorted(f1s.items())
    ]

Three bugs, each a rule from this lesson. The dict comprehension best assigns every run under its model, so the last run wins, which happens to be the best only sometimes. dict.fromkeys(models, []) puts one shared list under every model, so all means were the mean of all runs. And for m in models iterates a set of strings, whose order depends on hash randomisation and changes between processes, so the report order was not stable. The fix groups once (here with setdefault, equivalent to a defaultdict), takes max of each group instead of relying on order, and iterates sorted(f1s.items()). Once the runs are grouped, the best, the mean and the count all come from the same list, so they cannot disagree.

Interview

17. What happens with duplicate keys in a dict comprehension, and how do you invert a dict safely?

SolutionModel answer

A dict comprehension assigns d[key] = value for every item, so a repeated key is overwritten: the last value wins, and the key keeps the position of its first insertion. There is no error, so data loss is silent. Inverting {k: v} with {v: k for k, v in d.items()} is only safe when the values are unique and hashable; you can check with len(set(d.values())) == len(d), or assert it. If values can repeat, inversion is grouping: one pass with a defaultdict(list) gives {v: [keys]}. If values are unhashable (lists, dicts), they cannot be keys at all, and you need to convert them (for example to tuples) or rethink the structure.

Interview

18. When should you use a set comprehension instead of a list comprehension, and why can a set's order change between runs?

SolutionModel answer

Use a set comprehension when you need distinct values or fast membership tests and do not care about order or count: unique domains, vocabulary candidates, ids already seen. Use a list when order, duplicates or positions matter. A set stores elements by hash in a table, so iteration order follows hash values and table layout, not insertion. For strings and bytes, Python randomises the hash function per process (to defend against attacks that force hash collisions), so the order of a set of strings can differ every time the program runs; PYTHONHASHSEED can fix it, but the robust answer is to sort before anything order-dependent: numbering, saving, printing, comparing outputs in tests.

19. How would you make label ids and vocabularies reproducible between training and serving?

SolutionModel answer

Build them deterministically and then treat them as part of the model. Deterministically means from a sorted list of unique values ({label: i for i, label in enumerate(sorted(set(labels)))}), with special tokens (<pad>, <unk>) at fixed positions, and filters such as a minimum count applied in a fixed order, never from a set's iteration order. Part of the model means saving them with the weights (Hugging Face stores label2id and id2label in config.json, tokenizers in their own files), versioning them together, and loading them at serving time instead of rebuilding them from new data, which would renumber classes and silently scramble predictions. At serving time, map unknown values to <unk> or an "other" class, log how often that happens, and add a test that loads the saved maps and checks a few known ids.

Recap

  • {k: v for ...} assigns for every item: a repeated key keeps its first position and takes the last value, silently.
  • {x for ...} builds a set: distinct by equality and hash, no order. Sort before numbering, saving or printing. {} is an empty dict.
  • Comprehensions transform and filter; grouping and counting accumulate, so use defaultdict or Counter, then summarise with a comprehension.
  • dict.fromkeys(keys, []) shares one list; {k: [] for k in keys} does not. Test is None when 0 or False are valid values.
  • Label maps and vocabularies: built from sorted unique values, saved with the model, loaded at serving time.
