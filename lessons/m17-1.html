D.1 NumPy for ML: arrays, broadcasting and vectorisation

Every ML library sits on NumPy arrays: feature matrices, embeddings, predictions and metrics are all arrays. What an array is and why it is fast, dtypes and shapes, views versus copies, broadcasting, reductions along an axis, and the vectorised patterns behind softmax, cosine search, distances and pooling.

1What an array is, and why it is fast

A Python list of numbers is a list of pointers: each element is a separate Python object somewhere in memory, with its own type and reference count, so sum(xs) follows a pointer and checks a type for every element. A NumPy array stores the raw numbers next to each other in one block of memory, all of the same dtype (float64, int32, bool...), plus a shape such as (1000, 768): a thousand rows of 768 numbers, the usual layout for a batch of embeddings. Because the layout is known, an operation like a * 2 runs one tight loop in compiled C over the block, with no per-element Python work. That is the whole reason NumPy, pandas, scikit-learn and PyTorch exist in their current form.

Think of it like the difference between a SQL table with a declared column type and a column of sql_variant: once every value has the same type and width, the engine can scan it at full speed. The price is the same as in SQL: one dtype per array. Mixing ints and floats gives floats, mixing numbers and strings gives an array of strings, and fixed-size integers wrap around silently on overflow instead of growing like Python ints.

2Indexing: views, copies and masks

Basic indexing (integers and slices, a[1:3], m[:, 0]) returns a view: a new array object that points into the same memory. Writing to the view writes to the original. reshape and .T are views too, whenever the memory layout allows it. Advanced indexing, with a boolean mask (a[a > 0]) or an integer list (a[[0, 2]]), returns a copy, because the selected elements are not evenly spaced in memory. np.shares_memory(x, y) tells you which case you are in, and .copy() makes an independent array when you need one.

views.py
import numpy as np

a = np.arange(4)
v = a[1:3]
c = a[[1, 2]]
v[0] = 99
c[1] = -1
print(a, v, c)
print(np.shares_memory(a, v), np.shares_memory(a, c))
m = np.arange(6).reshape(2, 3)
print(m)
print(m[:, 1], m[1], m[m % 2 == 0])
m[m > 3] = 0
print(m)
print(np.shares_memory(m, m.T), np.shares_memory(m, m.reshape(3, 2)))

Masks are NumPy's WHERE clause: scores[labels == 1] keeps the scores of positive examples, and x[x > 3] = 0 updates in place, like an UPDATE ... WHERE. Combine conditions with &, | and ~ (not and/or/not, which try to turn the whole array into one bool and raise), and put each comparison in parentheses because & binds tighter than >. A function that receives an array and slices it can modify the caller's data through the view, which is the NumPy version of the shared-list bugs in Module 2; copy before modifying, or document that the function works in place.

3Broadcasting

Broadcasting is how NumPy combines arrays of different shapes without copying. Line the shapes up from the right; two dimensions are compatible if they are equal or one of them is 1, and a size-1 dimension is stretched to match. Missing dimensions on the left count as 1. So a (1000, 768) embedding matrix minus a (768,) mean vector subtracts the mean from every row, and a (3, 1) column plus a (1, 4) row gives a (3, 4) grid: every pair, which is the trick behind pairwise distances. If no rule applies, NumPy raises ValueError: operands could not be broadcast together.

broadcast.py
import numpy as np

X = np.array([[1.0, 10.0], [3.0, 30.0], [5.0, 50.0]])
mu = X.mean(axis=0)
print(mu.shape, X - mu)
row_norm = np.linalg.norm(X, axis=1, keepdims=True)
print(row_norm.shape, (X / row_norm).round(3))
y = np.array([1.0, 2.0, 3.0])
pred = np.array([[1.5], [2.0], [2.0]])

The middle lines show the trap that costs ML engineers whole afternoons: y has shape (3,) and pred has shape (3, 1) (a column, as many models return), so y - pred broadcasts to (3, 3), every target minus every prediction, and the "mean squared error" is a wrong number with no error raised. Flatten with .ravel() or reshape(-1), or assert shapes before computing a metric. keepdims=True is the opposite habit: it keeps a reduced axis as size 1, so the result (3, 1) broadcasts back over the rows it came from.

4Reductions along an axis

sum, mean, std, max, argmax and friends take an axis: the dimension that is collapsed. For a (rows, columns) matrix, axis=0 collapses the rows and gives one value per column (like SELECT AVG(col1), AVG(col2) FROM t), and axis=1 collapses the columns, one value per row (like a calculated column in Power BI that averages across a row). With no axis, the whole array becomes one number. argmax(axis=1) on a (batch, classes) matrix of scores is how a classifier's predicted class is read off; argsort sorts indices; argpartition(-scores, k)[:k] finds the top k without sorting everything, which matters when searching a million embeddings.

axis.py
import numpy as np

scores = np.array([[0.1, 0.7, 0.2],
                   [0.5, 0.3, 0.2],
                   [0.2, 0.2, 0.6]])
print(scores.sum(axis=1), scores.mean(axis=0).round(3))
print(scores.argmax(axis=1), scores.max(axis=1))
sims = np.array([0.12, 0.91, 0.45, 0.88, 0.05, 0.67])
top = np.argpartition(-sims, 3)[:3]
print(sorted(top.tolist()), top[np.argsort(-sims[top])])
v = np.array([1.0, np.nan, 3.0])
print(v.mean(), np.nanmean(v), np.isnan(v).sum())

[1. 1. 1.] [0.267 0.4   0.333]
[1 0 2] [0.7 0.5 0.6]
[1, 3, 5] [1 3 5]
nan 2.0 1

Two details. argpartition only guarantees that the first k positions hold the k largest (in any order), so sort those k afterwards if order matters: O(n + k log k) instead of O(n log n). And a single NaN poisons mean, sum and max; the nan* functions skip them, but in a pipeline it is usually better to find out why there is a NaN (a division by zero, a missing feature) than to skip it silently.

5Vectorised building blocks for ML

Vectorising means expressing a computation as whole-array operations so the loop runs in C. Element-wise math (np.exp, np.log, np.sqrt, +, *) is done by ufuncs; np.where(cond, a, b) is a vectorised if/else (Power BI's IF on a whole column); matrix products use @. Most ML formulas are written this way, and three of them appear in every GenAI codebase.

Softmax turns scores into probabilities: exp(z) / sum(exp(z)). Computed literally, exp(1000) overflows to inf and the result is nan, so real code subtracts the row maximum first, which changes nothing mathematically and keeps every exponent at or below 0. Cosine similarity between embeddings is the dot product of unit vectors: normalise each row once (E / norm(E, axis=1, keepdims=True)), then one matrix product Q @ E.T gives every query-document similarity. Masked mean pooling averages token embeddings (batch, tokens, dim) while ignoring padding: multiply by the mask with an added axis, sum over tokens, divide by the number of real tokens.

vectorised.py
import numpy as np

def softmax(z, axis=-1):
    z = z - z.max(axis=axis, keepdims=True)
    e = np.exp(z)
    return e / e.sum(axis=axis, keepdims=True)

z = np.array([[1000.0, 1001.0, 1002.0], [1.0, 2.0, 3.0]])
with np.errstate(over="ignore", invalid="ignore"):
    naive = np.exp(z) / np.exp(z).sum(axis=1, keepdims=True)
print(naive.round(4))
print(softmax(z).round(4), softmax(z).sum(axis=1))

E = np.array([[3.0, 4.0], [1.0, 0.0], [0.0, 2.0]])
E_unit = E / np.linalg.norm(E, axis=1, keepdims=True)
q = np.array([[0.6, 0.8]])
print((q @ E_unit.T).round(3))

pooled = (tokens * mask[..., None]).sum(axis=1) / mask.sum(axis=1, keepdims=True)

print(np.where(np.array([0.2, 0.7, 0.5]) >= 0.5, "spam", "ham"))
rng = np.random.default_rng(0)
print(rng.integers(0, 10, 5), rng.normal(size=2).round(3))

solution.py
import numpy as np


def normalise(E, eps=1e-12):
    E = np.asarray(E, dtype=np.float64)
    norms = np.linalg.norm(E, axis=1, keepdims=True)
    return E / np.maximum(norms, eps)

axis=1 computes one norm per row, and keepdims=True keeps it as a (n, 1) column so the division broadcasts across the row's d values. Without keepdims, a (n,) vector would be lined up with the columns instead, which only happens to work when n == d and is wrong even then. np.maximum with a tiny eps keeps zero rows at zero instead of producing 0 / 0 = nan, which would otherwise poison every similarity score computed later. np.asarray(..., dtype=float64) converts integer input and creates a new array, so the caller's data is never modified.

solution.py
import numpy as np


def minmax(X):
    X = np.asarray(X, dtype=float)
    lo = X.min(axis=0)
    rng = X.max(axis=0) - lo
    return (X - lo) / np.where(rng == 0, 1.0, rng)

Without an axis, min and max look at the whole matrix, so every column is scaled by the global range (1 to 30) and only the widest column reaches 1. axis=0 collapses the rows and leaves one statistic per column, shape (3,), which broadcasts against (3, 3) row by row. For a constant column the range is 0; dividing by 1 there leaves x - min = 0, the conventional output, instead of 0 / 0. In a real pipeline the min and max are learned on the training split only and reused on the test split, which is exactly what scikit-learn's MinMaxScaler does in D.6.

solution.py
import numpy as np


def mse(y_true, y_pred):
    y_true = np.asarray(y_true, dtype=float).reshape(-1)
    y_pred = np.asarray(y_pred, dtype=float).reshape(-1)
    if y_true.shape != y_pred.shape:
        raise ValueError(f"shapes differ: {y_true.shape} vs {y_pred.shape}")

(3,) minus (3, 1) broadcasts to (3, 3): every target minus every prediction. Its mean is a real number, so nothing fails, and a model can be "selected" on a metric that measures nothing. Flattening both inputs makes the subtraction element by element, and checking the shapes afterwards turns a length mismatch into a clear error instead of another broadcast. scikit-learn's metrics do the same validation, which is one reason to use them in D.6.

import numpy as np


def softmax(z, axis=-1):
    z = np.asarray(z, dtype=float)
    z = z - z.max(axis=axis, keepdims=True)
    e = np.exp(z)
    return e / e.sum(axis=axis, keepdims=True)


def log_softmax(z, axis=-1):
    z = np.asarray(z, dtype=float)
    z = z - z.max(axis=axis, keepdims=True)
    return z - np.log(np.exp(z).sum(axis=axis, keepdims=True))

Softmax does not change if you subtract the same constant from every score in a row, because the constant cancels between numerator and denominator. Subtracting the row maximum makes the largest exponent exp(0) = 1, so nothing overflows, and rows [1000, 1001, 1002] and [1, 2, 3] give identical probabilities, as they should. The starter also summed over the whole array, so rows did not sum to 1 individually. log_softmax is the log-sum-exp trick: log(exp(-1000) / ...) underflows to log(0), but -1000 - log(1 + exp(-1000)) is finite. Cross-entropy losses in every framework are built from this, never from log(softmax(z)).

SolutionShow the solution and why
solution.py
import numpy as np


def search(query, E, k):
    E = np.asarray(E, dtype=float)
    q = np.asarray(query, dtype=float)
    En = E / np.maximum(np.linalg.norm(E, axis=1, keepdims=True), 1e-12)
    qn = q / max(np.linalg.norm(q), 1e-12)
    sims = np.round(En @ qn, 4)
    n = len(sims)
    if k >= n:
        idx = np.arange(n)
    else:
        cut = sims[np.argpartition(-sims, k - 1)[:k]].min()
        idx = np.flatnonzero(sims >= cut)
    order = sorted(idx.tolist(), key=lambda i: (-sims[i], i))[:k]
    return [(i, float(sims[i])) for i in order]

The starter used raw dot products, so long vectors win: [10, 10] scores 20 against [2, 2]'s 4, although they point in exactly the same direction. Cosine similarity divides out the lengths, which is why both score 1.0 and the index breaks the tie. argpartition(-sims, k - 1) places the k largest similarities in the first k slots in O(n), but when several documents tie with the k-th score it keeps an arbitrary one of them: here documents 0 and 2 both score 0.7071 for the third place. So the solution uses the partition only to find the cut-off score, keeps every document at or above it (a handful), and sorts those by (-score, index). Rounding before ranking makes ties exact, so the tie rule is applied to scores that print the same. This is what a vector database does in miniature; with a million documents it replaces a million-element sort with a linear pass.

import numpy as np


def one_hot(labels, n_classes):
    labels = np.asarray(labels)
    if labels.size and (labels.min() < 0 or labels.max() >= n_classes):
        raise ValueError("label out of range")
    Y = np.zeros((labels.size, n_classes))
    Y[np.arange(labels.size), labels] = 1.0
    return Y


def from_one_hot(Y):
    return np.asarray(Y).argmax(axis=1)

Y[:, labels] = 1 selects whole columns: every row gets a 1 in every column that appears anywhere in labels. Pairing two index arrays, Y[np.arange(n), labels], selects one cell per row: (0, 2), (1, 0), (2, 1), (3, 2). Negative labels would silently index from the end (-1 is the last class), which is why the range check comes first. max(axis=1) returns the value 1, not where it is; argmax returns the position, which is the label. The same argmax(axis=1) turns a classifier's probability matrix into predictions.

solution.py
import numpy as np


def pairwise_sq(A, B):
    A = np.asarray(A, dtype=float)
    B = np.asarray(B, dtype=float)
    aa = (A ** 2).sum(axis=1)[:, None]
    bb = (B ** 2).sum(axis=1)[None, :]
    return np.maximum(aa + bb - 2 * A @ B.T, 0.0)


def knn_predict(A_train, y_train, A_test, k):
    D = pairwise_sq(A_test, A_train)
    nearest = np.argsort(D, axis=1, kind="stable")[:, :k]
    votes = np.asarray(y_train)[nearest]
    return np.array([np.bincount(row).argmax() for row in votes])

The starter is correct but builds an (n, m, d) array: for 10,000 test rows, 100,000 training rows and 768 dimensions that is 768 billion numbers, far more memory than any machine has. The expansion needs only the (n, m) result: squared norms as a column and a row, broadcast together, minus twice the matrix product, which runs in optimised BLAS code. Floating-point cancellation can leave values like -1e-15 for identical points, hence the clip. For the vote, argsort along axis=1 ranks the neighbours of every test row at once, fancy indexing y_train[nearest] looks up their labels as a (n_test, k) array, and bincount(...).argmax() returns the first (smallest) label among the most common, which is the tie rule. In the second test the two nearest points are one of each class, so the tie goes to 0.

Hint 2Open a hint

For the max, replace padding with -np.inf using np.where, take the max, then turn rows that stayed -inf into 0.

SolutionShow the solution and why
solution.py
import numpy as np


def mean_pool(H, mask):
    m = np.asarray(mask, dtype=float)[..., None]
    summed = (H * m).sum(axis=1)
    counts = m.sum(axis=1)
    return summed / np.maximum(counts, 1.0)


def max_pool(H, mask):
    m = np.asarray(mask, dtype=bool)[..., None]
    masked = np.where(m, H, -np.inf)
    out = masked.max(axis=1)
    return np.where(np.isinf(out), 0.0, out)

Padding tokens exist only to make sentences the same length, so including them drags every short sentence's embedding towards whatever the padding vectors happen to be (here 100). Adding an axis to the mask, (batch, tokens, 1), lets it broadcast over the embedding dimension, so multiplying zeroes the padding, and dividing by the count of real tokens gives the true mean. Clamping the count at 1 turns an empty sentence into 0 / 1. For max pooling, multiplying by 0 is not enough (a 0 could beat negative real values), so padding is replaced with -inf, which can never win; a row with no real tokens stays -inf and is set to 0. np.where builds new arrays, so H is untouched. This is exactly how sentence-transformers pools BERT outputs.

SolutionShow the solution and why
solution.py
import numpy as np


def confusion(y_true, y_pred, n_classes):
    idx = np.asarray(y_true) * n_classes + np.asarray(y_pred)
    return np.bincount(idx, minlength=n_classes * n_classes).reshape(n_classes, n_classes)


def _safe_div(a, b):
    a = a.astype(float)
    return np.divide(a, b, out=np.zeros_like(a), where=b > 0)


def per_class_recall(C):
    return _safe_div(np.diag(C), C.sum(axis=1))


def per_class_precision(C):
    return _safe_div(np.diag(C), C.sum(axis=0))

Buffered fancy assignment is the trap: C[y_true, y_pred] += 1 reads all the cells, adds 1, and writes them back, so a pair that occurs twice is still counted once. Encoding each (true, pred) pair as one integer true * n + pred and counting with bincount handles repeats, and minlength guarantees all n * n cells exist before reshaping. (np.add.at(C, (y_true, y_pred), 1) is the unbuffered alternative.) The starter also swapped the axes: recall asks "of the true class-i examples, how many were found", which is row i, so it divides by row sums; precision divides by column sums. np.divide with where= skips empty classes instead of dividing by zero, and the last test turns any division warning into an error to prove it.

At 2^24, adjacent float32 values are 2 apart, so adding 1 rounds back to the same number, while float64 still has room. Summing ten million float32 values of 0.1 gives 1000000.1 in float32 and 1000000.0 in float64. 15. What is the difference between a view and a copy in NumPy, and when does each happen?

SolutionModel answer

A view is a new array object that shares memory with another array; a copy owns its own memory. Basic indexing with integers and slices (a[2:5], m[:, 0], a[::2]), reshape when the layout allows, .T and ravel when possible all return views, because the selected elements can be described as the same buffer with different offsets and strides. Advanced indexing, with boolean masks or integer arrays, returns copies, because the chosen elements are scattered. Arithmetic always produces new arrays. Consequences: writing to a view changes the original (a feature for in-place updates of big data, a bug when a helper modifies its caller's training set), and a small view keeps a huge base array alive in memory. Check with np.shares_memory or arr.base, and call .copy() when you need independence. pandas has the same question, which pandas 3 answers with Copy-on-Write (D.2).

Interview

16. Explain broadcasting, and describe a bug it can cause.

SolutionModel answer

Broadcasting lets NumPy combine arrays of different shapes without copying data. Shapes are compared from the right; each pair of dimensions must be equal or contain a 1, and missing leading dimensions count as 1; size-1 dimensions are stretched virtually. So (n, d) - (d,) centres every row, (n, d) / (n, 1) scales each row by its own value, and (n, 1) + (1, m) builds an (n, m) grid, the basis of pairwise distances and attention scores. The classic bug is (n,) combined with (n, 1): it broadcasts to (n, n) instead of failing, so y_true - y_pred with a column of predictions computes every target minus every prediction, and an MSE or accuracy is silently wrong. Defences: flatten predictions, use keepdims=True for reductions you will broadcast back, assert shapes at function boundaries, and prefer library metrics that validate inputs.

Interview

17. Why is vectorised NumPy code so much faster than a Python loop, and when is it not the answer?

SolutionModel answer

A Python loop executes bytecode for every element: it fetches an object, checks its type, dispatches the operation, allocates a result object and updates reference counts. A vectorised NumPy call checks types once and runs a compiled loop over a contiguous block of a single dtype, often using SIMD instructions, and matrix products go to optimised BLAS libraries that use cache blocking and several cores. That is typically 10 to 100 times faster, and more for matrix work. It is not always the answer: vectorising can create huge temporary arrays (the (n, m, d) distance cube), so you may need chunking or a smarter formula; computations where each step depends on the previous (a recurrence, an early-exit search) do not vectorise naturally and are better served by Numba, Cython, or a library function that already implements them; and for tiny arrays the per-call overhead of NumPy can exceed a plain loop. Measure, as Module 16 said, and remember that clarity matters: np.where chains five deep are harder to review than a loop.

Recap

  • An ndarray is one block of memory with one dtype and a shape; operations run as compiled loops. Fixed-size ints wrap on overflow; float32 keeps about 7 digits.
  • Slices and reshapes are views (writes reach the original); masks and integer-array indexing make copies. Check with np.shares_memory, copy with .copy().
  • Broadcasting matches shapes from the right and stretches size-1 dimensions; (n,) with (n, 1) silently gives (n, n), so flatten or assert shapes.
  • axis is the dimension that is collapsed: axis=0 gives one value per column, axis=1 one per row; keepdims=True keeps it ready to broadcast back.
  • Vectorised ML blocks: stable softmax (subtract the max), cosine search (normalise once, one matrix product, argpartition), masked pooling, bincount.
