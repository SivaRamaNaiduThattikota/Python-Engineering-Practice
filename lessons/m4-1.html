4.1 Lists: indexing, slicing and methods

How a list is stored and why that makes some operations instant and others slow, the exact rules for indexes and slices (including the xs[-0:] trap), slice assignment, which methods change the list, and when a list is the wrong tool.

19 problems4 easy · 10 medium · 5 hard

1What a list is in memory

In CPython, a list is a dynamic array of references: the list object stores its length, how much room it has, and a pointer to one contiguous block of slots. Each slot holds a reference to an item stored somewhere else (2.1), which is why one list can hold a string, a float and a dict side by side, and why copying a list copies the references, not the items (2.3).

Every performance rule of lists follows from that picture:

  • xs[i] is O(1). The slot's address is "start + i times slot size", one calculation whatever the length.
  • append is amortized O(1). There is usually spare room at the end, so appending just fills the next slot. When the room runs out, Python allocates a bigger block (with extra room to spare) and moves the references over. That resize is O(n), but it happens rarely enough that the average cost per append stays constant.
  • insert(0, x) and pop(0) are O(n). Every other reference has to shift one slot to make or close the gap.
  • x in xs, xs.index(x), xs.remove(x) are O(n). Nothing tells Python where a value is, so it checks slots one by one (2.1: identity first, then equality).
growth.py
import sys

xs = []
sizes = []
for i in range(12):
    xs.append(i)
    sizes.append(sys.getsizeof(xs))
print(sizes)                    # the size only jumps now and then: spare room in action
print(len(xs), xs[7], xs[-1])
Output
[44, 44, 44, 44, 60, 60, 60, 60, 92, 92, 92, 92]
12 7 11

The exact byte numbers depend on the Python version and platform, so do not memorise them. What matters is the pattern: the size stays flat for several appends, then jumps. Each jump is one resize, and between jumps an append only fills a spare slot.

2Indexing, step by step

Valid indexes for a list of length n run from 0 to n - 1. A negative index counts from the end: Python converts xs[-k] to xs[n - k], so -1 is the last item and -n the first. Anything outside -n .. n - 1 raises IndexError.

3Slicing rules

xs[start:stop:step] builds a new list (a shallow copy, 2.3) with the items from start up to but not including stop, taking every step-th one. Each part is optional, and the rules for filling them in are what you need to predict any slice:

  • With a positive step (default 1): a missing start means 0, a missing stop means "to the end".
  • With a negative step: the slice walks backwards, a missing start means "the last item" and a missing stop means "past the beginning". xs[::-1] is a reversed copy.
  • Negative start and stop count from the end, exactly like indexes.
  • Out-of-range bounds are clamped, never an error: xs[2:100] on a 5-item list gives the last three items, and xs[10:20] gives [].
  • If start is already at or past stop in the direction of travel, the slice is empty.
slicing.py
t = ["a", "b", "c", "d", "e", "f"]
print(t[1:4], t[:2], t[4:], t[-2:])
print(t[::2], t[1::2], t[::-1], t[4:1:-1])
print(t[2:100], t[10:20], t[4:2])

The -0 trap. "The last n items" is usually written xs[-n:]. It works for every n from 1 up, but for n = 0 the start is -0, which is just 0, so xs[-0:] is xs[0:]: the whole list, the opposite of what you meant. Code that trims chat history or keeps "the last k scores" hits this whenever k can be 0. Write xs[len(xs) - n:] or guard n == 0 explicitly.

4Slice assignment and del

On the left of =, a slice means "replace this part of the list in place". The right side can be any iterable, and the list grows or shrinks to fit, so slice assignment can insert, replace or delete. del xs[a:b] removes a range in place. With a step other than 1 ("extended slices"), the right side must have exactly as many items as the slice selects.

slice_assignment.py
xs = [0, 1, 2, 3, 4]
xs[1:3] = ["a", "b", "c"]      # replace two items with three: the list grows
print(xs)
xs[:0] = ["start"]             # an empty slice at the front: insert
print(xs)
del xs[-2:]                    # remove the last two
print(xs)
xs[::2] = [None] * len(xs[::2])  # extended slice: lengths must match
print(xs)
try:
    xs[::2] = [1]
except ValueError as e:
    print("ValueError:", e)
Output
[0, 'a', 'b', 'c', 3, 4]
['start', 0, 'a', 'b', 'c', 3, 4]
['start', 0, 'a', 'b', 'c']
[None, 0, None, 'b', None]
ValueError: attempt to assign sequence of size 1 to extended slice of size 3

xs[:] = new_items replaces the whole contents while keeping the same list object, which is how you change a list in place for every alias (2.2, normalise_inplace). By contrast, xs = xs[2:] builds a new list and moves only the local name: callers holding the old list see no change (problem 14).

When a list is the wrong tool

Use collections.deque when you add or remove at the front (a queue, a breadth-first search) or need a fixed-size window (deque(maxlen=20) keeps the last 20 chat turns and drops older ones automatically). Use a set or dict when you mostly ask "is x in here?" (4.4, 4.5). Use a numpy array for large numeric data, where whole-array operations run in C (2.2).

def collect_chunks(docs, chunker):

solution.py
def last_turns(history, n):
    has_system = bool(history) and history[0]["role"] == "system"
    head = history[:1] if has_system else []
    rest = history[1:] if has_system else history

rest[-n:] would return everything for n = 0, exactly the opposite of "no turns". Building the result with + returns a new list and leaves the caller's history alone (2.4).

Write windows(xs, size, step=1) that returns the list of slices xs[i:i + size] for every start i that gives a full window, moving step positions each time. Used to build training examples from a time series. Raise ValueError if size or step is less than 1.

HintOpen a hint

SolutionShow the solution and why
solution.py
def windows(xs, size, step=1):
    if size < 1 or step < 1:
        raise ValueError("size and step must be at least 1")
    return [xs[i:i + size] for i in range(0, len(xs) - size + 1, step)]

The range of starts does the "full windows only" work: if size > len(xs), the stop of the range is 0 or negative, so it is empty and no window is produced, without any special case. Each window is a new list (a slice), so changing one cannot affect the series or the other windows. With numpy, np.lib.stride_tricks.sliding_window_view produces the same windows as views without copying, which is much faster for long series but shares memory (2.2).

solution.py
def drop_rows(rows, bad_positions):
    bad = set(bad_positions)
    rows[:] = [r for i, r in enumerate(rows) if i not in bad]

Each del shifts every later row one position to the left, so the next position points at a different row than intended, and a position near the end can be past the new end (IndexError). The set makes each membership check O(1) (4.4).

SolutionShow the solution and why
solution.py
def fit_budget(messages, budget, count=len):
    has_system = bool(messages) and messages[0]["role"] == "system"
    head = messages[:1] if has_system else []
    rest = messages[1:] if has_system else messages
    used = sum(count(m["content"]) for m in head)
    kept = []
    for m in reversed(rest):
        cost = count(m["content"])
        if used + cost > budget:
            break
        kept.append(m)
        used += cost
    kept.reverse()
    return head + kept

Walking backwards with reversed(rest) (a lazy iterator, no copy) visits the newest messages first, and break stops at the first one that does not fit, so the kept turns are always a contiguous recent window: skipping ahead to an older small message would put a reply in context without the question it answers. Appending then reversing once is O(n); inserting at position 0 for each message would be O(n²). count is a parameter (3.5), so the same function works with a real tokenizer, such as lambda t: len(enc.encode(t)) with tiktoken.

def add(window, message, max_turns):
    """Append a message, then drop the oldest so at most max_turns remain."""
    window.append(message)
    if len(window) > max_turns:

    return "\n".join(f"{m['role']}: {m['content']}" for m in recent(window, n))

Bug one is rebinding instead of changing (2.2, 2.4): window = window[-max_turns:] makes a trimmed copy and points the local name at it, while the caller's list keeps every message. del window[:k] removes the oldest k items from the caller's own list. Bug two is the -0 trap: window[-0:] is the whole window. In production you would use collections.deque(maxlen=max_turns), which drops the oldest item automatically on each append, in O(1).

Write rotate(xs, k) that rotates xs to the right by k positions in place (the same list object) and returns None. k may be larger than the length or negative (negative rotates left). An empty list stays empty.

Hint 1Open a hint

Rotating by k and by k % len(xs) give the same result, and Python's % already turns a negative k into the right positive amount (1.1).

Hint 2Open a hint

The rotated list is xs[-k:] + xs[:-k]. Put it back with slice assignment, and beware k == 0 (the -0 trap again).

SolutionShow the solution and why
solution.py
def rotate(xs, k):
    if not xs:
        return None
    k %= len(xs)
    xs[:] = xs[len(xs) - k:] + xs[:len(xs) - k]

k % len(xs) reduces any rotation to 0 .. n - 1, and because Python's modulo takes the sign of the divisor, -1 % 4 is 3: rotating left by one is rotating right by three. Using len(xs) - k as the split point instead of -k avoids the -0 trap when k becomes 0. Slice assignment keeps the same list object. This uses O(n) extra memory for the temporary slices; the classic interview follow-up is the O(1)-memory version, which reverses the whole list and then reverses each part. collections.deque.rotate(k) does it for deques.

16. Merge two sorted lists

Write merge_sorted(a, b) that returns one sorted list from two already-sorted lists in O(len(a) + len(b)) time, without calling sort or sorted. Equal items from a come before those from b. Used to combine ranked results from two retrievers that are already in score order.

TestsThe 4 checks Run tests uses
assert merge_sorted([1, 4, 9], [2, 3, 10, 11]) == [1, 2, 3, 4, 9, 10, 11]
assert merge_sorted([], [1, 2]) == [1, 2] and merge_sorted([3], []) == [3]
left = [(1, "a"), (2, "a")]
right = [(1, "b")]
assert merge_sorted([x[0] for x in left], [x[0] for x in right]) == [1, 1, 2]
big = merge_sorted(list(range(0, 2000, 2)), list(range(1, 2000, 2)))
assert big == list(range(2000))
Hint 1Open a hint

Two positions i and j. While both lists have items left, append the smaller current item and advance that position.

Hint 2Open a hint

When one list runs out, the rest of the other is already sorted: add it with a slice and extend.

SolutionShow the solution and why
solution.py
def merge_sorted(a, b):
    out = []
    i = j = 0
    while i < len(a) and j < len(b):
        if b[j] < a[i]:
            out.append(b[j])
            j += 1
        else:
            out.append(a[i])
            i += 1
    out.extend(a[i:])
    out.extend(b[j:])
    return out

Each comparison moves one position forward, so the loop runs at most len(a) + len(b) times: O(n + m), better than concatenating and sorting (O((n + m) log(n + m))). Taking from a unless b's item is strictly smaller keeps the merge stable: equal items from a come first. Extending with the two leftover slices handles the tail in one step, since only one of them is non-empty. This "two pointers" pattern is the merge step of merge sort, heapq.merge does it lazily for many lists, and it is how hybrid search combines ranked lists before rank fusion (Module 16).

17. Why is list.append O(1) but list.insert(0, x) O(n)?

SolutionModel answer

A CPython list is a dynamic array of references with spare capacity at the end. append writes into the next free slot, which is O(1); when the capacity runs out, the list allocates a larger block (growing by a fraction of its size) and copies the references, which is O(n) but rare enough that the cost averages out to O(1) per append (amortized). insert(0, x) must shift every existing reference one slot to the right to open the gap, so it is O(n) every time, and pop(0) shifts them back. For fast operations at both ends, use collections.deque. Follow-ups worth mentioning: indexing is O(1) because slots are contiguous, and x in list is O(n) because there is no index of values.

18. Why does xs[-n:] break for n = 0, and how do you write "the last n items" safely?

SolutionModel answer

Because -0 equals 0, so xs[-0:] means xs[0:], the whole list, while "the last 0 items" should be empty. It only fails for exactly that value, so it slips through tests that use n >= 1. Safe forms: xs[len(xs) - n:] (with max(0, ...) if n can exceed the length), or xs[-n:] if n else [], or for a rolling window a deque(maxlen=n). Mention where it bites in practice: trimming chat history, "keep the last k checkpoints", or taking the last k scores for early stopping.

Interview

19. When do you use a Python list, and when a numpy array, for numeric data?

SolutionModel answer

A list stores references to separate Python objects, can mix types, grows cheaply with append, and is ideal for building up results, small data, or heterogeneous records. A numpy array stores raw numbers of one dtype in one block, so it uses far less memory and runs whole-array operations (arr * 2, arr.mean(), matrix products) in compiled code, often 10 to 100 times faster than Python loops. But arrays have a fixed size (appending copies the whole array), and basic slices are views that share memory, while list slices are copies. A common pattern: collect in a list, then convert once with np.array(values). Mention that object-dtype arrays lose most of the benefit, and that pandas is built on the same array model.

Recap

  • A list is a dynamic array of references: indexing and append are O(1); insert(0), pop(0), in, remove and index are O(n).
  • Negative indexes count from the end. Slices never raise: they clamp. stop is never included.
  • xs[-n:] is the whole list when n == 0. Use xs[len(xs) - n:] or guard zero.
  • Slice assignment and del change the list in place and can grow or shrink it. xs = xs[...] only moves your local name.
  • append adds one item; extend adds each item. Use deque for queues and windows, sets and dicts for membership, numpy for big numbers.
