Mixed problems from all of Module 12: paths and files, CSV, JSON and JSON Lines, logging, and configuration. 1How to use this page

Every file-handling task raises the same four questions. Where is it? Build paths with pathlib, find files with explicit filters, and never trust that a folder exists (12.1). What format, and what types? CSV gives strings, JSON loses some types, JSONL streams, and every reader must decide what a bad record means (12.2). What happens if it fails halfway? Write atomically, log the failure with its traceback once, and keep going or stop deliberately (12.1, 12.3). Who decides the settings? Defaults, a file and the environment, parsed strictly at start-up, with secrets kept out of code and logs (12.4).

The problems mix the lessons on purpose, and the mini project combines all four in the kind of batch job that feeds every RAG system.

import json
from pathlib import Path


def append_metrics(path, run, metrics):
    path = Path(path)
    path.parent.mkdir(parents=True, exist_ok=True)
    with open(path, "a", encoding="utf-8") as f:
        f.write(json.dumps({"run": run, **metrics}) + "\n")


def best_run(path, metric):
    best = None
    with open(path, encoding="utf-8") as f:
        for line in f:
            if not line.strip():
                continue
            try:
                record = json.loads(line)
            except json.JSONDecodeError:
                continue
            value = record.get(metric) if isinstance(record, dict) else None
            if isinstance(value, (int, float)) and not isinstance(value, bool):
                if best is None or value > best[1]:
                    best = (record.get("run"), value)
    return best

Appending one JSON line per run is the simplest durable experiment log: concurrent-safe enough for one writer, readable after a crash, and greppable. Reading it is a streaming scan with explicit tolerance for the junk that accumulates in such files (a broken line, a metric written as a string, a boolean, which Python counts as an int). The "loss" query shows the function is generic, though for a loss you would want the minimum; a real tracker (MLflow, Weights & Biases) stores a direction per metric.

solution.py
import tomllib
from pathlib import Path


def _validate(data):
    if not isinstance(data.get("name"), str) or not data["name"]:
        raise ValueError("missing name")
    if not isinstance(data.get("template"), str):
        raise ValueError("missing template")
    variables = data.get("variables")
    if not isinstance(variables, list) or not all(isinstance(v, str) for v in variables):
        raise ValueError("variables must be a list of strings")


def load_prompts(folder, logger):
    prompts = {}
    for path in sorted(Path(folder).glob("*.toml")):
        try:
            with open(path, "rb") as f:
                data = tomllib.load(f)
            _validate(data)
        except ValueError as e:
            logger.warning("skipping %s: %s", path.name, e)
            continue
        if data["name"] in prompts:
            logger.warning("duplicate prompt %r in %s", data["name"], path.name)
            continue
        prompts[data["name"]] = {"template": data["template"], "variables": data["variables"], "file": path.name}
    return prompts

Prompts kept as files outside the code can be reviewed, diffed and changed without a deploy, and TOML handles multi-line templates well. The loader combines the module: glob (not rglob) for one folder and sorted for a deterministic order (12.1), tomllib.load on a binary file (12.4), validation of the parsed data, and warnings with lazy arguments (12.3). Because TOMLDecodeError subclasses ValueError, syntax errors and validation errors share one handler. Whether a bad prompt file should be a warning or a start-up failure is a policy choice; failing hard is safer when the missing prompt would break a feature.

HintOpen a hint

Opening with "w" truncates the file before the first line is read. Read everything into latest first, then write a temporary file and os.replace it.

SolutionShow the solution and why
solution.py
import json, os

def compact(path):
    latest = {}
    with open(path, encoding="utf-8") as src:
        for line in src:
            if line.strip():
                record = json.loads(line)
                latest[record["id"]] = record
    tmp = path + ".tmp"
    try:
        with open(tmp, "w", encoding="utf-8") as dst:
            for record in latest.values():
                dst.write(json.dumps(record) + "\n")
        os.replace(tmp, path)
    except BaseException:
        if os.path.exists(tmp):
            os.remove(tmp)
        raise
    return len(latest)

Both open calls run before the loop, and "w" empties the file at once, so the reader found nothing: the data was destroyed by the attempt to rewrite it. Reading into memory first and writing to a temporary file that replaces the original (12.1) fixes both the logic and the crash-safety. Assigning to an existing dict key keeps its original position while updating the value, which gives "last record, in order of first appearance" for free. For files too large for memory, the same job writes the compacted output to a new file in a second streaming pass, or uses a database.

Both write the same 2,000-record payload to an open text file. Which is faster?

setup
import io, json

HintOpen a hint

json.dump writes each piece as the encoder produces it; json.dumps builds the whole string in C first.

SolutionShow the solution and why
OptionTime per run (measured at build time)
A23.84 ms
B5.17 ms

json.dump streams: it walks the data and calls f.write for every small chunk the encoder produces (each key, value and separator), so the cost is dominated by thousands of method calls. json.dumps encodes everything in the C accelerator into one string, and a single write follows. The trade-off is memory: dumps holds the whole document as one string, which is fine for megabytes and wasteful for gigabytes, where streaming (or JSONL, one dumps per record) is the better structure anyway.

8. Rotate log files by size

Write rotate(path, max_bytes, backups) that does nothing if path does not exist or is at most max_bytes bytes. Otherwise it shifts the backups: app.log.{backups-1} becomes app.log.{backups} (replacing it), down to app.log.1 becoming app.log.2, then renames app.log to app.log.1, and returns True. With backups=0 it just deletes the file. Write log_line(path, line, max_bytes, backups) that rotates when needed, then appends the line and a newline.

SolutionShow the solution and why
solution.py
from pathlib import Path


def rotate(path, max_bytes, backups):
    path = Path(path)
    if not path.exists() or path.stat().st_size <= max_bytes:
        return False
    if backups <= 0:
        path.unlink()
        return True
    for i in range(backups - 1, 0, -1):
        older = path.with_name(f"{path.name}.{i}")
        if older.exists():
            older.replace(path.with_name(f"{path.name}.{i + 1}"))
    path.replace(path.with_name(f"{path.name}.1"))
    return True


def log_line(path, line, max_bytes, backups):
    rotate(path, max_bytes, backups)
    with open(path, "a", encoding="utf-8") as f:
        f.write(line + "\n")

Each event line is 8 bytes, so the file passes 16 bytes with its third line and is rotated before the fourth write, which is why each backup holds three complete events. Shifting must start with the oldest backup, or renaming .1 to .2 would overwrite .2 before it moved on; replace overwrites the last backup, which is how old logs fall off the end. This is what logging.handlers.RotatingFileHandler(path, maxBytes=..., backupCount=...) does for you, and why services rotate logs at all: unbounded log files fill disks, which takes down far more than logging.

import csv, json, os
from pathlib import Path


def export_metrics(runs_dir, out_path, logger):
    decimals = int(os.environ.get("EXPORT_DECIMALS", "3"))
    rows = []
    for path in sorted(Path(runs_dir).rglob("*.json"), key=lambda p: p.stem):
        try:
            data = json.loads(path.read_text(encoding="utf-8"))
            rows.append((path.stem, float(data["f1"]), float(data["loss"])))
        except (json.JSONDecodeError, KeyError, TypeError, ValueError) as e:
            logger.warning("skipping %s: %s: %s", path.name, type(e).__name__, e)
    logger.info("exporting %d runs", len(rows))
    out = Path(out_path)
    out.parent.mkdir(parents=True, exist_ok=True)
    tmp = out.with_name(out.name + ".tmp")
    try:
        with open(tmp, "w", encoding="utf-8", newline="") as f:
            writer = csv.writer(f)
            writer.writerow(["run", "f1", "loss"])
            for run, f1, loss in rows:
                writer.writerow([run, f"{f1:.{decimals}f}", f"{loss:.{decimals}f}"])
        os.replace(tmp, out)
    except BaseException:
        tmp.unlink(missing_ok=True)
        raise
    return len(rows)

The fix touches every lesson of the module. Files: rglob finds runs in subfolders, sorting makes the report stable, the output folder is created, and the temporary file plus os.replace means the dashboard always reads a complete CSV, old or new (12.1). Formats: the csv writer with a header and newline="" replaces string joining, and fixed-decimal formatting replaces round, which prints 0.4 instead of 0.40 (12.2). Logging: one warning per skipped file with the reason, instead of a crash or a print nobody sees (12.3). Configuration: the environment value is parsed as an int when the function runs, not used as the string "2", which would make round fail (12.4).

Interview

11. Walk through how you would design a batch job that turns a folder of documents into chunks for a vector index.

SolutionModel answer

Configuration first: source and output locations, file types, chunk size and overlap, read from a TOML file with environment overrides and validated at start-up (12.4). Discovery: walk the tree with explicit filters (types, hidden and vendor folders), sorted for reproducibility, and read each file with an explicit encoding, treating undecodable or empty files as skipped, not fatal (12.1). Identity: give every document a stable id (its relative path) and a content hash, so unchanged documents can be skipped on the next run and duplicates detected. Output: stream chunks to a JSONL file with the document id, chunk number and hash, written to a temporary file and atomically replaced, plus a manifest with counts, skipped and duplicate files and the configuration used (12.2). Observability: log one line per skipped file with the reason and a summary at the end, structured so it can be charted (12.3). Then embedding and upserting read the JSONL, which also makes those steps restartable without redoing the parsing.

Interview

12. Your batch job runs fine locally but produces different output in production. How do you investigate?

SolutionModel answer

Start with the inputs the code does not control. Configuration: print or log the effective settings at start-up with their sources (masking secrets), and compare; a different environment variable, a stale .env, or a default used because a variable was misspelt is the commonest cause. Data: compare file lists and content hashes, since a different checkout, mounted folder or rglob order (unsorted) can change results. Encodings and locale: a missing encoding= uses the platform default, so the same file decodes differently on Windows and in a Linux container; line endings and BOMs differ too. Versions: pin and compare dependency versions and the Python version. Time and randomness: time zones, the current date, and unseeded random generators. Make the job reproducible by design: explicit encodings, sorted iteration, a manifest that records config, input hashes and versions, and structured logs, so the two runs can be diffed instead of guessed at.

13. Ingest a corpus into JSONL chunks

Implement run_ingest(config_toml, environ, logger).

  • Configuration (12.4): the TOML has an [ingest] table with source and output (paths), max_words (int, default 50) and suffixes (default [".md", ".txt"]). The environment variables INGEST_OUTPUT and INGEST_MAX_WORDS override them; INGEST_MAX_WORDS must be a positive integer, otherwise raise ValueError.
  • Discovery (12.1): every file under source, sorted by relative POSIX path, whose suffix (case-insensitive) is in suffixes and which is not inside a folder starting with ..
  • Reading: decode as UTF-8; a file that is not valid UTF-8 or is empty after stripping is skipped, with a warning "skipping %s: %s" (relative path and "not UTF-8" or "empty").
  • Duplicates: a file whose SHA-256 equals an earlier file's is a duplicate, logged at INFO as "duplicate %s of %s", and not chunked.
  • Output (12.2): a JSONL file at output (parents created) with one record per chunk of at most max_words words: {"doc": relative path, "chunk": k, "sha256": first 12 hex digits, "text": words joined by spaces}, and a manifest at output with the suffix replaced by .manifest.json: {"documents": n, "chunks": m, "duplicates": [...], "skipped": [...], "max_words": ...} with indent=2. Both are written atomically; no temporary files remain.
  • Logging (12.3): a final INFO record "ingest done" with extra fields documents and chunks.
  • Return the manifest dict.

import hashlib, json, os, tomllib
from pathlib import Path


def _settings(config_toml, environ):
    cfg = tomllib.loads(config_toml)["ingest"]
    source = Path(cfg["source"])
    output = Path(environ.get("INGEST_OUTPUT") or cfg["output"])
    max_words = cfg.get("max_words", 50)
    raw = environ.get("INGEST_MAX_WORDS", "").strip()
    if raw:
        try:
            max_words = int(raw)
        except ValueError:
            raise ValueError(f"INGEST_MAX_WORDS must be an integer, got {raw!r}") from None
    if not isinstance(max_words, int) or max_words <= 0:
        raise ValueError(f"max_words must be a positive integer, got {max_words!r}")
    suffixes = {s.lower() for s in cfg.get("suffixes", [".md", ".txt"])}
    return source, output, max_words, suffixes


def _discover(source, suffixes):
    found = []
    for path in source.rglob("*"):
        if not path.is_file() or path.suffix.lower() not in suffixes:
            continue
        rel = path.relative_to(source)
        if any(part.startswith(".") for part in rel.parts[:-1]):
            continue
        found.append((rel.as_posix(), path))
    return sorted(found)


def _write_atomic(path, text):
    tmp = path.with_name(path.name + ".tmp")
    try:
        tmp.write_text(text, encoding="utf-8")
        os.replace(tmp, path)
    except BaseException:
        tmp.unlink(missing_ok=True)
        raise


def run_ingest(config_toml, environ, logger):
    source, output, max_words, suffixes = _settings(config_toml, environ)
    seen, lines, duplicates, skipped = {}, [], [], []
    documents = 0
    for rel, path in _discover(source, suffixes):
        data = path.read_bytes()
        try:
            text = data.decode("utf-8")
        except UnicodeDecodeError:
            logger.warning("skipping %s: %s", rel, "not UTF-8")
            skipped.append(rel)
            continue
        words = text.split()
        if not words:
            logger.warning("skipping %s: %s", rel, "empty")
            skipped.append(rel)
            continue
        digest = hashlib.sha256(data).hexdigest()
        if digest in seen:
            logger.info("duplicate %s of %s", rel, seen[digest])
            duplicates.append(rel)
            continue
        seen[digest] = rel
        documents += 1
        for k, start in enumerate(range(0, len(words), max_words)):
            record = {"doc": rel, "chunk": k, "sha256": digest[:12], "text": " ".join(words[start:start + max_words])}
            lines.append(json.dumps(record, ensure_ascii=False) + "\n")
    manifest = {"documents": documents, "chunks": len(lines), "duplicates": duplicates, "skipped": skipped, "max_words": max_words}
    output.parent.mkdir(parents=True, exist_ok=True)
    _write_atomic(output, "".join(lines))
    _write_atomic(output.with_suffix(".manifest.json"), json.dumps(manifest, indent=2))
    logger.info("ingest done", extra={"documents": documents, "chunks": len(lines)})
    return manifest

Every lesson of the module has a job here:

  • Paths and files (12.1): rglob with explicit filters for suffix (case-insensitive, so terms.TXT counts) and hidden folders, sorting by relative path so "first seen" and the output are deterministic, mkdir(parents=True, exist_ok=True) for the output folder, and atomic writes so the index builder never reads half a file. Reading bytes once serves both the hash and the decoding.
  • Formats (12.2): chunks are JSONL, one record per line with the metadata a vector index needs, and the manifest is indented JSON for people. The duplicate is reported against the file seen first in sorted order, copy-of-refunds.md.
  • Logging (12.3): each skipped or duplicate file gets one line with lazy arguments, and the summary record carries its numbers as extra fields.
  • Configuration (12.4): TOML provides the structure, the environment overrides the output location and chunk size, and a bad override fails at start-up with a clear message, before any work is done.

The manifest makes runs comparable: if tonight's run has fewer documents than last night's, the skipped list says why. Production versions add overlap between chunks, token-based sizes, incremental runs that skip unchanged hashes, and parallel reading, but keep this structure.

Recap

  • Build paths with pathlib, filter and sort what rglob finds, and never assume folders exist.
  • Rewrite files through a temporary file and os.replace; opening the target with "w" destroys it first.
  • Pick the format for the data: CSV for flat tables (strings only), JSON for documents, JSONL for record streams, and decide what a bad record means.
  • Log skips and failures once, with the reason and context, and summarise runs with structured fields.
  • Read configuration at start-up from defaults, files and the environment, parse it strictly, and keep secrets out of code and logs.
