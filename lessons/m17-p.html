import pandas as pd


def weekly_by_product(df):
    counts = df.groupby([pd.Grouper(key="submitted", freq="W"), "product"]).size()
    wide = counts.unstack("product", fill_value=0).sort_index(axis=1)
    wide = wide.asfreq("W", fill_value=0)
    return wide.rename_axis(index=None, columns=None).astype(int)

This combines D.3 and D.4: a group-by on two keys, one of them a time bin (pd.Grouper is resample inside a group-by), then unstack to go from long (week, product) counts to a wide table, filling missing combinations with 0. Weeks with no complaints at all are missing from the group-by result, so asfreq("W") reinstates them; skipping that step makes a chart or a forecasting model treat the third week as following the first directly. Removing the axis names gives plain columns for saving or plotting, and wide.plot() would now draw one line per product (D.5).

3. A customer feature that leaks the label

add_customer_rate adds each customer's historical escalation rate as a feature. It is computed on the whole dataset before splitting, so every row's own label is included in its feature, and the validation score is far too good. Rewrite it as add_customer_rate(train, test) that returns (train_out, test_out): test rows get the rate learned from train (the global train rate for unknown customers), and train rows get a leave-one-out rate, the customer's rate over their other training rows (the global train rate if they have none). Round to 3.

Hint 1Open a hint

Leave-one-out: (group sum - own label) / (group count - 1), with transform("sum") and transform("count").

Hint 2Open a hint

Rows whose customer has only one training row divide by zero; replace those with the global train mean.

SolutionShow the solution and why
solution.py
import pandas as pd


def add_customer_rate(train, test):
    prior = train["escalated"].mean()
    g = train.groupby("customer")["escalated"]
    total, count = g.transform("sum"), g.transform("count")
    loo = (total - train["escalated"]) / (count - 1).where(count > 1)
    tr = train.assign(cust_rate=loo.fillna(prior).round(3))
    rates = g.mean()
    te = test.assign(cust_rate=test["customer"].map(rates).fillna(prior).round(3))
    return tr, te

A group mean that includes the row's own label is a disguised copy of the label: customer b has one row, so the "rate" is exactly that row's answer. The model learns to trust it, scores brilliantly in validation, and degrades in production, where the current complaint's outcome is not yet known. Test rows must only see training statistics (D.2's imputer rule). Training rows need the same honesty, which leave-one-out provides: customer a's first complaint sees the other two (one escalated of two, 0.5), and its third sees two escalations (1.0). Customers with a single row, and unseen customers, fall back to the global rate. This is the same idea as out-of-fold target encoding in D.3, with folds of size one.

SolutionShow the solution and why
solution.py
import numpy as np


def near_duplicates(E, ids, threshold=0.95):
    E = np.asarray(E, dtype=float)
    En = E / np.maximum(np.linalg.norm(E, axis=1, keepdims=True), 1e-12)
    S = En @ En.T
    i, j = np.where(np.triu(S >= threshold, k=1))
    return sorted((ids[a], ids[b], round(float(S[a, b]), 3)) for a, b in zip(i, j))


def keep(ids, pairs):
    drop = {b for _, b, _ in pairs}
    return [x for x in ids if x not in drop]

The starter compared raw dot products (so the long vector d4 looked unlike its twin d3), compared every document with itself (similarity 1 on the diagonal), and listed each pair twice. Normalising first makes the dot product a cosine (D.1); one matrix product gives all n * n similarities; np.triu(..., k=1) keeps only pairs above the diagonal, so i < j and each pair appears once. This is quadratic in memory, fine for thousands of documents; for millions, the same idea runs inside an approximate nearest-neighbour index or with MinHash. Dropping the later document of each pair keeps the earliest version, a deterministic rule.

solution.py
import numpy as np
import pandas as pd
import matplotlib.pyplot as plt


def calibration_table(y_true, proba, bins=5):
    df = pd.DataFrame({"y": np.asarray(y_true), "p": np.asarray(proba, dtype=float)})
    df["bin"] = pd.cut(df["p"], np.linspace(0, 1, bins + 1), include_lowest=True)
    t = df.groupby("bin", observed=True).agg(n=("y", "size"), mean_pred=("p", "mean"), frac_pos=("y", "mean")).reset_index()
    t["bin"] = t["bin"].astype(str)
    t[["mean_pred", "frac_pos"]] = t[["mean_pred", "frac_pos"]].round(3)
    return t


def plot_calibration(table):
    fig, ax = plt.subplots(figsize=(3.6, 3.4))
    ax.plot(table["mean_pred"], table["frac_pos"], marker="o", label="model")
    ax.plot([0, 1], [0, 1], linestyle="--", color="gray", label="perfect")
    ax.set(xlabel="mean predicted probability", ylabel="fraction positive", xlim=(0, 1), ylim=(0, 1))
    ax.legend()
    return ax


def ece(table):
    gap = (table["mean_pred"] - table["frac_pos"]).abs()
    return round(float((gap * table["n"]).sum() / table["n"].sum()), 3)

Ranking metrics such as ROC AUC ignore whether the probabilities mean what they say, but any decision that uses the number itself (expected cost, a "70% likely" message to an agent, combining scores) needs calibration. pd.cut with fixed edges assigns each score to a bin, the group-by gives the average prediction and the observed rate per bin, and the reliability diagram plots one against the other: points below the diagonal mean the model is over-confident. Grouping with observed=True skips empty bins, as the last test checks. The expected calibration error summarises the gaps weighted by how many predictions fall in each bin. scikit-learn's calibration_curve and CalibratedClassifierCV compute and fix this; LLM confidence scores are notoriously uncalibrated, which is why they are checked the same way.

6. Has the input data drifted

Write psi(reference, current) computing the population stability index between two categorical Series: for every category in either, take its share in each (adding eps=1e-4 to every share before the logarithm), and sum (cur - ref) * ln(cur / ref); round to 3. solution.py
import numpy as np
import pandas as pd


def psi(reference, current, eps=1e-4):
    r = reference.value_counts(normalize=True)
    c = current.value_counts(normalize=True)
    cats = r.index.union(c.index)
    r = r.reindex(cats, fill_value=0) + eps
    c = c.reindex(cats, fill_value=0) + eps
    return round(float(((c - r) * np.log(c / r)).sum()), 3)


def drift_report(train_df, new_df, cols):
    values = pd.Series({col: psi(train_df[col], new_df[col]) for col in cols})
    status = np.select([values < 0.1, values < 0.25], ["stable", "watch"], default="drift")
    return pd.DataFrame({"psi": values, "status": status}).sort_values("psi", ascending=False)

A model is trained on one distribution and served on another; when inputs shift, its accuracy can fall long before labels arrive to measure it, so input drift is the first thing production monitoring checks. PSI compares the share of each category: each term is positive whenever shares differ, and it grows quickly for categories that appear from nowhere, such as crypto, which is why the small eps matters (without it, a share of zero would make the logarithm infinite). Aligning both distributions on the union of categories is the same unseen-category problem as D.4's one-hot encoder. The 0.1 and 0.25 cut-offs are industry conventions from credit scoring; numeric columns are handled the same way after binning them with the training quantiles.

import pandas as pd


def error_analysis(df, by, min_n=5):
    d = df.assign(correct=(df["y_true"] == df["y_pred"]).astype(int))
    seg = d.groupby(by).agg(n=("correct", "size"), correct=("correct", "sum"))
    seg = seg[seg["n"] >= min_n]
    total = pd.DataFrame({"n": [len(d)], "correct": [d["correct"].sum()]}, index=["ALL"])
    out = pd.concat([seg.sort_index(), total])
    out["accuracy"] = (out["correct"] / out["n"]).round(3)
    out["errors"] = out["n"] - out["correct"]
    body = out.drop(index="ALL").sort_values(["accuracy", "n"], ascending=[True, False], kind="stable")
    return pd.concat([body, out.loc[["ALL"]]])[["n", "accuracy", "errors"]]

An overall accuracy of 0.667 hides that loans are at 0.6 while mortgages reach 0.8 and cards 0.833; error analysis by segment tells you where to look next (more data for loans, a feature that separates loan cases, or a different threshold). Tiny segments are dropped from the ranking because their accuracy is mostly noise (two auto loans), but they still count in the overall row, so the totals reconcile with the full evaluation. Sorting worst first with size as the tie-breaker puts the biggest problem at the top. The same table, with y_true and y_pred from an LLM judge, is how GenAI teams find the prompt's weak categories.

Interview

9. Walk me through how you would build a first model for a new tabular or text dataset.

SolutionModel answer

Start with the question and the decision: what is predicted, when, for whom, and what does each kind of error cost; that defines the label, the metric and the split. Then look at the data before modelling: row meaning, dtypes, missing values, duplicates, class balance and time range (info, a quality report, histograms, a few raw examples), and check for label leakage (columns created after the outcome). Define the split to match production, by time or by entity, keep a test set aside, and set up cross-validation. Build a baseline (majority class, or a simple rule), then a simple, strong model inside one pipeline: imputation, scaling and one-hot for tabular columns, TF-IDF for text, logistic regression or gradient boosting. Evaluate with the chosen metric against the baseline, look at the confusion matrix, the calibration and errors by segment, and inspect the model (coefficients, important features) for nonsense. Only then iterate on features, models and thresholds, each change judged by cross-validation; finally score the test set once, document the results, and plan monitoring (input drift, prediction rates, delayed labels).

Interview

10. Once a model is in production, what do you monitor, and why?

SolutionModel answer

Model quality decays silently, because the world changes and nothing crashes. Monitor at several levels. Service health: latency, error rates and throughput, like any API. Inputs: schema and type checks, missing-value rates, ranges, and distribution drift per feature (PSI or KS tests against training data), plus the rate of unseen categories; these move first and need no labels. Outputs: the distribution of scores and the share of each predicted class; a sudden jump in "urgent" predictions is either a real event or a broken feature. Quality: once labels arrive (often days later), precision, recall and calibration over time and per segment, compared with the offline evaluation. For LLM features add cost per request, token counts, refusal and format-error rates, and a regular sampled human or LLM-judge review. Each metric needs a threshold and an owner, and the response playbook includes rolling back, retraining on recent data, or adjusting the threshold. Logging inputs and predictions with model versions makes all of this possible.

import io, math, re
import numpy as np
import pandas as pd
import matplotlib.pyplot as plt
from sklearn.compose import ColumnTransformer
from sklearn.dummy import DummyClassifier
from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.impute import SimpleImputer
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import accuracy_score, confusion_matrix, f1_score, precision_score, recall_score
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import OneHotEncoder, StandardScaler

FEATURES = ["narrative", "amount", "product"]


def load(csv_text):
    df = pd.read_csv(io.StringIO(csv_text), dtype={"amount": "str"})
    return (df.assign(
                product=lambda d: d["product"].str.strip().str.lower(),
                amount=lambda d: pd.to_numeric(d["amount"], errors="coerce"),
                submitted=lambda d: pd.to_datetime(d["submitted"], format="%Y-%m-%d %H:%M"),
                narrative=lambda d: d["narrative"].fillna("").str.replace(r"\bX{2,}\b", "[X]", regex=True))
              .drop_duplicates("id", keep="first"))


def build_model():
    num = Pipeline([("impute", SimpleImputer(strategy="median")), ("scale", StandardScaler())])
    prep = ColumnTransformer([
        ("text", TfidfVectorizer(ngram_range=(1, 2)), "narrative"),
        ("num", num, ["amount"]),
        ("cat", OneHotEncoder(handle_unknown="ignore"), ["product"]),
    ])
    return Pipeline([("prep", prep), ("clf", LogisticRegression(max_iter=1000, class_weight="balanced"))])


def report_figure(y_true, y_pred, products):
    C = confusion_matrix(y_true, y_pred, labels=[0, 1])
    fig, (a, b) = plt.subplots(1, 2, figsize=(8, 3.2))
    a.imshow(C, cmap="Blues")
    for i in range(2):
        for j in range(2):
            a.text(j, i, str(C[i, j]), ha="center", va="center", color="white" if C[i, j] > C.max() / 2 else "black")
    a.set_xticks([0, 1], labels=["normal", "escalated"])
    a.set_yticks([0, 1], labels=["normal", "escalated"])
    a.set(title="confusion matrix", xlabel="predicted", ylabel="true")
    pos = pd.DataFrame({"product": products, "hit": np.asarray(y_pred) == 1})[np.asarray(y_true) == 1]
    recall = pos.groupby("product")["hit"].mean().sort_values()
    b.barh(recall.index, recall.values)
    b.set(title="recall by product", xlim=(0, 1), xlabel="recall")
    fig.tight_layout()
    return fig


def run_project(csv_text, test_frac=0.25):
    df = load(csv_text).sort_values("submitted", kind="stable").reset_index(drop=True)
    n_test = math.ceil(test_frac * len(df))
    train, test = df.iloc[: len(df) - n_test], df.iloc[len(df) - n_test:]
    model = build_model().fit(train[FEATURES], train["escalated"])
    pred = model.predict(test[FEATURES])
    y = test["escalated"].to_numpy()
    base = DummyClassifier(strategy="most_frequent").fit(train[FEATURES], train["escalated"]).predict(test[FEATURES])
    r3 = lambda v: round(float(v), 3)
    metrics = {"accuracy": r3(accuracy_score(y, pred)), "precision": r3(precision_score(y, pred, zero_division=0)),
               "recall": r3(recall_score(y, pred, zero_division=0)), "f1": r3(f1_score(y, pred, zero_division=0)),
               "baseline_accuracy": r3(accuracy_score(y, base))}
    names = model.named_steps["prep"].get_feature_names_out()
    coef = model.named_steps["clf"].coef_[0]
    text_idx = [i for i, n in enumerate(names) if n.startswith("text__")]
    top = sorted(text_idx, key=lambda i: -coef[i])[:5]
    return {"model": model, "metrics": metrics, "top_words": [names[i][len("text__"):] for i in top],
            "figure": report_figure(y, pred, test["product"].to_numpy()),
            "n_train": len(train), "n_test": len(test), "split_time": test["submitted"].iloc[0]}

Every step is one lesson, and the order matters as much as the steps. Cleaning comes first and is applied identically to all rows (stripping and lower-casing merges " Credit card" and "credit card" into one category; the duplicated export row is removed before it can land in both splits). The split is by time, so the evaluation asks the production question: trained on earlier complaints, how well does it flag later ones? Everything learned (the TF-IDF vocabulary, the median amount, the product categories, the model weights) sits inside one pipeline fitted on the training rows only, so the test set never influences preprocessing, and the fitted object accepts raw columns, including an unseen product and a missing amount. The baseline gives the metrics their meaning: about 70% of complaints are not escalated, so accuracy alone says little, while F1 for the escalated class shows real skill. The top words are a sanity check that the model learned the intended signal (fraud, unauthorized, stolen) rather than an artefact such as the redaction marker. The report figure is what you would show a stakeholder: where the errors are, and whether any product is badly served.

From here, the next steps are the ones in the interview answers above: cross-validated tuning, a threshold chosen from the precision-recall curve, calibration, error analysis by product, and monitoring for drift once it is live.

Recap

  • Say the shape of the data at every step: what a row is, which columns and dtypes, and what the result should look like.
  • NumPy for whole-array maths, pandas for cleaning, joins, group-bys, time and text, matplotlib to look, scikit-learn pipelines for anything learned.
  • Ask of every feature and split: could this leak? Group statistics need out-of-fold or leave-one-out values; splits follow time or entities.
  • Always compare with a baseline, then check calibration, errors by segment and the model's top features before trusting a score.
  • Production adds monitoring: input drift (PSI), output rates and delayed-label quality, with thresholds and owners.
