16.5 Dynamic programming

Dynamic programming solves problems whose answer is built from answers to smaller, overlapping versions of the same problem. Recognising it, memoization with functools.cache, bottom-up tables, reconstructing the solution, and the classics that interviews and ML code actually use: coin change, longest common subsequence, edit distance (the metric behind word error rate), knapsack (choosing context chunks under a token budget), longest increasing subsequence and segmentation.

18 problems4 easy · 9 medium · 5 hard

1Overlapping subproblems

Some recursive solutions call themselves with the same arguments many times. The naive Fibonacci fib(n) = fib(n - 1) + fib(n - 2) recomputes fib(n - 2) from both branches, and the number of calls grows exponentially, about 1.6^n. Dynamic programming applies when a problem has optimal substructure (the answer for a state is built from answers for smaller states) and overlapping subproblems (the same smaller states recur). Then each distinct state is computed once: the cost becomes the number of states times the work per state, often turning O(2^n) into O(n) or O(n^2).

Every DP solution answers four questions: what is the state (the arguments that identify a subproblem: an index, a remaining budget, two prefix lengths), what is the recurrence (how a state's answer follows from smaller states), what are the base cases, and in what order states are computed (top-down with a cache, or bottom-up in a table). Writing them down before coding is most of the work, in interviews and in practice.

2Top-down: memoization

The quickest way from a correct recursive solution to an efficient one is a cache: @functools.cache (or @functools.lru_cache(maxsize=None)) stores each call's result by its arguments, which must therefore be hashable (tuples, not lists; problem 3). The code stays close to the recurrence, and only states that are actually reached are computed. The costs are Python's recursion limit (about 1,000 frames by default; deep recursion can also crash browser-based Python such as this site's) and function-call overhead. cache_info() reports hits and misses, and cache_clear() empties the cache, which matters when the function depends on data that can change.

memo.py
from functools import cache

calls = {"naive": 0}

def fib_naive(n):
    calls["naive"] += 1
    return n if n < 2 else fib_naive(n - 1) + fib_naive(n - 2)

@cache
def fib(n):
    return n if n < 2 else fib(n - 1) + fib(n - 2)

print(fib_naive(20), calls["naive"])
print(fib(20), fib.cache_info())
print(fib(60), fib.cache_info().misses)

3Bottom-up: tabulation

Bottom-up DP fills a table from the base cases upwards in an order where every state's dependencies are already computed, with plain loops: no recursion limit, no call overhead, and often a chance to keep only the last row or two (O(n) memory instead of O(n^2)). Two-sequence problems use a table dp[i][j] for the first i items of one sequence and the first j of the other, with an extra row and column for the empty prefixes; most off-by-one errors come from forgetting those (problem 7). To return the solution and not just its value (which coins, which chunks, which edits), either store choices in the table or walk backwards from the final cell, checking which recurrence branch produced each value (problems 9 and 13).

edit_distance.py
def edit_distance(a, b):
    prev = list(range(len(b) + 1))
    for i in range(1, len(a) + 1):
        cur = [i] + [0] * len(b)
        for j in range(1, len(b) + 1):
            cost = 0 if a[i - 1] == b[j - 1] else 1
            cur[j] = min(prev[j] + 1, cur[j - 1] + 1, prev[j - 1] + cost)
        prev = cur
    return prev[-1]

print(edit_distance("kitten", "sitting"), edit_distance("refund", "refunds"), edit_distance("", "abc"), edit_distance("same", "same"))
ref = "refunds take five business days".split()
hyp = "refund takes five days".split()
print(edit_distance(ref, hyp), round(edit_distance(ref, hyp) / len(ref), 2))
Output
3 1 3 0
3 0.6

Edit distance counts the minimum insertions, deletions and substitutions turning one sequence into another; each cell takes the cheapest of deleting, inserting, or substituting (free when the items match), and keeping only the previous row makes memory O(len(b)). Applied to words, it is the numerator of word error rate, the standard metric for speech recognition and a useful one for comparing generated text with a reference: here 3 errors over 5 reference words.

4The classics and where they appear

Coin change (fewest coins, or number of ways, for an amount) is the template for "combine items to reach a total". Longest common subsequence underlies diff, sequence alignment and ROUGE-L for summarisation. Edit distance gives fuzzy matching, typo correction and WER. 0/1 knapsack chooses items with weights and values under a capacity: choosing retrieved chunks to maximise relevance within a token budget is exactly this (problem 9), O(n * capacity). Longest increasing subsequence has an O(n log n) solution with bisect (problem 11). Kadane's algorithm finds the best contiguous sum in O(n) by deciding at each step whether to extend the current run or start over. Word break segments text with a dictionary, related to how tokenizers split words into subwords (problem 12).

solution.py
def count_ways(n, steps):
    ways = [0] * (n + 1)
    ways[0] = 1
    for i in range(1, n + 1):
        ways[i] = sum(ways[i - s] for s in steps if s <= i)
    return ways[n]

The state is the remaining height i, and the recurrence follows from the last step taken: any sequence reaching i ends with some step s, after a sequence reaching i - s. With ways[0] = 1 (the empty sequence) as the base case and the table filled from small to large, every needed value is ready when used, so there is no recursion and n = 500 is instant despite the astronomically large answer (Python integers grow as needed). With steps 1 and 2 this is the Fibonacci sequence.

solution.py
from functools import cache

@cache
def _best(costs):
    if not costs:
        return 0
    best = None
    for k in range(1, len(costs) + 1):
        candidate = max(costs[:k]) * k + _best(costs[k:])
        if best is None or candidate < best:
            best = candidate
    return best

def best_split(costs):
    return _best(tuple(costs))

The cache stores results in a dict keyed by the arguments, so every argument must be hashable; a list is not, because it could change after being used as a key. Converting to a tuple once, at the public boundary, keeps callers free to pass lists while the memoised helper works on immutable tuples whose slices are tuples too. Even better for long inputs is to make the state an index (_best(i) for the suffix starting at i), which avoids building and hashing slices: O(n) states instead of slices of every length. Choosing a small, hashable state is half of designing a DP.

4. Kadane's maximum subarray

def max_subarray(values):
    best = cur = values[0]
    start = best_start = best_end = 0
    for i in range(1, len(values)):
        if cur + values[i] < values[i]:
            cur, start = values[i], i
        else:
            cur += values[i]
        if cur > best:
            best, best_start, best_end = cur, start, i
    return best, values[best_start:best_end + 1]

print(max_subarray(daily_gain))
print(max_subarray([-3, -1, -4]), max_subarray([2, 3, -1, 4]))

Kadane's algorithm is DP with a one-number state: the best sum of a run ending at the current position, which is either the element alone or the element added to the best run ending just before. solution.py
def min_coins(coins, amount):
    INF = float("inf")
    best = [0] + [INF] * amount
    last = [None] * (amount + 1)
    for a in range(1, amount + 1):
        for c in coins:
            if c <= a and best[a - c] + 1 < best[a]:
                best[a], last[a] = best[a - c] + 1, c
    if best[amount] == INF:
        return None
    combo, a = [], amount
    while a:
        combo.append(last[a])
        a -= last[a]
    return best[amount], sorted(combo, reverse=True)


def count_combinations(coins, amount):
    ways = [1] + [0] * amount
    for c in coins:
        for a in range(c, amount + 1):
            ways[a] += ways[a - c]
    return ways[amount]

The state is the remaining amount. For the fewest coins, the recurrence tries every coin as the last one: best[a] = 1 + min(best[a - c]), and storing which coin achieved the minimum lets you rebuild the combination by walking back from amount. Greedy "take the largest coin" fails for coins [1, 3, 4] and amount 6 (4 + 1 + 1 instead of 3 + 3), which is the classic reason to reach for DP. For counting, the loop order decides what is counted: coins outside means each coin's uses are added before the next coin is considered, so every combination is built in one canonical order and counted once (242 ways to make a dollar from US coins); amounts outside would count orderings, as in problem 2.

solution.py
def edit_distance(a, b):
    prev = list(range(len(b) + 1))
    for i in range(1, len(a) + 1):
        cur = [i] + [0] * len(b)
        for j in range(1, len(b) + 1):
            cost = 0 if a[i - 1] == b[j - 1] else 1
            cur[j] = min(prev[j] + 1, cur[j - 1] + 1, prev[j - 1] + cost)
        prev = cur
    return prev[-1]


def _words(text):
    return [w.strip(".,!?").lower() for w in text.split() if w.strip(".,!?")]


def word_error_rate(reference, hypothesis):
    ref, hyp = _words(reference), _words(hypothesis)
    if not ref:
        return 0.0 if not hyp else 1.0
    return round(edit_distance(ref, hyp) / len(ref), 3)

Edit distance's state is a pair of prefix lengths; the last items either match (free), or one is substituted, deleted or inserted (cost 1), and the table's first row and column are the costs of building a prefix from nothing. Only the previous row is needed for the next, so memory is O(len(b)) while time stays O(len(a) * len(b)). Because the function works on any sequences, the same code gives character edits (typo correction, fuzzy matching of entity names) and word edits: word error rate, the main metric for speech recognition and a robust way to compare transcripts or extracted text. WER can exceed 1 when the hypothesis has many insertions, so it is not a percentage.

7. An LCS table without the empty prefixes

lcs_length(a, b) should return the length of the longest common subsequence of two token lists (the core of ROUGE-L for summaries), but its table has no row and column for empty prefixes: it indexes dp[i - 1] with i = 0, silently reading the last row, and it crashes on empty input. Fix it with an (len(a) + 1) x (len(b) + 1) table.

TestsThe 4 checks Run tests uses

assert lcs_length("the cat sat on the mat".split(), "the cat lay on a mat".split()) == 4
assert lcs_length([], ["a"]) == 0 and lcs_length(["x"], ["x"]) == 1 and lcs_length(list("abc"), list("def")) == 0
assert lcs_length(list("aab"), list("ab")) == 2
HintOpen a hint

dp = [[0] * (len(b) + 1) for _ in range(len(a) + 1)], loop i from 1 to len(a) and j from 1 to len(b), comparing a[i - 1] with b[j - 1].

SolutionShow the solution and why
solution.py
def lcs_length(a, b):
    dp = [[0] * (len(b) + 1) for _ in range(len(a) + 1)]
    for i in range(1, len(a) + 1):
        for j in range(1, len(b) + 1):
            if a[i - 1] == b[j - 1]:
                dp[i][j] = dp[i - 1][j - 1] + 1
            else:
                dp[i][j] = max(dp[i - 1][j], dp[i][j - 1])
    return dp[-1][-1]

dp[i][j] should mean "the LCS of the first i items of a and the first j of b", which needs i and j to range from 0 (empty prefix, LCS 0) upwards. Without that row and column, the base case was missing, and Python's negative indexing turned dp[-1] into the last row of the table, garbage that happens to be 0 at the start, which is why the bug can pass small tests. The padded table makes the base cases explicit and the indices honest. ROUGE-L divides the LCS length by the reference and candidate lengths to score how much of a reference summary's word order a generated summary preserves.

solution.py
def select_chunks(chunks, budget):
    n = len(chunks)
    best = [[0.0] * (budget + 1) for _ in range(n + 1)]
    for i in range(1, n + 1):
        tokens, value = chunks[i - 1]
        for w in range(budget + 1):
            best[i][w] = best[i - 1][w]
            if tokens <= w and best[i - 1][w - tokens] + value > best[i][w]:
                best[i][w] = best[i - 1][w - tokens] + value
    chosen, w = [], budget
    for i in range(n, 0, -1):
        if best[i][w] != best[i - 1][w]:
            chosen.append(i - 1)
            w -= chunks[i - 1][0]
    return round(best[n][budget], 3), sorted(chosen)

Packing context is a knapsack: each chunk has a weight (its tokens) and a value (its relevance), and the budget is the capacity. Greedy by relevance per token is not optimal (with 1,000 tokens it might take the 700-token chunk and waste the rest); the DP considers every chunk in or out for every remaining budget, O(n * budget) time, and the table lets you walk back to the chosen set. Real systems round token counts to coarser units (multiples of 10 or 50) to shrink the table, and often add constraints such as "at most two chunks per document", which become extra state dimensions.

11. Longest increasing subsequence with bisect

from bisect import bisect_left

def lis(values):
    tails, idx, prev = [], [], [None] * len(values)
    for i, v in enumerate(values):
        k = bisect_left(tails, v)
        if k == len(tails):
            tails.append(v)
            idx.append(i)
        else:
            tails[k] = v
            idx[k] = i
        prev[i] = idx[k - 1] if k else None
    out, i = [], idx[-1] if idx else None
    while i is not None:
        out.append(values[i])
        i = prev[i]
    return len(tails), tails, out[::-1]

print(lis([10, 9, 2, 5, 3, 7, 101, 18]))
print(lis([3, 3, 3]), lis([]), lis([1, 2, 3, 4]))
HintOpen a hint

tails[k] is the smallest possible last value of an increasing subsequence of length k + 1 seen so far; each value replaces the first tail that is not smaller.

SolutionShow the solution and why
Real output
(4, [2, 3, 7, 18], [2, 3, 7, 18])
(1, [3], [3]) (0, [], []) (4, [1, 2, 3, 4], [1, 2, 3, 4])

The patience-sorting idea keeps, for each length, the smallest tail an increasing subsequence of that length can have; a new value extends the longest one if it is larger than every tail, or improves (lowers) the first tail it does not exceed, found with bisect_left in O(log n), so the whole algorithm is O(n log n) instead of the O(n^2) table. tails is not in general a real subsequence of the input (here it happens to be one); following the prev links from the last tail's index always rebuilds a real one, [2, 3, 7, 18]. With bisect_left, equal values do not extend the sequence (strictly increasing), so [3, 3, 3] gives length 1.

def segment(text, vocab):
    n = len(text)
    longest = max((len(w) for w in vocab), default=0)
    INF = float("inf")
    best = [0] + [INF] * n
    back = [None] * (n + 1)
    for i in range(1, n + 1):
        for k in range(min(longest, i), 0, -1):
            j = i - k
            if best[j] + 1 < best[i] and text[j:i] in vocab:
                best[i], back[i] = best[j] + 1, j
    if best[n] == INF:
        return None
    words, i = [], n
    while i:
        words.append(text[back[i]:i])
        i = back[i]
    return words[::-1]

The state is a prefix length; text[:i] can be segmented if some vocabulary word ends at i and the text before it can be segmented, and taking the minimum over those words gives the fewest pieces. Limiting candidates to the longest vocabulary word keeps the work O(n * L) with O(1) set lookups, and back records where each best last word starts, so the segmentation is rebuilt by walking backwards. Subword tokenizers face the same question of how to split a word into known pieces; WordPiece takes the longest match greedily from the left, while a DP like this finds a segmentation that is optimal for a chosen score (fewest pieces here, highest probability in a unigram language-model tokenizer).

solution.py
def align(reference, hypothesis):
    n, m = len(reference), len(hypothesis)
    dp = [[0] * (m + 1) for _ in range(n + 1)]
    for i in range(n + 1):
        dp[i][0] = i
    for j in range(m + 1):
        dp[0][j] = j
    for i in range(1, n + 1):
        for j in range(1, m + 1):
            cost = 0 if reference[i - 1] == hypothesis[j - 1] else 1
            dp[i][j] = min(dp[i - 1][j - 1] + cost, dp[i - 1][j] + 1, dp[i][j - 1] + 1)
    ops, i, j = [], n, m
    while i > 0 or j > 0:
        if i and j:
            cost = 0 if reference[i - 1] == hypothesis[j - 1] else 1
            if dp[i][j] == dp[i - 1][j - 1] + cost:
                ops.append(("keep", reference[i - 1]) if cost == 0 else ("sub", reference[i - 1], hypothesis[j - 1]))
                i, j = i - 1, j - 1
                continue
        if i and dp[i][j] == dp[i - 1][j] + 1:
            ops.append(("del", reference[i - 1]))
            i -= 1
        else:
            ops.append(("ins", hypothesis[j - 1]))
            j -= 1
    return dp[n][m], ops[::-1]

The distance alone says how wrong a transcript or generated answer is; the alignment says where: which words were substituted, dropped or added, which is what an evaluation report or a diff view shows. Recovering it requires the full table (O(n * m) memory instead of two rows), because backtracking asks, at each cell, which neighbour produced its value; a fixed preference order makes the result deterministic when several moves are optimal. The same backtracking pattern recovers the chosen items in knapsack (problem 9), the words in segmentation (problem 12) and the common subsequence in LCS.

14. Read the code: counting decodings

Messages are encoded as digit strings with A=1 ... Z=26. count_decodings(s) should count the ways to decode s ("226" has 3: BZ, VF, BBF). The recursive version is exponential (it recomputes the same suffixes), treats "0" as a letter, accepts two-digit codes like "06" and "27", and returns 1 for an empty string only by accident. Rewrite it bottom-up in O(n): a single 0 decodes to nothing, a two-digit code is valid only from 10 to 26, and the empty string has exactly one decoding.

def count_decodings(s):
    ways = [1] + [0] * len(s)
    for i in range(1, len(s) + 1):
        if s[i - 1] != "0":
            ways[i] += ways[i - 1]
        if i >= 2 and 10 <= int(s[i - 2:i]) <= 26:
            ways[i] += ways[i - 2]
    return ways[-1]

The recursion had the right shape (the first letter uses one or two digits) but recomputed the same suffixes exponentially often: sixty 1s would take years, while the table needs sixty steps (the answer is a Fibonacci number). The base case "length at most one means one way" was wrong for "0", which cannot be decoded, and the two-digit test accepted "06" (leading zero) and any number below 27 including single digits; the precise rules are "one digit from 1 to 9" and "two digits from 10 to 26". The empty prefix has exactly one decoding (decode nothing), the base case that makes every count correct, the same role {0: 1} played in 16.2's prefix sums.

lru_cache keys on the arguments exactly as given, so a positional call, the same call with the default spelled out, and a keyword call are three separate cache entries even though they mean the same thing: one hit and three misses, with only two entries kept. Adding "b" and "c" evicts the older entries, so "a" is a miss again, and currsize never exceeds maxsize. cache_clear() resets the statistics and contents, and __wrapped__ reaches the original function without the cache. For caches of expensive calls (embeddings, completions), normalise arguments into one canonical key yourself.

8Interview questions

Interview

16. How do you recognise a dynamic programming problem, and how do you approach it?

SolutionModel answer

Signals: the question asks for an optimum (minimum cost, maximum value, longest, fewest) or a count of ways, the input is a sequence, string, grid or budget, and a brute force would try all combinations, with the same sub-decisions recurring (the remaining amount, the suffix still to process, the prefixes compared so far). The approach: define the state (the smallest set of parameters that determines a subproblem), write the recurrence by considering the last (or first) decision, list the base cases, and choose an order: top-down recursion with functools.cache is quick to write and only visits reachable states, bottom-up tabulation avoids recursion limits and often allows keeping only one or two rows. State the complexity as states times transitions per state. Then reconstruct the solution if needed by storing choices or backtracking through the table. Check small cases by hand, including the empty input, and compare against brute force on random tests.

Interview

17. Memoization or tabulation: what are the trade-offs?

SolutionModel answer

Memoization (top-down) keeps the code close to the recursive definition, computes only the states actually reached (a win when many states are irrelevant), and is fast to write with @functools.cache; but it pays function-call overhead, hits Python's recursion limit for deep state chains (about 1,000 by default), needs hashable arguments, and keeps every cached result in memory. Tabulation (bottom-up) uses loops in an order that guarantees dependencies are ready, has no recursion limit and lower overhead, and lets you discard old rows (edit distance in O(m) memory instead of O(n m)); but it computes every state in the table, even unused ones, and requires working out the iteration order explicitly. In interviews, starting top-down and converting to bottom-up when asked about memory or deep inputs is a good way to show both.

Interview

18. Where does dynamic programming show up in ML and LLM work?

SolutionModel answer

Many places, often hidden inside libraries. Evaluation: edit distance gives word and character error rates for speech and OCR, longest common subsequence gives ROUGE-L for summaries, and alignment (backtracking the edit table) explains errors. Sequence models: the Viterbi algorithm finds the most likely tag sequence in HMMs and CRFs, the forward algorithm computes sequence probabilities, CTC loss for speech recognition sums over alignments with DP, and beam search is a pruned approximation of exact DP decoding. Tokenisation: unigram language-model tokenizers (SentencePiece) choose the most probable segmentation with DP over the text, the same structure as word break. Retrieval and prompting: choosing context chunks under a token budget is a knapsack, and dynamic time warping aligns time series. Reinforcement learning: value iteration and the Bellman equation are DP over states. Knowing the pattern helps you recognise when a greedy shortcut is wrong and when an exact solution is cheap.

Recap

  • DP applies when the answer for a state is built from smaller overlapping states: compute each state once.
  • Design it with four questions: state, recurrence, base cases, order; complexity is states times transitions.
  • Top-down: @functools.cache (hashable arguments, recursion limits). Bottom-up: tables filled in dependency order, often with one or two rows of memory.
  • Pad two-sequence tables with an empty-prefix row and column; reconstruct solutions by storing choices or backtracking.
  • Classics: coin change, LCS (ROUGE-L), edit distance (WER, alignment), knapsack (context budgets), LIS with bisect, Kadane, segmentation.
